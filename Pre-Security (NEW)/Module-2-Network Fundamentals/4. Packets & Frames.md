# Packets & Frames

## What are Packets and Frames?

Packets and frames are small units of data used to transmit information across a network. While they work together, they belong to different layers of the OSI model.

- **Packet** → Layer 3 (Network Layer)
- **Frame** → Layer 2 (Data Link Layer)

### Packet (Layer 3)

A packet contains:
- IP header
- Payload (actual data)

Packets are responsible for logical addressing using IP addresses and routing data across networks.

### Frame (Layer 2)

A frame:
- Encapsulates the packet
- Adds MAC addresses
- Prepares data for physical transmission on a local network

Think of it like mailing a letter:

- Letter content = Packet  
- Envelope = Frame  

The envelope helps deliver the letter to the correct house. Once opened, the letter inside is forwarded appropriately.

This wrapping process is called **encapsulation**.

---

## Why Packets Are Important

Instead of sending large data all at once, networks divide data into small packets.

Benefits:
- Reduces congestion
- Improves efficiency
- Prevents bottlenecks
- Allows reassembly at destination

Example:
When loading an image from a website, the image is divided into multiple packets and reconstructed at the receiving device.

# IP Packet Structure (Layer 3)

Packets follow standards and include headers that control delivery.

### Important IP Headers

| Header | Description |
|--------|------------|
| Time to Live (TTL) | Prevents packets from circulating forever by setting a hop limit |
| Checksum | Verifies integrity of data |
| Source Address | IP address of sender |
| Destination Address | IP address of receiver |

---

# TCP/IP Model Overview

The TCP/IP model is a simplified version of the OSI model.

## Four Layers

1. Application
2. Transport
3. Internet
4. Network Interface

Data gains headers at each layer (encapsulation) and loses them when received (decapsulation).

---

# TCP (Transmission Control Protocol)

TCP is:

- Connection-based
- Reliable
- Ordered
- Error-checked

It guarantees data delivery using a process called the **Three-Way Handshake**.

---

## TCP Advantages and Disadvantages

| Advantages | Disadvantages |
|------------|--------------|
| Guarantees data integrity | Requires stable connection |
| Prevents packet flooding | Slower than UDP |
| Ensures correct order | More resource usage |

---

## Important TCP Headers

| Header | Description |
|--------|------------|
| Source Port | Random port chosen by sender (0–65535) |
| Destination Port | Service port on receiver (e.g., 80 for HTTP) |
| Source IP | Sender IP address |
| Destination IP | Receiver IP address |
| Sequence Number | Tracks order of data |
| Acknowledgement Number | Confirms received data |
| Checksum | Ensures data integrity |
| Data | Actual transmitted content |
| Flags | Control connection behaviour |

---

# TCP Three-Way Handshake

TCP establishes a connection before sending data.

### Steps

1. SYN → Client initiates connection
2. SYN/ACK → Server acknowledges and synchronizes
3. ACK → Client confirms connection
4. DATA → Data transmission begins
5. FIN → Clean connection closure
6. RST → Abrupt termination (error case)

### Example Sequence Flow

Client ISN: 0  
Server ISN: 5000  

- Client sends SYN (0)
- Server responds SYN/ACK (5000, ACK 0)
- Client sends ACK (ACK 5000, Seq 1)

Sequence numbers increment by 1 for proper ordering.

---

# TCP Closing a Connection

When communication ends:

1. Device sends FIN
2. Other device ACKs
3. Both sides close cleanly

Closing connections frees system resources.

3. ACK - Client: I ACKnowledge your Initial Sequence Number (ISN) of (5,000), here is some data that is my ISN+1 (0 + 1)

TCP Closing a Connection :
Let's quickly explain the process behind TCP closing a connection. First, TCP will close a connection once a device has determined that the other device has successfully received all of the data. Because TCP reserves system resources on a device, it is best practice to close TCP connections as soon as possible. To initiate the closure of a TCP connection, the device will send a "FIN" packet to the other device. Of course, with TCP, the other device will also have to acknowledge this packet. # UDP (User Datagram Protocol)

UDP is:

- Connectionless
- Faster
- No error checking
- No delivery guarantee

Used when speed is more important than reliability.

Examples:
- Video streaming
- Online gaming
- VoIP
- ARP
- DHCP

---

## UDP Advantages and Disadvantages

| Advantages | Disadvantages |
|------------|--------------|
| Faster than TCP | No guarantee of delivery |
| Lightweight | No ordering |
| No connection overhead | Data may be lost |

---

## Common UDP/IP Headers

| Header | Description |
|--------|------------|
| Time to Live (TTL) | Packet expiry limit |
| Source Address | Sender IP |
| Destination Address | Receiver IP |
| Source Port | Random port chosen by sender |
| Destination Port | Target service port |
| Data | Transmitted content |

UDP does not use a handshake or acknowledgement system.

---

# Ports

A port is a logical communication endpoint used by applications to send and receive data.

Port range:
0 – 65535

Ports allow multiple applications to use the network simultaneously.

> Because ports can range from anywhere between 0-65535, there quickly runs the risk of losing track of what application is using what port. A busy harbour is chaos! Thankfully, we associate applications, software and behaviours with a standard set of rules. For example, by enforcing that any web browser data is sent over port 80, software developers can design a web browser such as Google Chrome or Firefox to interpret the data the same way as one another. This means that all web browsers now share one common rule : data is sent over port 80. How the browsers look, feel and easy to use is up to the designer or the user's decision.
---

## Common Ports (0–1024)

| Port | Protocol | Description |
|------|----------|------------|
| 21 | FTP | File transfer |
| 22 | SSH | Secure remote login |
| 80 | HTTP | Web traffic |
| 443 | HTTPS | Secure web traffic |
| 445 | SMB | File & printer sharing |
| 3389 | RDP | Remote desktop access |

Note:
Applications can run on non-standard ports (e.g., web server on 8080), but clients must specify the port using a colon:

example.com:8080

---

# Key Takeaways

- Packet = Layer 3 (IP-based logical delivery)
- Frame = Layer 2 (MAC-based physical delivery)
- Encapsulation adds headers at each layer
- TCP is reliable and connection-based
- UDP is fast and connectionless
- Ports allow applications to communicate correctly

Understanding packets and frames is essential for networking, packet analysis, and cybersecurity.
