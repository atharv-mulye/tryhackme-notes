# Intro to LAN

## Introduction to Network Topologies

### What is a Topology?

Network topology refers to the physical or logical arrangement of devices (nodes) and connections (links) in a computer network. It defines how devices are connected and how data flows between them.

The three primary LAN topologies covered in this module are:

- Star Topology  
- Bus Topology  
- Ring Topology  

---

# 1️. Star Topology

In a star topology, every device is connected individually to a central device such as a switch or hub.

All communication between devices passes through this central device.

<img width="350" height="350" alt="image" src="https://github.com/user-attachments/assets/8016feda-43d2-4554-83cc-9581e37bafd4" />

## How It Works

- Each device connects directly to a central switch or hub.
- Data sent from one device goes to the central device first.
- The central device forwards the data to the intended destination.

## Advantages

- High reliability (one cable failure doesn’t affect others)
- Easy to scale
- Easy to isolate faulty devices
- Good performance management

## Disadvantages

- Expensive (more cabling and hardware required)
- Central device is a single point of failure
- More maintenance in large networks

---

# 2️. Bus Topology

In a bus topology, all devices are connected to a single backbone cable.

All data travels along this shared cable.

<img width="350" height="350" alt="image" src="https://github.com/user-attachments/assets/db2eaa25-f28f-408b-9667-be0efcfb7cc3" />

## How It Works

- Devices connect to one main cable.
- Data is broadcast across the backbone.
- Each device checks if the data is intended for it.

## Advantages

- Simple setup
- Cost-effective
- Requires minimal hardware

## Disadvantages

- Single point of failure (backbone cable)
- Performance bottlenecks
- Difficult troubleshooting
- Limited scalability

---

# 3️. Ring Topology

In a ring topology, devices are connected in a closed loop.

Data travels in one direction around the ring until it reaches its destination.

<img width="300" height="300" alt="image" src="https://github.com/user-attachments/assets/2ab98e2f-8e2f-4d6f-8e4b-27aed3bac044" />

## How It Works

- Devices form a circular connection.
- Each device forwards data to the next device.
- Data moves in one direction only.

## Advantages

- Less cabling than star
- No central device required
- Fewer collisions
- Easier to trace direction of failure

## Disadvantages

- Single break can stop the whole network
- Slow data delivery in large rings
- Difficult to add/remove devices

## Activity Lab: Topology Flaws

## Objective

To understand how different network topologies respond to failures by intentionally causing faults and observing the impact on network communication.

Topologies tested:

- Ring Topology
- Bus Topology
- Star Topology

---

# 1. Ring Topology

## How It Works

- Devices are connected in a closed loop.
- Each device connects to exactly two other devices.
- Data travels sequentially from one device to the next until it reaches its destination.

## Flaw Identified

- A single cable break or device failure disrupts the loop.
- Data can no longer circulate.
- Entire network communication stops.

## Lab Action

- Cut the cable in the middle of the ring.

## Observation

- Packets stopped moving.
- Network became completely unavailable.

## Conclusion

Ring topology has no fault tolerance unless additional redundancy is implemented.

---

# 2. Bus Topology

## How It Works

- All devices connect to a single backbone cable.
- Data is broadcast along the backbone in both directions.
- Each device checks if the packet is intended for it.

## Flaw Identified

- High traffic leads to collisions.
- Backbone cable is a single point of failure.
- Performance degrades significantly under load.

## Lab Action

- Sent multiple packets rapidly to overload the network.

## Observation

- Network congestion occurred.
- Communication failed.
- Bus network crashed.

## Conclusion

Bus topology struggles with scalability and heavy traffic, making it unsuitable for large or high-demand networks.

---

# 3. Star Topology

## How It Works

- Each device connects directly to a central switch or hub.
- All communication passes through the central device.

## Flaw Identified

- The central switch is a single point of failure.
- If the switch fails, all communication stops.

## Lab Action

- Simulated failure of the central switch.

## Observation

- Devices could no longer communicate.
- Entire network went down.

## Conclusion

While individual cable failures do not affect the entire network, failure of the central device results in complete network outage.

---

## Key Takeaways

- Every topology has inherent weaknesses.
- Single points of failure are critical design risks.
- Shared-medium networks struggle under heavy traffic.
- Proper network design requires redundancy and fault tolerance planning.

# Introduction to Subnetting

Subnetting is the process of dividing a large network into smaller, manageable networks called subnets.
Each subnet allows devices to communicate efficiently while staying organized, secure, and optimized.

## Analogy :

Think of a network as a cake. 
The entire cake = one big network,
Cutting slices = subnetting,
Each slice = a subnet for a specific group,
You control who gets which slice = proper allocation & organization,
Subnetting makes sharing the “network cake” fair, secure, and efficient.

## Why Subnetting Is Important ?

Subnetting solves major problems in large networks :

- Efficient IP Usage : Prevents wasting IP addresses by assigning only what each group needs.

- Better Performance : Smaller subnets = less broadcast traffic = faster communication.

- Improved Security : Separates departments so they cannot freely access each other.

- Easier Management : Smaller, organized networks are simpler to monitor and troubleshoot.

- Full Control & Organization : Network admins decide how to structure the network (e.g., by department).

## Real Company Example (Classful Addressing)

Let's consider a company that follows classful addressing, it has a Class C network (192.168.1.0/24) with 256 IP addresses. It has three departments :

- Subnetting divides large networks into smaller logical segments.

- Proper subnet planning prevents IP wastage.

# ARP (Address Resolution Protocol)

Devices on a network have two identifiers:

- **MAC address** (physical hardware address)  
- **IP address** (logical network address)  

The **Address Resolution Protocol (ARP)** allows devices to map a MAC address to an IP address, enabling proper communication on a network. Each device maintains a **cache** that stores the MAC addresses associated with IP addresses of other devices.

---

## How ARP Works

ARP works by sending two types of messages:

1. **ARP Request**  
   - Broadcasted to all devices on the network.  
   - Asks: "Who owns this IP address?"  
   - Only the device with the matching IP address responds.

2. **ARP Reply**  
   - Sent by the device that owns the IP address.  
   - Contains its MAC address.  
   - The requesting device stores this MAC-IP mapping in its ARP cache for future communication.

---

## ARP Process Flow

1. A device wants to communicate with another device on the same network.
2. It checks its ARP cache for the IP-to-MAC mapping.
3. If the mapping is not found, it broadcasts an **ARP Request**.
4. The device with the requested IP replies with an **ARP Reply** containing its MAC address.
5. The requesting device updates its ARP cache and can now send data directly to the target device.

---

### Example

Assume a device wants to communicate with `192.168.1.100`:

- ARP Request: "Who has `192.168.1.100`?"  
- Device with `192.168.1.100` replies with its MAC, e.g., `00:1A:2B:3C:4D:5E`.  
- The requester stores this mapping:  
IP Address: 192.168.1.100 → MAC Address: 00:1A:2B:3C:4D:5E

Future communication to `192.168.1.100` uses the cached MAC address.

> When an ARP request is sent, a message is broadcasted on the network to other devices asking, "What is the mac address that owns this IP address?" When the other devices receive that message, they will only respond if they own that IP address and will send an ARP reply with its MAC address. The requesting device can now remember this mapping and store it in its ARP cache for future use.

## Key Points

- ARP enables devices to communicate using IP and MAC addresses.  
- The ARP cache reduces network broadcast traffic.  
- ARP only works within a local network (Layer 2).  
- Dynamic and automatic process; no manual configuration is required under normal conditions.

# DHCP (Dynamic Host Configuration Protocol)

IP addresses can be assigned to devices in two ways:

1. **Manual Assignment**  
   - The network administrator enters the IP address, subnet mask, and other settings directly into the device.

2. **Automatic Assignment via DHCP**  
   - DHCP (Dynamic Host Configuration Protocol) automates IP address assignment.  
   - When a device connects to a network without a preconfigured IP, it follows this process:

---

## DHCP Process Flow

1. **DHCP Discover**  
   - The device broadcasts a request asking if any DHCP servers are available on the network.

2. **DHCP Offer**  
   - The DHCP server responds with an available IP address and network configuration details (subnet mask, gateway, DNS, etc.).

3. **DHCP Request**  
   - The device replies to the DHCP server confirming it wants to use the offered IP address.

4. **DHCP Acknowledgment (ACK)**  
   - The DHCP server sends a final acknowledgment.  
   - The device can now start using the assigned IP address.

---

### Example

Suppose a device joins a network:

- Device sends DHCP Discover → network broadcast.  
- DHCP server offers: `192.168.1.101` → DHCP Offer.  
- Device sends DHCP Request for `192.168.1.101`.  
- DHCP server sends DHCP ACK → Device starts using `192.168.1.101`.  

IP Address Assigned: 192.168.1.101<br>
Subnet Mask: 255.255.255.0<br>
Default Gateway: 192.168.1.1 <br>

**OR**

> IP addresses can be assigned either manually, by entering them physically into a device, or automatically and most commonly by using a DHCP (Dynamic Host Configuration Protocol) server. When a device connects to a network, if it has not already been manually assigned an IP address, it sends out a request (DHCP Discover) to see if any DHCP servers are on the network. The DHCP server then replies back with an IP address the device could use (DHCP Offer). The device then sends a reply confirming it wants the offered IP Address (DHCP Request), and then lastly, the DHCP server sends a reply acknowledging this has been completed, and the device can start using the IP Address (DHCP ACK).

## Key Points

- DHCP eliminates the need for manual IP configuration.  
- Reduces IP conflicts and errors.  
- Works only within the local network (Layer 3).  
- Can provide other configuration details (DNS, gateway) along with the IP.
