# Cryptography Concepts

## Introduction

### What is Cryptography ?
- Cryptography is the practice of protecting information by converting it into a secure, unreadable form.
- It ensures that only intended recipients can understand the data.

### Why Cryptography is Needed
- In the digital world, data is constantly :
  - Sent over the internet
  - Stored on systems
  - Shared between users and services

- This data does not travel directly from sender to receiver.
- It passes through multiple intermediate systems (networks, routers, servers).

This creates multiple points where data can be :
- Intercepted (read by attackers)
- Modified (tampered with)
- Blocked (prevented from reaching destination)

### Connection to Cyber Security (CIA Triad)
- Cryptography plays a key role in protecting:
  - Confidentiality → keeps data private
  - Integrity → ensures data is not altered

- Without cryptography :
  - Sensitive information can be exposed
  - Data can be changed without detection

### Core Idea Behind Cryptography
- Instead of sending readable data directly :
  - Data is scrambled before sending
  - Only the receiver can unscramble it

---

### Basic Terminology
- **Plaintext** - original readable data  
  - Example : `HELLO`, personal details

- **Ciphertext** - encrypted unreadable data  
  - Example: `KHOOR`, random-looking text
  
### How Cryptography Works 
- Uses two main components :
  - **Algorithm** - rules for encryption
  - **Key** - secret value used in the process

- Process :
  - Plaintext + Key + Algorithm → Ciphertext
  - Ciphertext + Key + Algorithm → Plaintext

### Real-World Importance
- Used in everyday activities like :
  - Secure websites (HTTPS)
  - Online banking
  - Messaging apps

- Protects sensitive data such as :
  - Passwords
  - Personal information
  - Financial transactions

### Key Understanding
- Cryptography does not stop data from being seen
- It makes data useless without the key

### Summary
- Data travelling over networks is vulnerable
- Cryptography protects it by encryption
- It is essential for maintaining privacy and trust in digital communication

## Hiding Information : Symmetric Encryption 

### Core Idea
- Symmetric encryption uses one single key for both :
  - Encrypting data
  - Decrypting data

### Key Terms
- **Plaintext** - readable message  
- **Ciphertext** - scrambled unreadable message  
- **Key** - secret value used to lock/unlock data  
- **Algorithm** - method used to apply the key  

### Encryption & Decryption Process

- Same key is used on both sides
- Both sender and receiver must have this key

### Example : Caesar Cipher

- Simple method where letters are shifted by a number (key)

#### Example (Key = 3)

HELLO → KHOOR


- Each letter moves forward by 3 positions
- Decryption moves letters backward by 3

---

### Important Concept
- Algorithm is not secret
- Security depends on keeping the key secret

**Kerckhoffs’s Principle :** A cryptographic system should remain secure even if everything about it is public except the key.
- The algorithm is not secret and can be known by anyone.
- The security depends only on keeping the key secret.

### Why This Matters
- Hiding the algorithm is not reliable (it can be discovered).
- Strong systems assume attackers already know how the system works.
- Only the key must remain confidential.

### Simple Understanding
- Algorithm = lock design (public)
- Key = actual key (private)

> Even if someone knows how the lock works, they still can’t open it without the key.

#### Advantages
- Very fast
- Efficient for large data
- Widely used for file encryption and network traffic

#### Disadvantage
- **Key Distribution Problem**
  - Both users need the same key
  - Sharing the key securely is difficult

### Key Distribution Problem Explained
- If key is sent openly → attacker can capture it
- If key is encrypted → need another key to protect it
- Leads to a loop (problem cannot be solved easily)

### Real-World Use
- Used in :
  - Disk encryption
  - Secure file storage
  - Network communication (after connection setup)

### Key Understanding
- Symmetric encryption is :
  - Fast and efficient
  - But depends heavily on keeping the key secret

### Summary
- One key is used for both encryption and decryption
- Easy to use but hard to share securely
- Forms the base for many real-world encryption systems

## Sharing Keys Safely : Asymmetric Encryption

### Core Idea
- Asymmetric encryption solves the key sharing problem of symmetric encryption.
- Instead of one key, it uses two different but related keys.

### Two Types of Keys
- **Public Key**
  - Can be shared with anyone
  - Used to encrypt data

- **Private Key**
  - Kept secret by the owner
  - Used to decrypt data

### How It Works

<img width="500" height="600" alt="image" src="https://github.com/user-attachments/assets/a79f800c-ea8b-47da-8aad-04af0801255f" />

- Data encrypted with Public Key → Decrypted with Private Key
- Only the owner of the private key can read the message


### Solving the Key Distribution Problem
- No need to send a secret key beforehand
- Steps :
  1. User creates public & private key pair
  2. Public key is shared openly
  3. Sender encrypts data using public key
  4. Receiver decrypts using private key

### Advantages
- Secure key exchange
- No need for pre-shared secret
- Safe for communication over open networks

### Limitation
- Slower than symmetric encryption
- Not efficient for large data

### Real-World Use – HTTPS

- Used when visiting secure websites (🔒icon)

#### Process :
1. Browser requests website’s public key
2. Website sends public key via certificate
3. Secure connection is established
4. A shared symmetric key is created
5. Data transfer continues using symmetric encryption


### Hybrid Encryption
- Real systems use both methods :

| Step | Method Used |
|------|------------|
| Key exchange | Asymmetric |
| Data transfer | Symmetric |

### Why Use Both Asymmetric and Symmetric Encryption ?

Real-world systems combine both because each has strengths and weaknesses.

### Key Exchange : Asymmetric Encryption
- Asymmetric encryption is used first because :
  - No need to share a secret key beforehand
  - Public key can be shared openly
  - Secure even over insecure networks

> Solves the key distribution problem

### Data Transfer : Symmetric Encryption
- After a secure key is established :
  - Symmetric encryption is used for actual data

- Reason :
  - Much faster than asymmetric encryption
  - Efficient for large amounts of data

### Why Not Use Only One ?

#### Only Symmetric 
- Problem : How to safely share the key?

#### Only Asymmetric 
- Problem : Too slow for continuous data transfer

### Best Approach (Hybrid)
1. Use **asymmetric encryption** to securely exchange a key
2. Use **symmetric encryption** for fast data transfer

### Final Understanding
- Asymmetric = secure start  
- Symmetric = fast communication  

> That’s why both are used together in HTTPS and secure systems

### Certificates
- Used to verify identity of websites

#### Contains :
- Public key
- Website identity
- Signature from trusted authority (CA)

### Why Certificates Matter
- Prevent attackers from pretending to be real websites
- Browser verifies :
  - Trusted issuer
  - Validity period
  - Authenticity

### Symmetric vs Asymmetric

| Feature | Symmetric | Asymmetric |
|--------|----------|-----------|
| Keys | One | Two |
| Speed | Fast | Slow |
| Use | Data encryption | Key exchange |
| Security | Hard to share key | Easy key distribution |

### Key Understanding
- Asymmetric encryption solves the key sharing problem
- Works best when combined with symmetric encryption

### Summary
- Uses public + private key pair
- Enables secure communication without sharing secret keys
- Forms the foundation of secure web communication (HTTPS)
