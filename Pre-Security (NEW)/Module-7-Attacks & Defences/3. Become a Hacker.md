# Become a Hacker

## Introduction 

### What is Offensive Security ?
- Offensive security is the approach of actively testing systems by trying to break into them.
- The goal is not damage, but to find weaknesses before real attackers do.

### Shift in Perspective
- Earlier, you learned how systems work.
- Now, you start thinking from the attacker’s point of view.

> Instead of asking “How does this work ?”  
> Ask “How can this be misused or broken ?”

### Core Idea
- Systems often have hidden flaws.
- These flaws may not be obvious during normal use.
- Offensive security helps uncover :
  - Misconfigurations
  - Hidden pages
  - Weak authentication
  - Poor assumptions in design

### Why Offensive Security is Important
- Attackers constantly look for weaknesses
- If defenders don’t test systems :
  - Vulnerabilities remain unnoticed
  - Systems become easy targets

Offensive security helps :
- Identify risks early
- Fix issues before exploitation
- Strengthen overall security

### Ethical Hacking
- Offensive security is done legally and ethically
- Also called penetration testing

#### Key Rules :
- Always have permission
- Work within a defined scope
- Do not cause real damage

### How Hackers Think
- Hackers are curious and analytical
- They :
  - Question assumptions
  - Test unexpected inputs
  - Observe system behavior
  - Look for weaknesses others miss

### Key Understanding
- Offensive security is proactive, not reactive
- It focuses on :
  - Finding problems before attackers
  - Understanding real-world risks

### Summary
- Offensive security = testing systems like an attacker
- Done ethically to improve security
- Builds the foundation for real-world cyber security skills

## Finding Weaknesses 

### Core Idea
- Before exploiting anything, attackers first look for weaknesses.
- This phase is about gathering information and discovering exposed areas.

### Offensive Security Approach
- Instead of waiting for attacks :
  - Actively test systems
  - Identify weak points early

> This process is often called enumeration

## Key Terminology

### Red Teaming
- Simulates real-world attacks
- Tests how well defenses detect and respond

### Penetration Testing
- Controlled and authorized testing
- Goal : find and exploit vulnerabilities safely

### Vulnerability
- A weakness in :
  - System
  - Application
  - Configuration

> Can be exploited by attackers

### Exploit
- A method used to take advantage of a vulnerability

### Scope
- Defines :
  - What can be tested
  - What is allowed
  - What is off-limits

> Always follow scope (legal requirement)

---

### Important Rule
- Ethical hacking = permission-based
- No permission → illegal activity

## Finding Hidden Pages

### Goal
- Discover pages not meant for public access

### Manual Method
- Try common paths :
  - `/login`
  - `/admin`
  - `/register`
  - `/sitemap`

> If page exists → returns valid response  
> If not → returns 404 error

### Automated Method – Gobuster

```
gobuster dir --url http://www.onlineshop.thm/ -w /usr/share/wordlists/dirbuster/directory-list.txt
```

The command above is made up of the following parts :

- gobuster : The command-line tool used to perform the discovery of web content
- dir : Specifies the directory and file enumeration mode, which attempts to discover hidden directories and files on a web server
- --url http://www.onlineshop.thm/ : Sets the target website that Gobuster will scan
- -w /usr/share/wordlists/dirbuster/directory-list.txt : Specifies the wordlist Gobuster will use to guess directory and file names

### Why Use Automation ?
- Manual testing is slow
- Real systems have thousands of possible paths
- Tools speed up discovery

## Exploiting Weaknesses 

### Core Idea
- Finding a vulnerability is just the first step.
- Real impact comes from exploiting and combining weaknesses.

### Chaining Weaknesses
- A single flaw may seem harmless
- Multiple small flaws together can lead to serious compromise

> This is called chaining vulnerabilities

### Domino Effect Concept
- One weakness triggers another
- Leads to bigger impact step by step

Example :
- Hidden page → weak login → admin access

## Thinking Like a Hacker

### Key Mindset
- Don’t trust that systems work correctly
- Always question behavior

### Important Practices
- Ask “What if this fails ?”
- Test unexpected inputs
- Look for misuse, not just normal use
- Combine multiple findings

## Automated Attack – Hydra

### Command Used
```
hydra -l admin -P passlist.txt www.onlineshop.thm http-post-form "/login:username=^USER^&password=^PASS^:F=incorrect" -V
```

The command above is made up of the following parts :
- hydra : The command-line tool used to perform the dictionary attack
- -l admin : Attempts to log in using the username admin
- -P passlist.txt : Specifies the password list to try
- www.onlineshop.thm : Sets the target website
- http-post-form : Indicates that this is an HTTP POST request form
- "/login:username=^USER^&password=^PASS^:F=incorrect" : Specifies how the login request is sent and how Hydra determines whether a login attempt has failed
- -V : Enables verbose output, which displays each username and password attempted

### What Hydra Does ?
- Automates login attempts
- Uses a wordlist of passwords
- Identifies correct credentials faster

### Key Concept – Dictionary Attack
- Uses predefined list of passwords
- Tries each one until success

### Why This Matters
- Weak passwords are a major risk
- Hidden pages increase attack surface
- Combining both leads to compromise

### Key Understanding
- Exploitation = using weaknesses to gain access
- Automation makes attacks faster and scalable
- Small issues can become critical when combined

### Summary
- Find vulnerability → exploit it
- Combine multiple weaknesses
- Use tools to automate attacks
- Always think like an attacker
