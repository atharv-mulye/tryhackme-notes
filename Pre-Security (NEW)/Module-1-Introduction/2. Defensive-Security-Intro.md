# Defensive Security Intro

## Overview

Defensive Security focuses on protecting systems, detecting malicious activity, and responding effectively to security incidents.

While Offensive Security simulates attacks to find weaknesses, Defensive Security aims to:

- Prevent intrusions from occurring
- Detect intrusions when they occur
- Respond and recover properly

Blue Teams operate in the defensive security domain.

---

## Core Responsibilities in Defensive Security

- User Cyber Security Awareness  
- Asset Management and Documentation  
- System Updating and Patching  
- Implementing Preventative Controls (Firewall, IPS)  
- Logging and Continuous Monitoring  

---

## Key Areas of Defensive Security

### 1. Security Operations Center (SOC)

A SOC is a centralized team responsible for monitoring, detecting, and responding to security events 24/7.

SOC analysts focus on:

- Vulnerability identification and prioritization  
- Policy violation detection  
- Unauthorized activity monitoring  
- Network intrusion detection  

Common tools used in SOC environments include:

- SIEM (Security Information and Event Management)  
- IDS/IPS (Intrusion Detection/Prevention Systems)  
- Endpoint Detection tools  

---

### 2. Threat Intelligence

Threat Intelligence involves collecting and analyzing data about potential or active threats to build a threat-informed defense strategy.

It includes:

- Gathering internal and external data sources  
- Identifying Indicators of Compromise (IOCs)  
- Studying attacker Tactics, Techniques, and Procedures (TTPs)  
- Producing actionable mitigation strategies  

---

### 3. Digital Forensics and Incident Response (DFIR)

DFIR focuses on investigating, containing, and recovering from cybersecurity incidents.

#### Digital Forensics

- Disk and file system analysis  
- Memory (RAM) analysis  
- Log analysis  
- Network traffic analysis (PCAP)  

#### Incident Response Phases

1. Preparation  
2. Detection and Analysis  
3. Containment, Eradication, and Recovery  
4. Post-Incident Review  

---

### 4. Malware Analysis

Malware analysis studies malicious software to understand its behavior and impact.

Common malware types:

- Virus : Self-replicating code that attaches to legitimate programs and modifies, deletes, or corrupts files.  
- Trojan Horse : Malicious software disguised as legitimate programs, enabling unauthorized access or control.
- Ransomware : Malware that encrypts files and demands ransom payment to decrypt them.

Analysis techniques:

- Static Analysis (without execution) : Examination of malware binaries without execution, including reverse engineering and disassembly to identify code behavior.
- Dynamic Analysis (sandbox execution) : Execution of malware in a controlled, isolated environment (sandbox) to monitor runtime behavior, network activity, and system modifications.

## Lab Summary – SOC: Malicious IP Investigation & Block

In this lab, I performed the role of a SOC analyst responding to a suspicious alert generated by a SIEM system.

### Scenario

An alert indicated an unauthorized connection from a suspicious IP address.

### What I Did

- Reviewed alert details from the SIEM dashboard  
- Identified the suspicious source IP  
- Checked IP reputation using public intelligence sources  
- Gathered evidence about malicious reports and risk categories  
- Escalated findings to the SOC Team Lead  
- After approval, implemented a firewall block rule  
- Validated the mitigation and monitored for follow-up activity  

---

## Key Concepts Used

### SIEM

Security Information and Event Management (SIEM) systems aggregate logs and security events into a centralized platform, enabling near real-time detection and investigation.

### IP Reputation Checking

Public threat intelligence platforms help determine whether an IP address is:

- Malicious  
- Suspicious  
- Associated with known attacks  

These tools assist analysts in prioritizing and validating alerts.
