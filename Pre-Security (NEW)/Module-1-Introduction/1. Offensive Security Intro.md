# Offensive Security

## What is Offensive Security ?  

Offensive Security is the practice of testing systems by thinking and acting like an attacker. Instead of only defending, you try to find weaknesses by simulating real attacks in a safe and controlled way.

The goal is to understand how systems can be broken into, so those weaknesses can be fixed before real attackers exploit them.

In simple terms, Offensive Security involves :
- Thinking like an attacker  
- Breaking into systems ethically  
- Finding and exploiting software bugs  
- Helping organizations secure their infrastructure  

It represents the process of simulating real-world cyber attacks to uncover vulnerabilities before malicious hackers can exploit them.

## Lab Overview (FakeBank)

This lab provides a virtual machine with a simple banking web application. The idea is to interact with it like a normal user first, then start exploring ways it could be misused.

Since it’s a controlled environment, you can experiment freely without risk.

## Approach to the Lab

Instead of attacking randomly, the first step is exploration.

Web applications sometimes contain hidden pages that are not visible in the UI but still exist on the server. These pages can expose important functionality.

Finding such hidden endpoints is often the starting point in offensive security.

## Discovering Hidden Pages

A common technique is directory brute-forcing, where a tool checks for possible page names using a wordlist.

### Example Command :
```
dirb http://fakebank.thm
```

### What Gobuster does ?
Gobuster takes a target URL and a wordlist, then requests the target with every entry from the list to discover hidden directories or files (pages). If a request returns a positive status (e.g 200), Gobuster reports that path — which helps you find admin panels, hidden endpoints, or other sensitive pages that aren’t linked from the site.

**Command used**
```
gobuster -u http://fakebank.thm -w wordlist.txt dir
```
-u specifies the target URL <br>
-w specifies the wordlist file to try <br>
-dir tells Gobuster to run in directory enumeration mode <br>

### What Happens :
- The tool uses a list of common directory names
- It sends requests to the server for each one
- If a page exists, the server responds positively
- The tool reports those discovered paths

> This helps uncover endpoints that are not publicly linked.

### Exploiting the Application

After finding a hidden page, it was observed that it allowed actions that should normally be restricted.

By interacting with that functionality :
- Sensitive operations were accessible
- No proper access checks were enforced
- The system accepted actions without validation

> This demonstrates how missing security controls can be exploited.

### Key Takeaways
- Hidden pages are not secure just because they are not visible
- Proper authentication and authorization are essential
- All user actions should be validated on the server side
- Even simple features can introduce vulnerabilities

### Final Understanding

In this exercise, the process followed was :

- Explore the application
- Identify hidden entry points
- Analyze functionality
- Exploit weak or missing security controls

Offensive Security is about understanding how systems fail and using that knowledge to make them stronger.
