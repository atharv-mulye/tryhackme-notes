# Putting It All Together

When you visit a website, a lot happens behind the scenes. Here's a step-by-step summary:

1. **DNS Lookup**  
   - Your computer first needs to find the IP address of the website.  
   - This is done using DNS (Domain Name System), which translates domain names like `tryhackme.com` into IP addresses that computers understand.

2. **HTTP/HTTPS Communication**  
   - Your computer connects to the web server using the HTTP or HTTPS protocol.  
   - HTTP is the set of rules for requesting and receiving web content.  
   - HTTPS is the secure version that encrypts the data for privacy and integrity.

3. **Sending a Request**  
   - Your browser sends an HTTP request to the server, which may include headers, cookies, and other metadata.  
   - The request specifies what resource you want (e.g., homepage, image, script) and how your browser can handle it.

4. **Server Response**  
   - The web server sends back an HTTP response.  
   - The response contains HTML, CSS, JavaScript, images, and other assets needed to display the page.  
   - The response also includes headers and status codes to tell your browser how to handle the content.

5. **Rendering the Website**  
   - Your browser interprets the HTML structure, applies CSS styling, and executes JavaScript for interactivity.  
   - The final result is the fully rendered webpage you see and interact with.

## Other Components of a Web Application

Websites are made up of multiple components that help them handle traffic, store data, and remain secure. Here are some key components :

### 1. Load Balancers
- Used when a website has high traffic or requires high availability.
- Purpose :
  - Distribute incoming requests across multiple web servers.
  - Provide failover if a server becomes unresponsive.
  <br>
  <img width="400" height="200" alt="image" src="https://github.com/user-attachments/assets/a159f59a-8dfe-47b8-8e69-366ce3301d0c" />

- How it works :
  - Your request first goes to the load balancer.
  - It decides which server to forward the request to using algorithms:
    - Round-robin : Sends requests to each server in turn.
    - Weighted : Sends requests to the least busy server based on current load.
  - Performs health checks to ensure servers are running properly. Unhealthy servers are skipped until they recover.

---

### 2. CDN (Content Delivery Network)
- Hosts static files like JavaScript, CSS, images, and videos across many servers worldwide.
- Purpose : Reduce load on the main server and improve website speed.
- Sends requests to the nearest server geographically to the user, cutting down latency.

---

### 3. Databases
- Websites often need to store and retrieve data for users.
- Web servers interact with databases to handle data.
- Types of databases:
  - Relational : MySQL, MSSQL, Postgres
  - NoSQL : MongoDB
- Databases can be simple files or complex clusters for speed and redundancy.

---

### 4. WAF (Web Application Firewall)
- Sits between the user’s request and the web server.

- Checks:
  - If the request uses common attack techniques.

## How Web Servers Work

### What is a Web Server?
A web server is software that listens for incoming connections and uses the HTTP protocol to deliver web content to clients (browsers).  

**Common web server software :**
- Apache
- Nginx
- IIS
- NodeJS

**Web server root directories :**
- Linux (Apache/Nginx): `/var/www/html`
- Windows (IIS): `C:\inetpub\wwwroot`

**Example :**  
Request : `http://www.example.com/picture.jpg`  
Served file : `/var/www/html/picture.jpg` (from the local hard drive)

---

### Virtual Hosts
- Allow a single web server to host multiple websites with different domain names.
- The server checks the HTTP Host header and matches it with the virtual host configuration.
- If no match is found, the default website is served.

**Example :**
- `one.com` → `/var/www/website_one`
- `two.com` → `/var/www/website_two`

> There is no limit to the number of virtual hosts/websites a server can host.

---

### Static vs Dynamic Content

**Static Content :**  
- Content that never changes.  
- Examples: Images, CSS, JavaScript, fixed HTML pages.  
- Served directly from the server.

**Dynamic Content :**  
- Content that changes based on requests.  
- Examples: Blog homepage showing latest entries, search results on a website.  
- Processed in the Backend, then sent as HTML to the Frontend.

> Everything you see in your browser is the Frontend, while the server processing happens in the Backend.

---

### Scripting and Backend Languages
- Backend languages enable interactive websites.
- They can interact with databases, process user data, call external services, and more.

**Common backend languages :** PHP, Python, Ruby, NodeJS, Perl, etc.

**Example (PHP) :**

```php
<html>
<body>
Hello <?php echo $_GET["name"]; ?>
</body>
</html>
```
Request : `http://example.com/index.php?name=adam` <br>
Response sent to client :
```
<html>
<body>
Hello adam
</body>
</html>
```

- The client never sees the backend code (PHP, Python, etc.). Backend processing generates the HTML displayed in the browser.
- Backend functionality enables interactivity but also introduces security risks if not handled properly

## How a Website Request Works

When you request a website in your browser (e.g., tryhackme.com), multiple steps happen behind the scenes to fetch and display the webpage. Here is the full flow:

### 1. Request Initiation
- The user types a URL in the browser (e.g., `https://tryhackme.com`) or clicks a link.
- The browser prepares to load the requested webpage.

### 2. Check Local Cache
- The browser first checks its local cache to see if the IP address of the website is already stored.
- If the IP address is found, the browser can skip DNS queries.

### 3. Query Recursive DNS Server
- If the IP is not in the local cache, the browser queries the recursive DNS server (usually provided by your ISP or a custom DNS like Google DNS).
- The recursive server also has a cache of recently resolved domains.

### 4. Query Root and Authoritative DNS Servers
- If the recursive server does not have the IP address cached:
  1. It queries a root DNS server.
  2. The root server redirects it to the correct TLD (Top-Level Domain) server (e.g., `.com`).
  3. The TLD server points to the authoritative DNS server for the domain.

### 5. Receive IP from DNS
- The authoritative DNS server returns the IP address of the website to the recursive DNS server.
- The recursive server sends this IP back to the browser.
- The browser may cache this IP for future requests (TTL).

### 6. Traverse Network
- The request passes through network firewalls and Web Application Firewalls (WAF), which may filter malicious traffic.

### 7. Traverse Load Balancer
- If the website uses a **load balancer**, the request is forwarded to one of the multiple servers behind it.
- The load balancer chooses the server using algorithms like round-robin or least connections.

### 8. Connect to Web Server
- The browser connects to the web server using port 80 (HTTP) or port 443 (HTTPS) at the IP address provided by DNS.

### 9. HTTP Request
- The browser sends an HTTP GET request to the web server to fetch the website content.
- Request headers may include `Host`, `User-Agent`, `Cookies`, etc.

### 10. Web Application Responds
- The web application on the server processes the request.
- If needed, it interacts with a database to fetch dynamic content.
- The server sends back HTML, CSS, JavaScript, images, and other resources.

### 11. Render Webpage
- The browser receives the response and starts rendering the page.
- HTML defines the structure, CSS styles it, and JavaScript adds interactivity.
- The final webpage is displayed to the user.

---

**Summary Flow :**

1. Browser → check local cache  
2. Browser → recursive DNS server  
3. Recursive DNS → root & TLD → authoritative DNS  
4. Authoritative DNS → return IP  
5. Request → WAF & firewalls  
6. Request → load balancer  
7. Browser → connect to web server (port 80/443)  
8. Web server → receive GET request  
9. Web application → process request (database if needed)  
10. Browser → render HTML/CSS/JS → viewable webpage
