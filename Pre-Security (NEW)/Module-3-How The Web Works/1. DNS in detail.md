# What is DNS?

## Introduction
DNS (Domain Name System) is a core networking service that translates human-readable domain names (like `www.example.com`) into IP addresses that computers use to locate and communicate with each other on a network or the Internet.  

Think of DNS as the phonebook of the Internet : it allows users to access websites without remembering numeric IP addresses like `104.26.10.229`.

> Computers only understand IP addresses, not domain names like `tryhackme.com`. DNS was created to translate (resolve) human-readable domain names into IP addresses.

## DNS: Protocol and Service
- DNS is both a **protocol** and a **network service**:
  - **Protocol :** Defines how devices communicate to request and provide domain name resolution.
  - **Service/System :** Servers run the DNS service to store and respond to these queries.  
  
> "The Domain Name System (DNS) is a network protocol and service that resolves human-readable hostnames, such as `tryhackme.com`, into IP addresses that computers understand."

---

## Why DNS Exists

1. **Computers Understand IP Addresses Only**
   - Computers and devices can only work with IP addresses.
   - Example: `104.26.10.229` (IPv4) or `2606:4700:20::681a:be5` (IPv6)
   - All communication over the Internet uses these numbers.

2. **Humans Prefer Names**
   - Humans find it easier to remember names rather than numbers.
   - Example: remembering `tryhackme.com` is easier than `104.26.10.229`.

3. **DNS Bridges the Gap**
   - DNS translates domain names into IP addresses so computers can connect.
   - Example: When you type `www.tryhackme.com`, your computer asks a DNS server for the IP. The DNS server responds with `104.26.10.229`, and then your computer connects to that server.

**Analogy :**  

The Internet is like a city :  
- Every house has an address (IP) for delivery.  
- Humans remember names (domain names).  
- DNS acts as a phonebook, converting names to addresses for computers.

## Domain Hierarchy

The Domain Name System (DNS) organizes domain names in a hierarchical structure, starting from the root domain at the top, branching into Top-Level Domains (TLDs), then Second-Level Domains (SLDs), and optionally subdomains.

### TLD (Top-Level Domain)
- The TLD is the rightmost part of a domain name.
- Example: In `tryhackme.com`, the TLD is `.com`.
- Two types of TLDs:
  1. **gTLD (Generic Top-Level Domain)** – Indicates the purpose of the domain:
     - `.com` → Commercial  
     - `.org` → Organization  
     - `.edu` → Education  
     - `.gov` → Government  
  2. **ccTLD (Country Code Top-Level Domain)** – Indicates a country or region:
     - `.ca` → Canada  
     - `.co.uk` → United Kingdom  
- New gTLDs exist, e.g., `.online`, `.club`, `.website`, `.biz`.

### Second-Level Domain (SLD)
- The SLD sits to the left of the TLD.
- Example: In `tryhackme.com`, the SLD is `tryhackme`.
- Rules for SLD:
  - Maximum 63 characters
  - Allowed characters: `a-z`, `0-9`, `-` (hyphen)
  - Cannot start or end with hyphens
  - No consecutive hyphens

### Subdomain
- A **subdomain** is placed to the left of the SLD, separated by a dot.
- Example: In `admin.tryhackme.com`, `admin` is the subdomain.
- Rules for subdomains:
  - Maximum 63 characters per subdomain
  - Allowed characters: `a-z`, `0-9`, `-` (hyphen)
  - Cannot start or end with hyphens
  - No consecutive hyphens
- Multiple subdomains can be chained, e.g., `jupiter.servers.tryhackme.com`.
- Maximum total length of a domain (including subdomains) is 253 characters.
- There is no limit on the number of subdomains you can create.

## Record Types

### DNS Record Types

DNS (Domain Name System) records are instructions that tell the Internet how to handle a domain name. They define where your domain should send web traffic, emails, subdomains, and verification information. DNS isn't just for websites—different record types serve different purposes.

Here are the most common DNS record types :

---

### 1. A Record (IPv4 Address)
- **Purpose:** Points a domain or subdomain to an IPv4 address.
- **Example:**  mywebsite.com → `192.168.10.50`
- When someone types `mywebsite.com` in a browser, DNS sends them to the server with IP `192.168.10.50`.

---

### 2. AAAA Record (IPv6 Address)
- **Purpose:** Same as A record, but for IPv6 addresses.
- **Example:**  mywebsite.com → `2606:4700:20::681a:be5`
- When someone types mywebsite.com in a browser, DNS sends the user to the server at 2606:4700:20::681a:be5 (the IPv6 address)

---

### 3. CNAME Record (Canonical Name / Alias)
- **Purpose:** Points one domain or subdomain to another domain (not directly to an IP). Useful for redirecting or aliasing domains.
- **Example:**  shop.mywebsite.com → shops.shopify.com
- When someone visits `shop.mywebsite.com`, DNS resolves it to `shops.shopify.com`, which then resolves to an IP.

---

## 4. MX Record (Mail Exchange)
- **Purpose:** Tells the Internet which mail server handles emails for the domain.
- **Example:**  
  `Priority 10 → mail.google.com`
- Emails sent to `info@mywebsite.com` will go to the server `mail.google.com`.  
- **Priority:** Lower numbers are tried first. If multiple servers exist, this ensures backup servers are used if the primary fails.

---

## 5. TXT Record (Text / Verification)
- **Purpose:** Stores text data for verification, security, or configuration.
- **Examples:**
  
i. `"v=spf1 include:_spf.google.com ~all"` – Only allows Google’s servers to send emails for the domain (prevents spam).
> This says: “Only Google’s servers are allowed to send email for mywebsite.com.” (Helps prevent spam)

ii. `"google-site-verification=abc123xyz"` – Used to verify domain ownership for Google services.
- TXT records can store any text information related to the domain, often used for security or validation purposes.
> Used to prove domain ownership to Google.

# Making a DNS Request

When you type a domain name in your browser (e.g., `www.tryhackme.com`), several steps happen behind the scenes to find the correct IP address. This process ensures that your computer can reach the website.  

---

## Step-by-Step Process

1. **Check Local Cache**
   - Your computer first checks its local DNS cache to see if the domain has been looked up recently.
   - **Explanation:** If the domain is cached, your computer uses the stored IP address, avoiding extra network requests.
   - **Example:** Visiting `google.com` multiple times may use the cached IP address.

2. **Recursive DNS Server**
   - If the address is not in your local cache, your computer sends a request to a **Recursive DNS Server**.
   - Usually provided by your **ISP**, but you can also choose custom DNS servers (like Google DNS or Cloudflare DNS).
   - The recursive server also has a cache of recently resolved domain names.
   - **Explanation:** If the recursive server has the answer, it returns the IP to your computer, and the request ends here.

3. **Root DNS Servers**
   - If the recursive server cannot resolve the domain, it queries the **root DNS servers** (the backbone of the Internet’s DNS system).
   - The root server does not have the exact IP but directs the request to the correct **Top-Level Domain (TLD) server** based on the domain extension (.com, .org, .net, etc.).
   - **Example:** For `www.tryhackme.com`, the root server points to the `.com` TLD server.

4. **TLD Server**
   - The **TLD server** knows which **authoritative DNS server** handles the domain.
   - **Example:** For `tryhackme.com`, the TLD server directs the request to `kip.ns.cloudflare.com` and `uma.ns.cloudflare.com`.
   - You'll often find multiple nameservers for a domain name to act as a backup in case one goes down.

5. **Authoritative DNS Server**
   - This server stores the actual DNS records (A, AAAA, MX, CNAME, TXT) for the domain.
   - It returns the requested record to the recursive server.
   - The recursive server caches the response for future requests (TTL – Time To Live) before sending it to your computer.
   - **Explanation:** Caching improves performance by avoiding repeated lookups.

## Summary of Flow

<img width="550" height="450" alt="image" src="https://github.com/user-attachments/assets/437256fe-30dc-4489-8a98-4e13f29a2ebf" />

**Example in Action:**

1. Type `www.tryhackme.com` in your browser.
2. Your computer checks the local cache → not found.
3. Sends request to Recursive DNS Server → not found.
4. Recursive queries Root Server → directs to `.com` TLD server.
5. TLD server directs to Cloudflare Authoritative Server.
6. Authoritative server returns IP `104.26.10.229`.
7. Recursive server caches IP for future requests and sends it back to your computer.
8. Browser connects to `104.26.10.229` to load the website.

> This whole process happens in milliseconds, making websites load quickly without the user ever knowing the DNS lookup process occurred.
