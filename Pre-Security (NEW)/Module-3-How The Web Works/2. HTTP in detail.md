# HTTP in Detail

## What is HTTP?

**HTTP (HyperText Transfer Protocol)** is the protocol used whenever you view a website.  
It was developed by **Tim Berners-Lee** and his team between 1989–1991.  

HTTP defines a set of rules that allow your web browser to communicate with web servers and request webpage data such as:  

- HTML pages  
- Images  
- Videos  
- Other resources  

> Whenever you type a website like `www.tryhackme.com` in your browser, your browser uses HTTP to ask the server for the content of the webpage.  

**Key Point:** HTTP is **stateless**, which means each request is independent and the server does not remember previous requests from the same client.

---

## What is HTTPS ?

**HTTPS (HyperText Transfer Protocol Secure)** is the **secure version of HTTP**.  

HTTPS encrypts the data exchanged between your browser and the web server. This ensures:  

1. **Privacy:** Nobody can see the data you send or receive (like login credentials).  
2. **Integrity:** Data cannot be tampered with during transmission.  
3. **Authentication:** Confirms that you are communicating with the intended web server, not an impersonator.

> When you visit `https://tryhackme.com`, HTTPS ensures your connection is secure and the server you are talking to is legitimate.


| Protocol | Port | Security | Purpose |
|----------|------|---------|---------|
| HTTP     | 80   | No      | Standard web communication |
| HTTPS    | 443  | Yes     | Secure web communication (encrypted) |

**Example in Action:**  
- HTTP: `http://example.com` → Data sent in plain text.  
- HTTPS: `https://example.com` → Data is encrypted, keeping it secure from attackers.

> **Tip:** Always look for the **padlock icon** in the browser when using HTTPS to ensure the connection is secure.

## HTTP Requests and Responses

When we access a website, your browser will need to make requests to a web server for assets such as HTML, Images, and download the responses. Before that, you need to tell the browser specifically how and where to access these resources, this is where URLs will help.


### What is a URL ? (Uniform Resource Locator) 

A URL is predominantly an instruction on how to access a resource on the internet. A URL is the address used to access resources on the Internet. It tells your browser **how and where** to find a resource.  

**Example URL:**

<img width="500" height="350" alt="image" src="https://github.com/user-attachments/assets/84beaabb-80af-4023-b81d-291a03ab1671" />


### Parts of a URL:

| Part | Description |
|------|-------------|
| **Scheme** | The protocol to use, e.g., `http`, `https`, `ftp`. |
| **User** | Optional username/password for authentication (e.g., `user:password`). |
| **Host** | The domain name or IP of the server (e.g., `tryhackme.com`). |
| **Port** | The port number to connect to (default `80` for HTTP, `443` for HTTPS). |
| **Path** | The location of the resource on the server (e.g., `/view-room`). |
| **Query String** | Extra data sent to the server (e.g., `?id=1`). |
| **Fragment** | A reference to a section of the page (e.g., `#task3`). |

> URLs provide all the instructions a browser needs to fetch a resource from the server.

## Making an HTTP Request

A browser communicates with a server by sending **HTTP requests**.  

**Basic Request Example:**

<pre>
GET / HTTP/1.1

Host: tryhackme.com
User-Agent: Mozilla/5.0 Firefox/87.0
Referer: https://tryhackme.com/

</pre>

### Breakdown of the Request:

1. `GET / HTTP/1.1` – Requesting the home page `/` using the GET method and HTTP/1.1 protocol.  
2. `Host: tryhackme.com` – The domain we want to access.  
3. `User-Agent: Mozilla/5.0 Firefox/87.0` – Browser information.  
4. `Referer: https://tryhackme.com/` – The page that referred us to this URL.  
5. A **blank line** – Indicates the end of the request.

> This tells the server exactly what resource you want and some info about your client.

## HTTP Response

The server replies with an HTTP response, containing status, headers, and content.

**Example Response:**

<pre>
HTTP/1.1 200 OK
Server: nginx/1.15.8
Date: Fri, 09 Apr 2021 13:34:03 GMT
Content-Type: text/html
Content-Length: 98

&lt;html&gt;
&lt;head&gt;
    &lt;title&gt;TryHackMe&lt;/title&gt;
&lt;/head&gt;
&lt;body&gt;
    Welcome To TryHackMe.com
&lt;/body&gt;
&lt;/html&gt;
</pre>

### Breakdown of the Response:

1. HTTP/1.1 200 OK – HTTP version and status code. 200 OK means the request was successful.
2. Server: nginx/1.15.8 – Server software and version.
3. Date: Fri, 09 Apr 2021 13:34:03 GMT – Server’s current date and time.
4. Content-Type: text/html – Type of data being sent (HTML in this case).
5. Content-Length: 98 – Size of the response body in bytes.
6. Blank line – Marks the end of the headers.
7. HTML content – The requested page content (homepage in this case).

> The server’s response provides the requested resource along with metadata (headers) so the browser can process it properly.

## HTTP Methods

HTTP methods are used by clients (like web browsers) to tell the web server what action they want to perform on a resource. There are many HTTP methods, but the most common ones are GET, POST, PUT, and DELETE.


### 1. GET Request
- **Purpose:** Retrieve information from the web server.
- **Example:** Requesting the homepage or a blog article.
- **Note:** GET requests should **not change any server data**.

### 2. POST Request
- **Purpose:** Send data to the web server, usually to create new records.
- **Example:** Submitting a registration form or posting a comment.
- **Note:** POST requests **can modify server data**.

### 3. PUT Request
- **Purpose:** Update existing information on the web server.
- **Example:** Updating your profile information on a website.
- **Note:** PUT is idempotent — sending the same request multiple times has the same effect as sending it once.

### 4. DELETE Request
- **Purpose:** Remove information/records from a web server.
- **Example:** Deleting a comment or removing a file from a server.
- **Note:** DELETE requests **permanently remove the resource**.

**Summary :**

| HTTP Method | Purpose                                | Example Use Case                     |
|------------|----------------------------------------|-------------------------------------|
| GET        | Retrieve data                          | Viewing a webpage                   |
| POST       | Create new data                        | Submitting a form                   |
| PUT        | Update existing data                   | Editing profile info                |
| DELETE     | Remove data                             | Deleting a post or file             |

## HTTP Status Codes

HTTP status codes are **3-digit numbers** sent by a web server to a client (like a browser) to indicate the result of the client's request. They tell the client whether the request was successful, redirected, or encountered an error.

## Status Code Ranges

HTTP status codes are grouped into 5 ranges :

| Range       | Name                 | Meaning                                                                                  |
|------------|---------------------|------------------------------------------------------------------------------------------|
| 100-199    | Informational       | The request is partially received; client should continue sending the rest. Rarely used today. |
| 200-299    | Success             | The request was successfully received, understood, and accepted.                        |
| 300-399    | Redirection         | The client needs to make another request to a different URL/resource.                   |
| 400-499    | Client Errors       | The request contains an error or cannot be fulfilled by the client.                      |
| 500-599    | Server Errors       | The server failed to process a valid request due to a server-side problem.              |

## Common HTTP Status Codes

| Code | Meaning                     | Explanation & Example                                                                 |
|------|-----------------------------|---------------------------------------------------------------------------------------|
| 200  | OK                          | Request completed successfully. **Example:** Browser loaded a webpage correctly.      |
| 201  | Created                     | A new resource has been created. **Example:** New user account or blog post created. |
| 301  | Moved Permanently           | Resource permanently moved to a new URL. **Example:** Page moved to another site.    |
| 302  | Found (Temporary Redirect)  | Resource temporarily moved. **Example:** Redirect for a temporary campaign page.    |
| 400  | Bad Request                 | Client request is malformed or missing information. **Example:** Missing required form data. |
| 401  | Unauthorized                | Client must authenticate to access resource. **Example:** Login required.            |
| 403  | Forbidden                   | Client is not allowed to access resource, even if authenticated.                     |
| 404  | Not Found                   | Resource does not exist at the requested URL. **Example:** Typing wrong page URL.    |
| 405  | Method Not Allowed           | HTTP method not allowed for resource. **Example:** Sending GET to an endpoint expecting POST. |
| 500  | Internal Server Error        | Server encountered an unexpected condition. **Example:** Server crash or misconfiguration. |
| 503  | Service Unavailable          | Server cannot handle request (overload or maintenance).                               |

## HTTP Headers

Headers are extra information sent along with an HTTP request or response. They help the client (browser) and server understand how to handle the data. Even though headers are not strictly required, without them websites may not load or function correctly.

**Common Request Headers**

Request headers are sent from the client (usually your browser) to the server.

| Header | Purpose | Example / Explanation |
|--------|---------|---------------------|
| **Host** | Specifies which website on the server you want to access (important if the server hosts multiple websites). | `Host: tryhackme.com` |
| **User-Agent** | Tells the server which browser software and version you are using. Helps the server format content properly. | `User-Agent: Mozilla/5.0 Firefox/87.0` |
| **Content-Length** | Specifies the size of the data being sent to the server (like form submissions). | `Content-Length: 348` |
| **Accept-Encoding** | Tells the server what compression methods the client supports to reduce data size. | `Accept-Encoding: gzip, deflate` |
| **Cookie** | Sends stored cookies to the server to maintain session or remember user data. | `Cookie: sessionId=abc123; theme=dark` |

**Common Response Headers**

Response headers are sent from the server back to the client after a request.

| Header | Purpose | Example / Explanation |
|--------|---------|---------------------|
| **Set-Cookie** | Sends cookies to the client which the browser will store and send back on future requests. | `Set-Cookie: sessionId=abc123; Path=/; HttpOnly` |
| **Cache-Control** | Instructs the browser how long to cache the response before requesting it again. | `Cache-Control: max-age=3600` |
| **Content-Type** | Indicates the type of data being returned (HTML, CSS, JS, Images, etc.) so the browser knows how to process it. | `Content-Type: text/html; charset=UTF-8` |
| **Content-Encoding** | Shows the method used to compress the data for faster transmission. | `Content-Encoding: gzip` |

> Headers are like extra instructions in a message between your browser and a server. Request headers tell the server about your browser and what you want, while response headers tell your browser how to handle the data sent back. Without headers, websites may not display or work correctly.

## Cookies

Cookies are small pieces of data stored on your computer by a web server. They are sent back to the server with each subsequent request to help the server remember you or your preferences.  

Because HTTP is stateless (it doesn’t remember previous requests), cookies are essential for tasks like authentication, personal settings, or tracking user activity.

> Cookies are small pieces of data stored on your computer by websites you visit. Because HTTP is stateless (it does not remember who you are between requests), cookies are used to store information so the website can recognize you on later requests. 

### How Cookies Work

1. When you visit a website, the server may send a Set-Cookie header in its HTTP response.  
2. Your browser stores this cookie locally.  
3. On subsequent requests to the same website, your browser automatically sends the cookie back to the server.

- Client requests a webpage.
- Server returns a form asking for the user’s name.
- Client submits the form with name=adam.
- Server responds with Set-Cookie: name=adam → browser stores this.
- Next request: browser sends Cookie: name=adam.
- Server sees the cookie and displays a personalized message instead of the form.
- Result : Cookies allow the server to remember users across multiple HTTP requests.

> Cookies can be used for many purposes but are most commonly used for website authentication. The cookie value won't usually be a clear-text string where you can see the password, but a token (unique secret code that isn't easily humanly guessable).
