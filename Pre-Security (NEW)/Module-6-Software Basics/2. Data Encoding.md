# Data Encoding 

## Introduction 

- Computers don’t understand letters or words directly.
- They only understand 0s and 1s (binary).
- So, every letter, number, or emoji is stored as a number inside the computer.

- Encoding is just a rule that tells :
  - which number = which character  
  - example : a number can mean `A`, `B`, or `😊`

- When saving and opening files, both sides must use the same encoding.
- If not, the text may look weird or unreadable (gibberish).

<pre>
Example : H → 72 e → 101......
So `Hello` = `72 101 108 108 111`
Encoding = rule that gives meaning to these numbers.
Problem : Different encodings = different meanings for same numbers.
- Save with one encoding → `72 = H`
- Open with another → `72 = @`
So : Hello → @#$$%
This wrong output is called gibberish.
</pre>

- In short :
  - Text → converted to numbers → stored in computer  
  - Encoding = how we convert between text and numbers

 
> Computers save text as numbers, not letters

## ASCII (American Standard Code for Information Interchange)

- ASCII is a character encoding standard.
- It defines a mapping between numeric values (0–127) and text characters.

### Core Concept
- Computers store data in binary (0s and 1s).
- ASCII assigns a unique 7-bit binary value to each character.
- This creates a fixed mapping :

Character → Decimal → Binary → Hex

### Character Coverage
ASCII supports:
- Uppercase letters: `A–Z`
- Lowercase letters: `a–z`
- Digits: `0–9`
- Punctuation: `! @ # $ %`
- Control characters (non-printable):
- `\n` → newline
- `\t` → tab
- `DEL` → delete

### Example Encoding

A → 65 → 01000001 → 0x41 <br>
a → 97 → 01100001 → 0x61 <br>
0 → 48 → 00110000 → 0x30

### String Representation

- A string is stored as a sequence of ASCII codes.

Example : "Try" <br>
Stored as : 84 114 121 <br>
Binary : 01010100 01110010 01111001

### Key Properties
- Fixed-size encoding → 7 bits per character
- Total characters → 128
- Characters are ordered sequentially
  - Example: `a=97, b=98, c=99`

---

### Why ASCII Uses 0–127

ASCII uses 7 bits to represent each character.

Bit Explanation : 
With 7 bits, total possible values :

2<sup>7</sup> = 128

So the range becomes : 0 to 127 → 128 unique values

### What this means

Each number in this range is assigned one specific character.

### Example

65 → A
97 → a
48 → 0
10 → \n (newline)

### Key Idea

ASCII = mapping of : Numbers (0–127) → Characters

### Why only 128 characters ?
- Early computers had :
  - Limited memory
  - Focus on English text only
- So 128 characters were enough at that time

---

### Extended ASCII
- Uses 8 bits (0–255) to extend character range.
- Includes regional characters (e.g., ñ, ü).
- Not standardized globally → multiple variants (ISO-8859).

---

### Limitations
- Cannot represent :
  - Non-English scripts (Arabic, Chinese, Japanese)
  - Emojis and modern symbols
- Limited to basic text representation

---

### Summary
- ASCII = 7-bit encoding standard
- 7 bits → 128 values → 128 characters
- Each value has a fixed meaning
- Maps numbers to characters
- Forms the foundation of modern encodings

## Unicode

- Unicode = Universal Character Encoding Standard  
- Developed to represent all characters from all languages

### Why Unicode is Needed

- ASCII was limited (only 128 characters → English only).
- Extended encodings (ISO-8859) → different standards for different regions
- Problem :
  - Same number → different characters in different encodings → caused confusion and wrong text display
  - Leads to gibberish text

### What is Unicode
- Unicode is a global standard that assigns a unique number (code point) to every character.

### Format

U+XXXX

### Examples

A → U+0041 <br>
Ω → U+03A9 <br>
あ → U+3042 <br>
😊 → U+1F60A

---

### Key Features
- Supports :
  - All languages (English, Arabic, Chinese, etc.)
  - Symbols
  - Emojis
- Same standard worldwide → avoids encoding mismatch

## Code Point
- Each character has a unique number called a code point.

Example :

😊 → U+1F60A


---

## UTF Encodings (Storage Formats)

### UTF-8
- Full form : Unicode Transformation Format - 8 bit
- Uses 1 to 4 bytes
- ASCII characters → 1 byte
- Emoji/complex → up to 4 bytes
- Most widely used (web)

### UTF-16
- Full form : Unicode Transformation Format - 16 bit
- Uses 2 or 4 bytes
- Common characters → 2 bytes
- Rare/emoji → 4 bytes

### UTF-32
- Full form : Unicode Transformation Format - 32 bit
- Uses fixed 4 bytes
- Simple but memory heavy

### Important Difference
- Unicode → defines characters (code points)
- UTF-8/16/32 → define how those characters are stored

### Examples

🔥 → U+1F525 <br>
龍 → U+9F8D <br>
ツ → U+30C4 <br>
♞ → U+265E


### Problem Solved by Unicode
- No need for multiple encodings
- Same text appears correctly everywhere
- Supports mixing multiple languages in one file

---

### Summary
- Unicode = universal character system
- Code point = unique number for each character
- UTF-8/16/32 = storage formats
- UTF-8 = most commonly used

---

## ASCII vs Unicode
- ASCII :
  - Range: 0–127
  - Only English characters

- Unicode:
  - Range : U+0000 → U+10FFFF
  - Covers all languages + symbols + emojis

Unicode uses only 21 bits

Total possible values : 2<sup>21</sup> = 1,114,112
That range in hex is : U+0000 → U+10FFFF
> Unicode stops at U+10FFFF because it uses 21 bits, not because of hex limits

Note on Range
- `U+10FFFF` is the maximum Unicode code point
- It is written in hexadecimal (base 16)
- Unicode is not limited to 4 digits (U+XXXX)
- It can go up to 6 hex digits

**What does 10 mean in 10FFFF ?**

- In hexadecimal :
A = 10 (decimal)
- But :
10 (hex) = 16 (decimal)
- So :
  - `10` in `10FFFF` is hexadecimal, not decimal
  - It represents 16 in decimal
  - It follows place value, not single-digit replacement

---

## Key Point
- ASCII = small mapping table  (2<sup>7</sup> = 128)
- Unicode = large universal mapping table (2<sup>21</sup> = 1,114,112)
