## Downloading Files (wget)

In Linux, downloading files is often done directly from the terminal instead of using a browser.  
This is useful when working on servers, remote machines, or automation scripts.

wget is a simple and powerful tool that lets you download files using a URL.  
You just provide the link, and it handles the rest like connecting, downloading, and saving the file.

**Basic Command :**

```
wget http://example.com/file.txt
```

### How it Works ?
- Sends a request to the given URL
- Connects to the remote server
- Downloads the file into your current directory
- Saves the file with the same name

### Common Options :

#### Save with Different Name
```
wget -O newname.txt http://example.com/file.txt
````
- -O	Output file name option
- newname.txt	New name to save file

#### Download in Background
```
wget -b http://example.com/file.txt
```
- -b	Run download in background

#### Resume Download
```
wget -c http://example.com/file.txt
```
- -c	Continue incomplete download

**Note :**
- File downloads into current directory
- Requires correct URL
- Works with HTTP and HTTPS

---

### Transferring Files Using SCP (Secure Copy)

scp is used to copy files between two systems securely.  
Unlike the normal cp command (which works only on one system), scp allows transfer between different machines.

It uses SSH, which means :
- Connection is secure  
- Data is encrypted  
- User authentication is required  

Working on a model of SOURCE and DESTINATION, SCP allows you to :
- Copy files & directories from your current system to a remote system
- Copy files & directories from a remote system to your current system

---

### Copy File (Local to Remote)

#### Example 

| Variable | Value |
|----------|------|
| Remote IP | 192.168.1.30 |
| Remote User | ubuntu |
| Local File | important.txt |
| Remote Save Name | transferred.txt |

#### Command
```
scp important.txt ubuntu@192.168.1.30:/home/ubuntu/transferred.txt
```

**Command breakdown :**
- `scp` :	Secure copy command
- `important.txt` :	File on your system
- `ubuntu` : Username on remote system
- `192.168.1.30` : Remote machine IP
- `:` :	Separator between host and path
- `/home/ubuntu/transferred.txt` :	Destination path and filename

---

### Copy File (Remote to local)

#### Example 

| Variable          | Value          |
|------------------|----------------|
| Remote IP        | 192.168.1.30   |
| Remote User      | ubuntu         |
| Remote File      | documents.txt  |
| Local Save Name  | notes.txt      |

#### Command
```
scp ubuntu@192.168.1.30:/home/ubuntu/documents.txt notes.txt
```

**Command breakdown :**

- `ubuntu@192.168.1.30` :	Remote login details
- `/home/ubuntu/documents.txt` : File on remote system
- `notes.txt` :	File name on your system

##  Serving Files From Your Host (Python HTTP Server)

Linux systems (like Ubuntu) come with Python3 already installed.  
Python provides a simple way to turn your system into a temporary web server so others can download files from it.

This is useful when you want to quickly share files between machines without setting up a full server.

### Idea

- Your system acts like a mini website  
- Files in your folder become downloadable  
- Other machines can access them using your IP  

### Start the Web Server

```
python3 -m http.server
```

**command breakdown :**
- python3	: Runs Python version 3
- -m : Runs a module as a script
- http.server :	Module that creates a web server

#### What Happens After Running ? 
- Server starts :	Runs in current directory
- Port used :	Default is 8000
- File access	: All files in folder become accessible
- Output shown :	Displays server address and port

---

### Downloading File from Server

From another terminal or machine :
```
wget http://MACHINE_IP:8000/filename
```

**command Breakdown :**
- wget :	Tool to download file
- http:// :	Protocol
- MACHINE_IP	: IP address of server
- :8000	: Port number
- /filename :	File to download

**What Happens During Download ?**

- Connect	wget : connects to server
- Request :	Asks for file
- Response :	Server sends file
- Save :	File is saved locally

**Note**
- Keep server running :	Do not close terminal running server
- Use another terminal :	Download must be done separately
- Stop server :	Press Ctrl + C
- Same network	: Both systems must be reachable

**Limitations :**
- No security :	No authentication
- Basic server :	Not for real-world hosting
- No indexing control :	Must know exact file name

## Processes 

A process is simply a program that is currently running on your system.  
Every time you run a command, open an app, or execute a script → a process is created.

Each process has a unique number called a PID (Process ID).

### Process Basics

| Concept | Meaning |
|--------|--------|
| Process | Running program |
| PID | Unique ID for each process |
| Kernel | Controls and manages processes |

PIDs increase one by one as new processes start.

### How Processes Start 

When you turn on a Linux system, processes don’t just appear randomly.  
There is a proper flow of how everything starts and runs.

### Step 1 : System Boot Starts First Process

- When the system boots, the first process starts automatically
- This process is called systemd
- It usually has PID = 1

<img width="847" height="56" alt="image" src="https://github.com/user-attachments/assets/e7ac3649-dca3-4c13-8509-7d8f4d5226d5" />


- systemd : Main process that controls everything 
- PID 1 : First process in the system 

Think of systemd as the "manager" of all processes  

### Step 2 : systemd Starts Other Processes

- After starting, systemd launches other programs and services  
- Every new process is created from an existing one  

- Parent Process : The one that starts another process 
- Child Process : The one that gets started 

So, most processes are children of systemd

### Step 3 : Process IDs (PID)

- Each process gets a unique ID  
- IDs increase as new processes are created  

-  PID 1 : systemd 
- PID 2, 3, 4... : New processes 

Helps the system track and manage processes  

###  Step 4 : Resource Sharing (Namespaces Idea)

The system divides resources like :
- CPU  
- Memory (RAM)  
- Priority  

into smaller parts for processes.


- Namespace : Separate space for processes 
- Isolation : Processes cannot see others outside their group 

Simple idea : System resources are split into "sections", and each process gets its own share  

---

### Why Namespaces Matter ?


- Security : Processes are isolated 
- Stability : One process doesn’t affect others
- Control : Better resource management 

### Full Flow 

- System boots
- systemd starts (PID 1)
- systemd launches other processes
- Each process gets PID
- Resources are divided using namespaces 

### Key Points

- systemd is the starting point of all processes  
- Every process comes from another process  
- Each process gets a unique PID  
- System resources are shared in a controlled way  
- Processes are isolated for security

### Starting Processes/Services on Boot (systemctl)

Some programs are important and need to run automatically when the system starts.  
For example, web servers, databases, or file transfer services.  
Instead of starting them manually every time, we can configure them to start on boot.

### systemctl (Service Manager)

systemctl is used to control and manage services in Linux.  
It works with systemd, which is responsible for handling system processes.

### Basic Syntax

```
systemctl [option] [service]
```
- systemctl : command used to manage services
- option : action (start, stop, enable, etc.)
- service : name of the service (like apache2)

### Common Commands

**1. Start a Service** 
```
systemctl start apache2
```
Starts the service immediately.

**2. Stop a Service**
```
systemctl stop apache2
```
Stops the running service.

**3. Enable Service on Boot**
```
systemctl enable apache2
```
Makes the service start automatically when the system boots.

**4. Disable Service on Boot**
```
systemctl disable apache2
```
Prevents the service from starting on boot.

**5. Check Service Status**
```
systemctl status apache2
```
Shows whether the service is running or not, along with details.

We can do five options with systemctl :

- Start : to run service now
- Stop : to stop it
- Enable : to run on boot
- Disable : to stop it from boot
- Status : to check it

**Simple flow :** 
- Start the service manually
- Enable it if you want it to run on boot
- Check its status to confirm

### Background & Foreground Processes 

In Linux, every command you run becomes a process.  
These processes can run in two modes:

- Foreground : runs directly in your terminal  
- Background : runs behind the scenes  

Understanding this helps you multitask efficiently in the terminal.

### Foreground Process (Default Behavior)

- Runs in the terminal you are using  
- Shows output directly  
- Blocks the terminal until it finishes  

### Example
```
echo "Hello"
```

While this runs, you cannot execute another command until it completes

### Background Process

- Runs without blocking your terminal
- Terminal becomes free for other commands
- Output is not shown immediately

**Run in Background :**
```
command &
```
**Example**
```
sleep 10 &
```

**Output example :**

[1] 1234
[1] : Job number
1234 : Process ID (PID)

The command runs, but your terminal is free instantly

**Why Backgrounding is Useful ?**
- Run long tasks without waiting
- Perform multiple operations at once
- Keep terminal responsive

**Common Use Cases**
- Copying large files
- Running scripts
- Downloads
- Starting servers

**Pausing a Running Process**
You can pause a foreground process and move it to background:
```
Ctrl + Z
```
What happens :
- Process is stopped temporarily
- Sent to background
- Terminal becomes free

**Bringing Process Back to Foreground**
```
fg
```
**What happens :**
- Process resumes execution
- Comes back to terminal
- Output becomes visible again

**Typical Workflow**
- Run command normally → foreground
- Press Ctrl + Z → pause and send to background
- Run other commands
- Use fg → resume process in foreground

**Useful commands :**
```
ps aux   # view running processes
fg       # bring process to foreground
```

## Maintaining Your System : Automation (Cron Jobs)

In Linux, you can automate tasks so they run automatically at specific times.  
This is useful for things like :
- Backing up files  
- Running scripts  
- Starting programs  

### What is Cron?

- cron is a service that runs in the background  
- It automatically executes scheduled tasks  
- These tasks are called cron jobs  

### What is Crontab ?

- A crontab is a file where you define scheduled tasks  
- Each line in the file = one task  
- cron reads this file and runs commands accordingly  

### Edit Crontab

<img width="500" height="300" alt="image" src="https://github.com/user-attachments/assets/4e394a4d-711e-402b-9fe1-79923004a301" />

```
crontab -e
```
Opens the crontab file in an editor (like nano)

**Crontab Format :** MIN HOUR DOM MON DOW CMD

- MIN :	Minute (0–59)
- HOUR : Hour (0–23)
- DOM :	Day of month (1–31)
- MON :	Month (1–12)
- DOW	: Day of week (0–7)
- CMD :	Command to run

**Example (Backup Every 12 Hours)**
```
0 */12 * * * cp -R /home/user/Documents /backup/
```

- 0	: Run at minute 0
- */12 : Every 12 hours
- * :	Every day
- *	: Every month
- * :	Every weekday
- cp -R : Command to execute
- Wildcard (*) : means "any value" : Used when you don’t care about that field
- Source (what is being backed up) : /home/user/Documents
- Destination (where backup is stored) : /backup/

#### Why Use Cron ?
- Automates repetitive tasks
- Saves time
- Runs tasks without manual effort

#### Useful Tips
- Each line = one scheduled task
- Make sure command paths are correct
- Test commands before adding to crontab

#### Helpful Tools
- Crontab Generator : helps create cron format
- Cron Guru : explains cron expressions

## Maintaining Your System: Package Management

Linux makes it easy to install and manage software using something called packages and repositories (repos).

### What are Packages ?

- A package is a ready-to-install software bundle  
- It contains :
  - Program files  
  - Dependencies  
  - Installation instructions  

Example : text editors, browsers, tools  

### What are Repositories (Repos) ?

- A repository is a storage location for packages  
- Think of it like an app store for Linux

Developers upload their software here  
Users download and install from here  

### Types of Repositories

- Default (official) repos → maintained by OS  
- Community repos → created by developers or users  

You can add extra repos to get more software  

### Managing Software with apt

apt is the main tool used to manage packages in Ubuntu.

### Common Commands

**Refresh list of available packages :**

```
apt update
```

**Install software :**
```
apt install package-name 
```

**Remove software :**

```
apt remove package-name
```

---

### Managing Repositories (Add & Remove)

In Linux, we use apt to install and manage software.  
It not only installs programs but also handles where those programs come from (repositories).

### What is Happening Here ?

- Software comes from repositories (repos)
- Sometimes default repos don’t have what you need  
- So, you add a new repository manually  

### Why Use apt ?

- Installs software easily  
- Keeps software updated  
- Checks all added repositories during update  

### Adding a New Repository 

#### Step 1 : Add Security Key (GPG Key)

```
wget -qO - https://download.sublimetext.com/sublimehq-pub.gpg | sudo apt-key add -
```
- Verifies the software source
- Ensures it is trusted and safe

#### Step 2 : Add Repository File

Create a file inside :
```
/etc/apt/sources.list.d/
```
Example : sublime-text.list

This file stores the repository details

#### Step 3 : Update System
```
apt update
```
System now :
- Reads new repository
- Updates package list

**Step 4 : Install Software**
```
apt install sublime-text
```
Installs the software from the new repo

**Removing Repository**
- Option 1 : Remove using command
  `add-apt-repository --remove ppa:name`
- Option 2 : Manual removal
Delete the repo file from :
  `/etc/apt/sources.list.d/`

**Removing Installed Software**
```
apt remove sublime-text
```
Removes the installed program

**Why GPG Key is Important ?**
- Confirms software is genuine
- Prevents fake or harmful packages
- If key is invalid → install fails

**Key Understanding**
- Add key → trust source
- Add repo → tell system where software is
- Update → refresh list
- Install → get the software

## Maintaining Your System : Logs 

Logs are files that record what is happening in your system.  
They help you understand system activity, errors, and security events.


### Where Logs are Stored ? 

Most logs are found in :

```
/var/log
```

This folder contains log files for :
- System
- Applications
- Services

**What Do Logs Contain ?**

Logs store information like :

- System activity
- Errors and warnings
- User actions
- Service events

**Log Rotation (Automatic Cleanup)**
- Logs keep growing over time
- System automatically manages them using log rotation
This means :
- Old logs are archived or deleted
- New logs are created
- Prevents disk from filling up
