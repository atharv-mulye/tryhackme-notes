# Linux Fundamentals Part 2

### What is SSH ?
- SSH (Secure Shell) is a protocol used to remotely access and control Linux machines.
- It encrypts all data sent over the network, so your commands and information stay secure.
- Using SSH, you can :
  - Run commands on a remote machine.
  - Transfer files securely.
  - Manage servers without physically being at the machine.

### Steps to Connect via SSH

**1. Open a terminal**
   - On Linux/macOS : Use the built-in Terminal.
   - On Windows : Use PowerShell, Command Prompt, or Windows Terminal. You can also use PuTTY for GUI-based SSH.

**2. Use the SSH command**
   ```
   ssh username@IP_ADDRESS
   ```
- username : The account you want to log into on the remote machine.
- IP_ADDRESS : The IP address or hostname of the remote machine.

**3. Trust the host**
- The first time you connect, you may see : <br>
    `The authenticity of host 'IP_ADDRESS' can't be established. Are you sure you want to continue connecting (yes/no)?`
- Type yes and press Enter.

**4. Enter the password**
- Password input is hidden for security; just type it and press Enter.

**5. You are now connected**
- The terminal now executes commands on the remote machine, not your local computer.
- You can verify by checking the prompt, usually showing the username and hostname.

## Flags and Switches

### What Are Flags / Switches ?
- Flags (or switches) are extra options added to commands to change how they work.
- They help you get more control and better output from commands.
- Without flags, commands run in their default mode.

### Format
```
command -flag
command --long-flag
```

### Why Flags Are Useful ? 
- Show more information
- Change output format
- Include hidden data
- Make commands more powerful

### Example : ls Command

#### Default Behavior
```
ls
```
- Shows files and folders in the current directory.
- Does NOT show hidden files.
#### Show Hidden Files
```
ls -a
```
- -a = all
- Shows hidden files (files starting with .)

> Example : .hiddenfile  file1  folder1

#### Combine Flags
```
ls -la
```
- -l : long format (more details like permissions, size, owner)
- -a : include hidden files

### Human Readable Sizes
```
ls -lh
```
- -h = human-readable sizes (KB, MB instead of bytes)

#### Using --help
- Most commands provide a quick help menu.
```
ls --help
```
- Shows :
  - List of available flags
  - What each flag does
  - How to use the command

### Using Manual Pages (man)

#### What is man ?
- man = manual
- Provides detailed documentation for commands
Example :
```
man ls
```
**What You’ll See :**
- NAME : command name and purpose
- SYNOPSIS : how to use it
- DESCRIPTION : explanation
- OPTIONS : all flags and what they do

**Navigating Man Pages**
- ↑ ↓ : scroll up/down
- Space : go to next page
- q : quit

- These commands allow you to :

  - Copy and move them
  - Delete them

### Overview of Linux File Permissions

Linux uses a permission system to control who can access or modify files and directories. Every file or directory has :

1. Owner – the user who created the file.
2. Group – a set of users who can share permissions for the file.
3. Others – everyone else who has access to the system.

**Types of Permissions**

| Permission | Symbol | Value | Description                                      |
|------------|--------|-------|--------------------------------------------------|
| Read       | r      | 4     | View file contents or list directory contents    |
| Write      | w      | 2     | Modify files or add/remove files in a directory  |
| Execute    | x      | 1     | Run files or access directories                  

**Permission Structure**

| Section  | Applies To | Permission | Meaning              |
|----------|------------|------------|----------------------|
| First 3  | Owner      | rwx        | Full access          |
| Next 3   | Group      | r-x        | Read + execute       |
| Last 3   | Others     | r--        | Read only            |

**Numeric Conversion Example**

| Section | Permissions | Calculation | Value |
|---------|------------|-------------|-------|
| Owner   | rwx        | 4 + 2 + 1   | 7     |
| Group   | rwx        | 4 + 2 + 1   | 7     |
| Others  | rwx        | 4 + 2 + 1   | 7     |

**More Common Examples**

| Symbolic   | Numeric | Meaning                                              |
|------------|---------|------------------------------------------------------|
| rwxr-xr-x  | 755     | Owner can do everything, others can read and execute |
| rw-r--r--  | 644     | Owner can read/write, others can only read           |
| rwx------  | 700     | Only the owner has access                            |

ls -lh

###  The Differences Between Users & Groups 

- Linux permissions are flexible (granular).
- A file can belong to one user, but other users or groups can still get access.
- This does not change ownership, only access rights.

#### Real-World Example 

- A web server needs full access to website files (read/write).
- Users (customers) should :
  - Upload their own files
  - NOT access other users' files

This keeps the system secure and organized.

#### Simple Analogy 

- Alice owns a notebook : She can read, write, and erase  
- Bob (same group) : Can only read the notebook  
- Charlie (not in group) : Cannot access the notebook  

#### Mapping to Linux

| Role     | Meaning                  |
|----------|--------------------------|
| Alice    | Owner (file creator)     |
| Bob      | Group (shared users)     |
| Charlie  | Others (everyone else)   |

#### Key Idea
- Owner has full control
- Group has limited access
- Others have very limited or no access
- The system decides who can do what

#### Real Linux Use Case

- Web server : full access (runs the website)
- Users : can upload their own files
- Users : cannot access others’ files

As a result :
- Data stays secure
- System works properly

### Switching Between Users
Switching between users in Linux is done using the su (substitute/switch user) command. This is useful when you need to perform actions as another user account.
Unless you are the root user (or using sudo), switching to another account with su requires :
- The username you want to switch to.
- The password for that user.

Running su with no username attempts to switch to root.

#### Common su Usage

**1. su user :**

Switch to another user without changing your current environment or working directory.

- Keeps most of your current environment variables (e.g., `PATH`).
- You stay in the same directory you were in before switching.
- Does not load the target user's login profile files.

**Example :**
```bash
$ pwd
/home/tryhackme

$ su user2
Password:

$ pwd
/home/tryhackme   # still the same directory
$ whoami
user2

```

***2. su -l user (or su --login user) :***
> Note : Its not 1(one) its small L(l).

- Switches your identity to user.
- Loads the user's login environment (their PATH, profile files).
- Moves you into the user's home directory.

**Example :**
```bash
$ pwd
/home/tryhackme

$ su -l user2
Password:

$ pwd
/home/user2   # changed to user2's home directory
$ whoami
user2

```

## Common Directories

### Overview
Linux has some important system folders. Knowing them helps you :
- Find files quickly
- Understand how Linux stores data
- Work more efficiently in the terminal

### Important Directories

| Directory | Meaning     | Purpose                                      |
|-----------|-------------|----------------------------------------------|
| /etc      | etcetera    | Stores system configuration files            |
| /var      | variable    | Stores data that changes often (logs, etc.)  |
| /root     | root home   | Home directory of the root (admin) user      |
| /tmp      | temporary   | Stores temporary files (auto-deleted later)  |


#### 1. /etc (Configuration Files)
- Contains important system settings and configs
- Used by OS and applications

| File     | Purpose                          |
|----------|----------------------------------|
| passwd   | Stores user account info         |
| shadow   | Stores encrypted passwords       |
| sudoers  | Controls sudo permissions        |

> Think of `/etc` as the settings folder of Linux

#### 2. /var (Changing Data)
- Stores data that keeps changing
- Used by services and applications

| Path       | Purpose                      |
|------------|------------------------------|
| /var/log   | System and app logs          |
| /var/tmp   | Temporary files (longer use) |
| /var/backups | Backup files               |

> Think of `/var` as logs + running system data

#### 3. /root (Admin Home)
- Home directory of the root user
- Root = admin with full control
- Different from normal users (`/home/user`)

> Think of `/root` as admin’s personal folder

#### 4. /tmp (Temporary Files)
- Stores temporary data
- Automatically cleared after reboot

> Think of `/tmp` like RAM storage (temporary workspace)

### Key Features

| Feature        | Description                          |
|----------------|--------------------------------------|
| Access         | All users can write here             |
| Data Life      | Temporary (deleted on restart)       |
| Usage          | Scripts, testing, temporary storage  |

### Summary

| Directory | Easy Meaning            |
|-----------|-------------------------|
| /etc      | System settings         |
| /var      | Logs and changing data  |
| /root     | Admin home              |
| /tmp      | Temporary files         |

### Key Points
- `/var/log` : where logs are stored
- `/tmp` : temporary and auto-deleted
- `/root` : root user's home
- `/etc` : very important config files
