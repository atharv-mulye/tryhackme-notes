# Nmap : The Basics

## Introduction

Nmap (Network Mapper) is a powerful open-source network scanning tool used to:

- Discover live hosts on a network
- Identify running services and open ports
- Gather information about target systems
- Perform network reconnaissance

Nmap is faster and more efficient than manually checking hosts and ports.

---

## Host Discovery: Finding Live Hosts

Before scanning ports and services, it's important to identify which hosts are online.

Nmap uses the `-sn` option (Ping Scan) to discover active devices without performing a port scan.

### Syntax

```bash
nmap -sn TARGET
```

---

## Target Specification

Nmap supports multiple ways to define targets.

| Target Type | Example |
|------------|---------|
| IP Range | `192.168.1.1-10` |
| Subnet | `192.168.1.0/24` |
| Hostname | `example.thm` |

## Host Discovery Methods

Nmap may use different probe types to identify live systems.

| Method | Description |
|----------|-------------|
| ARP | Used on local networks |
| ICMP Echo | Standard ping request |
| ICMP Timestamp | Timestamp request probe |
| TCP SYN | Sends SYN packets to specific ports |
| TCP ACK | Sends ACK packets to specific ports |
| UDP | Sends UDP probes to target ports |

## List Scan

Nmap can display targets without scanning them.

### Example

```bash
nmap -sL 192.168.0.0/24
```

### Purpose

- Lists all targets.
- Performs no host discovery.
- Useful for verifying scan targets before running a scan.

---

## Important Notes

- `-sn` performs host discovery only.
- No port scanning is performed.
- Useful for identifying active devices with minimal network noise.
- To discover services and open ports, additional scan types are required.

---

## Common Nmap Commands

| Command | Description |
|----------|-------------|
| `nmap -sn 192.168.1.0/24` | Discover live hosts on a subnet. |
| `nmap -sn 192.168.1.1-10` | Discover live hosts within an IP range. |
| `nmap -sn example.thm` | Perform host discovery on a hostname. |
| `nmap -sL 192.168.1.0/24` | List scan targets without scanning them. |

---

## Key Takeaways

- Nmap is a network discovery and scanning tool.
- Host discovery identifies which systems are online.
- Local network scans primarily use ARP requests.
- Remote network scans use ICMP, TCP, and UDP probes.
- The `-sn` option performs host discovery only.
- The `-sL` option lists targets without scanning them.

## Port Scanning : Who Is Listening

After finding live hosts, the next step is to identify which services are running on them.

A service is any application listening on a TCP or UDP port, such as:

- Web servers (HTTP/HTTPS → ports 80, 443)
- DNS servers (port 53)
- SSH servers (port 22)

Each system can have up to **65,535 TCP ports** and **65,535 UDP ports**, so scanning is needed to find active ones.

---

## TCP Port Scanning

TCP scanning checks which ports accept incoming connections.

---

### Connect Scan (-sT)

A connect scan completes the full TCP handshake.

### Syntax

```bash
nmap -sT TARGET
```

### How It Works

- Sends SYN packet
- Completes full TCP handshake if port is open
- Closes connection after detection

### Key Point

- Easy to detect because it fully connects to services
- Similar to manual tools like telnet

### Example 

our scanning machine has the IP address 192.168.124.148

<img width="1000" height="500" alt="image" src="https://github.com/user-attachments/assets/ce57806e-203e-4c1b-a4aa-73ec4294fad5" /> <br>

> In the part marked with 1, you can see how the TCP three-way handshake was completed and later torn down with a TCP RST-ACK packet by Nmap. The part marked with 2 shows a connection attempt to a closed port, and the target system responded with a TCP RST-ACK packet.

#### Part 1 — Port 22 (OPEN)

- Scanner (192.168.124.148) sends **SYN**
- Target replies with **SYN-ACK**
- Scanner sends **ACK**
- Full TCP 3-way handshake happens
- Then scanner sends **RST, ACK** to close connection

**Result : Port 22 is OPEN (service is running)**

#### Part 2 — Port 23 (CLOSED)

- Scanner sends **SYN**
- Target replies with **RST, ACK**
- No handshake happens

**Result : Port 23 is CLOSED (no service running)**

#### Key Idea

- SYN + SYN-ACK + ACK = OPEN port
- SYN → RST = CLOSED port
- A TCP connect scan actually tries to connect to the port.
- If connection succeeds → port is open.

  
---

### SYN Scan (-sS) Stealth Scan

A SYN scan only starts the handshake but does not complete it.

### Syntax

```bash
nmap -sS TARGET
```

### How It Works

- Sends SYN packet
- If port is open → receives SYN-ACK
- Sends RST instead of completing handshake

### Key Point

- Faster and more stealthy
- Less likely to be logged

### Example 

Our scanning machine has the IP address 192.168.124.148

<img width="1119" height="664" alt="image" src="https://github.com/user-attachments/assets/64e02afa-cce4-4388-8a5e-0898ca8c8bc0" />

In the part marked with 1, you can see how the TCP connection behaves when the port is open.  
The scan shows a partial TCP handshake where the target responds, but Nmap does not complete the full connection. Instead, it sends a reset packet to avoid fully establishing the session.

The part marked with 2 shows what happens when the scan hits a closed port. The target immediately rejects the connection attempt.

#### Part 1 — Port 22 (OPEN)

- Scanner (192.168.124.148) sends **SYN**
- Target replies with **SYN-ACK**
- Scanner responds with **RST** (instead of completing handshake)
- Full connection is NOT completed

**Result:** Port 22 is OPEN (service is running)

#### Part 2 — Port 23 (CLOSED)

- Scanner sends **SYN**
- Target replies with **RST-ACK**
- No handshake happens at all

**Result:** Port 23 is CLOSED (no service running)

#### Key Idea

- **SYN → SYN-ACK (then RST from scanner)** = OPEN port  
- **SYN → RST** = CLOSED port  

#### Key Understanding

A SYN scan tries to start a connection but never finishes it.  
If the target responds like it’s ready → port is open.  
If it rejects immediately → port is closed.

## UDP Port Scanning

UDP is connectionless and used by many services like :

- DNS
- DHCP
- NTP
- SNMP
- VoIP

---

### UDP Scan (-sU)

### Syntax

```bash
nmap -sU TARGET
```

### How It Works

- Sends UDP packets
- Closed ports often respond with ICMP "port unreachable"
- Open ports may not respond at all

### Example 

Nmap offers the option -sU to scan for UDP services. Because UDP is simpler than TCP, we expect the traffic to differ. The screenshot below shows several ICMP destination unreachable (port unreachable) responses as Nmap sends UDP packets to closed UDP ports.

## Limiting Ports in Nmap

By default, Nmap scans the top 1000 ports.

---

### Fast Scan (-F)

Scans only the 100 most common ports.

```bash
nmap -F TARGET
```

---

### Custom Port Range (-p)

#### Scan specific range

```bash
nmap -p10-1024 TARGET
```
Scans from port 10 to port 1024

#### Scan first 25 ports

```bash
nmap -p-25 TARGET
```
scan all the ports between 1 and 25.

#### Scan all ports

```bash
nmap -p- TARGET
```

Equivalent to:

```bash
nmap -p1-65535 TARGET
```

---

## Well-Known Ports

Ports 1–1024 are commonly used for standard services.

```bash
nmap -p1-1023 TARGET
```

## Comparison of Scan Types

| Scan Type | Command | property |
|------------|----------|------|
| Connect Scan | `-sT` | Full TCP handshake, easy to detect |
| SYN Scan | `-sS` | Half-open scan, stealthier |
| UDP Scan | `-sU` | Checks UDP services |

---

## Summary of Common Scan Options

| Option | What it means (simple explanation) |
|--------|------------------------------------|
| `-sT`  | TCP Connect Scan – completes the full TCP 3-way handshake (fully connects to the port) |
| `-sS`  | TCP SYN Scan – sends only SYN, checks response without fully connecting (stealthier scan) |
| `-sU`  | UDP Scan – checks UDP ports instead of TCP ports |
| `-F`   | Fast Scan – scans only the top 100 most commonly used ports |
| `-p [range]` | Select specific ports to scan (example: `-p 80`, `-p 1-1000`) |
| `-p-`  | Scans ALL 65535 ports (full port scan) |

---

## Key Takeaways

- Port scanning finds running services on a system.
- TCP uses connection-based scanning methods.
- SYN scan is more stealthy than connect scan.
- UDP scanning is slower and less predictable.
- Nmap scans top 1000 ports by default.
- `-p` allows full control over port selection.
- `-F` speeds up scans by checking fewer ports.

## Version Detection : Extract More Information

After finding open ports, the next step is to gather more details about the target system and the services running on it. Nmap provides options for OS detection, service version detection, and advanced scanning.

---

## OS Detection (`-O`)

Nmap can try to identify the target operating system using the `-O` option.

### Command

```bash
nmap -sS -O <target-ip>
```

### What it does

- Analyzes network responses from the target.
- Compares them against Nmap's OS fingerprint database.
- Makes an educated guess about the operating system.

### Example 

```terminal
root@tryhackme:~# nmap -sS -O 192.168.124.211

Nmap scan report for ubuntu22lts-vm (192.168.124.211)
Host is up (0.00043s latency).
Not shown: 999 closed tcp ports (reset)
PORT   STATE SERVICE
22/tcp open  ssh
MAC Address: 52:54:00:54:FA:4E (QEMU virtual NIC)
Device type: general purpose
Running: Linux 4.X|5.X
OS CPE: cpe:/o:linux:linux_kernel:4 cpe:/o:linux:linux_kernel:5
OS details: Linux 4.15 - 5.8
Network Distance: 1 hop

OS detection performed. Please report any incorrect results at https://nmap.org/submit/ .
Nmap done: 1 IP address (1 host up) scanned in 1.44 seconds
```

### Key points 

- OS detection is **not always 100% accurate**.
- Nmap provides the closest match based on available information.
- Useful for understanding the target environment before further enumeration.

### Key Takeaway

`-O` helps identify the likely operating system running on the target host.

---

## Service and Version Detection (`-sV`)

Finding an open port is useful, but knowing **which software and version** is running is even more valuable.

### Command

```bash
nmap -sS -sV <target-ip>
```

### What it does

- Connects to discovered services.
- Collects banners and response data.
- Identifies the service and its version.

### Example 


### Why it matters

Knowing the exact version helps:

- Identify outdated software.
- Search for known vulnerabilities.
- Understand the target's technology stack.

### Key Takeaway

`-sV` reveals the service name and version running on open ports.

---

## Aggressive Scan (`-A`)

Instead of running multiple options separately, Nmap provides the `-A` option.

### Command

```bash
nmap -A <target-ip>
```

### What it includes

- OS Detection (`-O`)
- Version Detection (`-sV`)
- Traceroute
- Default NSE scripts
- Additional host information gathering

### Benefits

- Faster information gathering.
- Provides a broad overview of the target in a single scan.

### Drawback

- More noisy and easier to detect.
- Generates more traffic than basic scans.

### Key Takeaway

`-A` is an all-in-one reconnaissance option for gathering detailed target information.

---

## Forcing a Scan (`-Pn`)

Before scanning ports, Nmap performs **host discovery** to check if a host is online.

Sometimes:

- ICMP requests are blocked.
- Firewalls prevent host discovery responses.
- The host appears offline even when it is actually running.

In these situations, Nmap may skip port scanning completely.

### Command

```bash
nmap -Pn <target-ip>
```

### What it does

- Skips host discovery.
- Assumes the target is online.
- Performs the scan regardless of ping responses.

### Example

```bash
nmap -sS -Pn <target-ip>
```

### When to use

- Target does not respond to pings.
- ICMP is filtered by a firewall.
- You suspect the host is alive but Nmap reports it as down.

### Key Takeaway

`-Pn` tells Nmap to treat the target as online and continue scanning even if host discovery fails.

---

## Quick Reference

| Option | Purpose |
|----------|----------|
| `-O` | Detect operating system |
| `-sV` | Detect service versions |
| `-A` | Aggressive scan (OS detection, version detection, scripts, traceroute) |
| `-Pn` | Skip host discovery and assume host is online |

---

## Key Points 

- `-O` attempts to identify the target operating system.
- `-sV` detects services and their versions.
- `-A` combines multiple reconnaissance features into one scan.
- `-Pn` forces Nmap to scan hosts even when they do not respond to discovery probes.

These options help move from simple port discovery to detailed target enumeration, providing valuable information for further security assessment.

## Timing : How Fast is Fast

Nmap allows you to control how fast or slow a scan runs. This is useful because very fast scans may trigger security systems such as IDS/IPS, while slower scans can be stealthier.

---

## Timing Templates (`-T`)

Nmap provides six built-in timing profiles.

### Syntax

```bash
nmap -T<0-5> <target-ip>
```

or

```bash
nmap -T paranoid <target-ip>
```

### Timing Levels

| Template | Name | Purpose |
|-----------|---------|---------|
| `T0` | Paranoid | Extremely slow, designed to avoid detection |
| `T1` | Sneaky | Very slow and stealthy |
| `T2` | Polite | Reduces load on the network |
| `T3` | Normal | Default timing |
| `T4` | Aggressive | Faster scans on reliable networks |
| `T5` | Insane | Extremely fast, may miss results on unstable networks |

---

## Timing Comparison

The following results were observed when scanning the 100 most common TCP ports.

| Timing | Scan Duration |
|----------|---------------|
| T0 (Paranoid) | 9.8 hours |
| T1 (Sneaky) | 27.53 minutes |
| T2 (Polite) | 40.56 seconds |
| T3 (Normal) | 0.15 seconds |
| T4 (Aggressive) | 0.13 seconds |

> Actual timings will vary depending on network speed, latency, and packet loss.

## Parallel Probes

Nmap can send multiple probes simultaneously.

### Options

```bash
--min-parallelism <num>
--max-parallelism <num>
```

### Example

```bash
nmap --min-parallelism 50 <target-ip>
```

### What it does

- Controls how many TCP/UDP probes run at the same time.
- Higher values increase scan speed.
- Lower values reduce network load.

### Notes

By default, Nmap automatically adjusts the number of parallel probes based on network performance.

---

## Packet Sending Rate

Nmap also allows control over packet transmission speed.

### Options

```bash
--min-rate <packets-per-second>
--max-rate <packets-per-second>
```

### Example

```bash
nmap --min-rate 1000 <target-ip>
```

### What it does

- Sets the packet transmission rate.
- Helps speed up or slow down scans.
- Rate applies to the entire scan, not a single host.

### Common Use

```bash
nmap -sS --min-rate 5000 <target-ip>
```

Used when performing fast reconnaissance on reliable networks.

---

## Host Timeout

Some hosts respond very slowly. Instead of waiting forever, Nmap allows you to define a timeout.

### Option

```bash
--host-timeout <time>
```

### Example

```bash
nmap --host-timeout 5m <target-ip>
```

### What it does

- Stops scanning a host after the specified time.
- Prevents wasting time on slow or unresponsive targets.
- Useful during large-scale scans.

---

## Quick Reference

| Option | Purpose |
|----------|----------|
| `-T0` | Paranoid (slowest) |
| `-T1` | Sneaky |
| `-T2` | Polite |
| `-T3` | Normal (default) |
| `-T4` | Aggressive |
| `-T5` | Insane (fastest) |
| `--min-parallelism` | Minimum parallel probes |
| `--max-parallelism` | Maximum parallel probes |
| `--min-rate` | Minimum packet rate |
| `--max-rate` | Maximum packet rate |
| `--host-timeout` | Maximum time to wait for a host |

---

## Key Takeaways

- Nmap timing templates (`-T0` to `-T5`) control scan speed and stealth.
- Lower timing values are slower and harder to detect.
- Higher timing values are faster but more noticeable.
- `--min-parallelism` and `--max-parallelism` control the number of simultaneous probes.
- `--min-rate` and `--max-rate` control packet transmission speed.
- `--host-timeout` prevents scans from hanging on slow hosts.

> For most TryHackMe labs and CTFs, T4 (Aggressive) is commonly used because it provides fast results without being excessively noisy.

## Key Takeaways

- `-v` provides real-time scan progress and additional information.
- Multiple `v`s increase verbosity.
- `-d` enables debugging output for troubleshooting.
- `-oN` saves human-readable reports.
- `-oX` saves XML reports for automation.
- `-oG` saves grep-friendly output.
- `-oA` saves all major output formats at once.

For most assessments, using:

```bash
nmap -sS -v -oA scan_results <target>
```

provides good visibility during the scan and saves results in all important formats.
