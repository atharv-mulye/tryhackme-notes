# Networking Essentials

## DHCP (Dynamic Host Configuration Protocol)

DHCP is used to automatically assign network settings to devices connected to a network.

Without DHCP, users would need to manually configure :
- IP Address
- Subnet Mask
- Default Gateway
- DNS Server

DHCP helps :
- automate network configuration
- prevent IP conflicts
- simplify device connectivity

DHCP uses UDP :
- Server → Port 67
- Client → Port 68

---

## DHCP Process (DORA)

<img width="550" height="400" alt="image" src="https://github.com/user-attachments/assets/26f34afb-06aa-4f73-a86e-624cdc21d8a2" />

DHCP works in 4 steps :

## 1. Discover
The client broadcasts a `DHCPDISCOVER` packet to find a DHCP server.

At this stage :
- Source IP = `0.0.0.0`
- Destination IP = `255.255.255.255`

## 2. Offer
The DHCP server replies with a `DHCPOFFER` packet containing:
- available IP address
- subnet mask
- gateway
- DNS server

## 3. Request
The client sends a `DHCPREQUEST` packet to accept the offered IP address.

## 4. Acknowledge
The server confirms the assignment using `DHCPACK`.

The client can now use the network.

---

## Key Points

- Before receiving an IP, the client uses `0.0.0.0`
- DHCP packets are initially broadcasted
- Broadcast MAC address:
  
```text
ff:ff:ff:ff:ff:ff
```

---

## Information Provided by DHCP

After successful configuration, DHCP provides :
- IP Address
- Subnet Mask
- Default Gateway
- DNS Server

---

## Example

In this example, the client gets the address 192.168.66.133

<img width="650" height="100" alt="image" src="https://github.com/user-attachments/assets/d1a54723-903c-474e-b27b-84894abf3314" />

### Step 1 — DHCP Discover

```bash
0.0.0.0 → 255.255.255.255 DHCP Discover
```

The client does not yet have :
- an IP address
- subnet mask
- gateway
- DNS settings

Because of this :
- Source IP = `0.0.0.0`
- Destination IP = `255.255.255.255` (broadcast)

The client is basically asking :

> "Is there any DHCP server available ?"

It also sends the packet using the broadcast MAC address:

```text
ff:ff:ff:ff:ff:ff
```

because it does not know the DHCP server's MAC address either.

### Step 2 — DHCP Offer

```bash
192.168.66.1 → 192.168.66.133 DHCP Offer
```

The DHCP server responds with :
- offered IP address
- subnet mask
- gateway
- DNS server

In this example :
- DHCP Server IP = `192.168.66.1`
- Offered Client IP = `192.168.66.133`

The server is saying :

> "You can use IP address 192.168.66.133"

The transaction ID remains the same so the client knows this reply belongs to its request.

### Step 3 — DHCP Request

```bash
0.0.0.0 → 255.255.255.255 DHCP Request
```

The client accepts the offered IP address.

It broadcasts again because :
- the IP is not officially assigned yet
- the client still cannot fully use `192.168.66.133`

The client is basically saying :

> "I want to use 192.168.66.133"

### Step 4 — DHCP ACK

```bash
192.168.66.1 → 192.168.66.133 DHCP ACK
```

The DHCP server confirms the assignment.

Now :
- the client officially owns `192.168.66.133`
- network communication can start normally

The client can now :
- access local devices
- connect to the internet
- resolve domains using DNS

---

## Why Broadcast is Used ? 

At the beginning :
- the client has no IP address
- the client does not know the DHCP server

So it uses :
- IP Broadcast → `255.255.255.255`
- MAC Broadcast → `ff:ff:ff:ff:ff:ff`

This allows every device on the local network to receive the packet.

---

## Transaction ID

```text
0xfb92d53f
```

The transaction ID is used to match :
- DHCP Discover
- DHCP Offer
- DHCP Request
- DHCP ACK

All packets in the same DHCP process share the same transaction ID.

---

## Final Result

After DHCP completes, the client receives:
- IP Address → `192.168.66.133`
- Subnet Mask
- Default Gateway
- DNS Server

The device is now fully configured for network communication.

## Key Takeaway

DHCP automatically configures network settings for devices, allowing quick and easy network access without manual setup.

## ARP (Address Resolution Protocol)

ARP is used to find the MAC address of a device when its IP address is already known.

Devices on the same local network communicate using MAC addresses, not IP addresses directly.

---

## Why ARP is Needed ? 

When a device wants to send data:
- it knows the destination IP address
- but Ethernet communication requires a destination MAC address

ARP solves this problem by translating :

```text
IP Address → MAC Address
```

---

## Ethernet Frame

An IP packet is encapsulated inside an Ethernet frame.

The Ethernet frame contains :
- Destination MAC Address
- Source MAC Address
- Protocol Type

Example :
- Ethernet / WiFi use MAC addresses for local communication
- IP addresses are used for logical addressing

---

## Example Scenario

Host A :
- IP = `192.168.66.89`
- MAC = `cc:5e:f8:02:21:a7`

Wants to communicate with:

Host B :
- IP = `192.168.66.1`
- MAC = Unknown initially

Because Host A does not know Host B's MAC address, it sends an ARP Request.

---

## ARP Packet Capture

```bash
1 cc:5e:f8:02:21:a7 → ff:ff:ff:ff:ff:ff ARP Who has 192.168.66.1? Tell 192.168.66.89

2 44:df:65:d8:fe:6c → cc:5e:f8:02:21:a7 ARP 192.168.66.1 is at 44:df:65:d8:fe:6c
```

### Step 1 — ARP Request

```bash
Who has 192.168.66.1 ? Tell 192.168.66.89
```

The sender:
- knows the target IP
- does not know the target MAC

So it broadcasts the request to every device on the network using:

```text
ff:ff:ff:ff:ff:ff
```

This is the broadcast MAC address.

The message basically means:

> "Which device owns IP 192.168.66.1? Send me your MAC address."

### Step 2 — ARP Reply

```bash
192.168.66.1 is at 44:df:65:d8:fe:6c
```

The target device responds with its MAC address.

Now Host A learns:

```text
192.168.66.1 → 44:df:65:d8:fe:6c
```

After this:
- communication can happen normally
- Ethernet frames can be properly created

---

## Important Notes

### ARP Uses Broadcast

ARP Requests are broadcasted because the sender does not know the destination MAC address yet.

### ARP Reply is Direct

The ARP Reply is sent directly back to the requester.

---

## ARP and Layers

ARP works between :
- Layer 2 (MAC Address)
- Layer 3 (IP Address)

It connects :
```text
IP Addressing ↔ MAC Addressing
```

---

## ARP is Not Inside IP or UDP

ARP packets are encapsulated directly inside Ethernet frames.

They are NOT carried inside:
- IP packets
- TCP packets
- UDP packets

## Key Takeaway

ARP allows devices on the same local network to discover MAC addresses using IP addresses so Ethernet communication can occur properly.

## ICMP (Internet Control Message Protocol)

ICMP is mainly used for :
- network diagnostics
- error reporting
- troubleshooting connectivity problems

Two common tools that use ICMP are :
- `ping`
- `traceroute`

---

## Ping

`ping` checks whether a target device is reachable.

It sends:
```text
ICMP Echo Request (Type 8)
```

The target replies with:
```text
ICMP Echo Reply (Type 0)
```

This confirms:
- the target system is online
- packets can travel successfully between systems

---

## Ping Example

<img width="718" height="231" alt="image" src="https://github.com/user-attachments/assets/32414b9e-ad86-4a12-9e63-76cca66e2a22" />

Option :
```bash
-c 4
```

means :
> send only 4 packets

## Explanation : 

```bash
64 bytes from 192.168.11.1: icmp_seq=1 ttl=63 time=11.2 ms
```

## Important Fields

### `64 bytes`
Size of the reply packet received.

### `icmp_seq=1`
Packet sequence number.

Used to identify each ping packet.

### `ttl=63`
Time To Live value.

TTL decreases by 1 whenever a packet passes through a router.

Helps prevent packets from looping forever.

### `time=11.2 ms`
Round Trip Time (RTT).

Time taken for:
- request to reach target
- reply to return back

Measured in milliseconds.

Lower value = faster connection.

---

## Ping Statistics

```bash
4 packets transmitted, 4 received, 0% packet loss
```

Meaning:
- 4 packets sent
- 4 packets received
- no packets lost

This indicates stable connectivity.

---

## RTT Statistics

```bash
rtt min/avg/max/mdev
```

## Meaning

| Field | Description |
|---|---|
| min | Fastest response time |
| avg | Average response time |
| max | Slowest response time |
| mdev | Variation between response times |

---

## Possible Reasons for No Reply

Ping may fail because:
- target system is offline
- firewall blocks ICMP packets
- network issue exists between devices

## Traceroute

`traceroute` discovers the path packets take to reach a destination.

Linux:
```bash
traceroute
```

Windows:
```bash
tracert
```

---

## How Traceroute Works ? 

Traceroute uses the IP field called :

```text
TTL (Time To Live)
```

Each router :
- decreases TTL by 1
- drops the packet when TTL reaches 0

When dropped, the router sends:

```text
ICMP Time Exceeded (Type 11)
```

Traceroute increases TTL step-by-step to identify every router in the path.

---

## Traceroute Process

### TTL = 1
- First router drops packet
- Sends ICMP Time Exceeded
- First router identified

### TTL = 2
- Second router drops packet
- Sends ICMP response
- Second router identified

This continues until :
- destination is reached

---

## Traceroute Example

```bash
1 192.168.66.1
2 192.168.11.1
3 100.104.0.1
```

Each line represents :
- one router (hop)
- between source and destination

---

## Understanding Hop Times

```bash
4.414 ms  4.342 ms  4.320 ms
```

These are RTT (round trip time) measurements for each probe packet.

Lower values mean :
- faster response
- shorter delay

---

## What `* * *` Means

```bash
5 * * *
```

This means:
- router did not respond
- ICMP response may be blocked
- firewall may filter packets

The router may still forward traffic normally.

---

## Public vs Private IPs

Traceroute may reveal :
- private IP addresses inside ISP networks
- public IP addresses on internet routers

Public IPs can sometimes reveal :
- ISP names
- router hostnames
- geographic locations

---

## Important Note

Traceroute paths can change because:
- internet routing is dynamic
- packets may take different routes

Running traceroute multiple times may produce different results.

## Key Takeaway

ICMP helps diagnose network communication problems.

- `ping` checks connectivity and response time
- `traceroute` reveals the path packets take through routers

---

## Routing

Routing is the process of deciding how packets travel from one network to another.

Routers are responsible for forwarding packets using the best available path.

---

## Why Routing is Needed ?

Devices inside the same network can communicate directly.

However, communication between different networks requires routers.

<img width="600" height="300" alt="image" src="https://github.com/user-attachments/assets/4315ed5c-5ae6-49b1-a525-a5a1dbda3aef" />

Example :
- Network 1 wants to communicate with Network 2
- packets must pass through routers
- routers decide the correct path

---

## Internet Routing

The Internet contains:
- millions of routers
- billions of connected devices

There are usually multiple possible paths between:
- source
- destination

Routers use routing algorithms and routing protocols to determine:
- best path
- shortest path
- fastest path
- most efficient path

---

## What Routers Do ? 

When a router receives a packet :
1. it checks the destination IP address
2. looks at its routing table
3. chooses the best route
4. forwards the packet to the next router

This process repeats until the packet reaches the destination.

---

## Routing Protocols

Routing protocols allow routers to:
- exchange network information
- learn available routes
- update routing tables automatically

## OSPF (Open Shortest Path First)

OSPF is a dynamic routing protocol.

It works by:
- sharing network topology information between routers
- building a complete map of the network
- calculating the shortest and most efficient path

### Features
- fast convergence
- efficient routing
- commonly used in enterprise networks

>  OSPF is a routing protocol that allows routers to share information about the network topology and calculate the most efficient paths for data transmission. It does this by having routers exchange updates about the state of their connected links and networks. This way, each router has a complete map of the network and can determine the best routes to reach any destination.

---

## EIGRP (Enhanced Interior Gateway Routing Protocol)

EIGRP is a Cisco proprietary routing protocol.

It combines features from different routing methods.

Routers exchange:
- reachable networks
- route costs
- bandwidth information
- delay information

Then they choose the best path.

### Features
- fast routing updates
- efficient path selection
- mainly used in Cisco environments

EIGRP is a Cisco proprietary routing protocol that combines aspects of different routing algorithms. It allows routers to share information about the networks they can reach and the cost (like bandwidth or delay) associated with those routes. Routers then use this information to choose the most efficient paths for data transmission.

---

## BGP (Border Gateway Protocol)

BGP is the main routing protocol used on the Internet.

It allows:
- ISPs
- large organizations
- autonomous systems

to exchange routing information.

BGP helps traffic move across multiple networks worldwide.

### Features
- Internet-scale routing
- controls inter-network communication
- highly scalable

> BGP is the primary routing protocol used on the Internet. It allows different networks (like those of Internet Service Providers) to exchange routing information and establish paths for data to travel between these networks. BGP helps ensure data can be routed efficiently across the Internet, even when traversing multiple networks.

---

## RIP (Routing Information Protocol)

RIP is a simple routing protocol mostly used in small networks.

Routers share:
- reachable networks
- hop counts

### Hop Count
A hop is:
> one router traversal

RIP selects routes with:
- the fewest hops

### Features
- simple configuration
- easy to understand
- limited scalability

> RIP is a simple routing protocol often used in small networks. Routers running RIP share information about the networks they can reach and the number of hops (routers) required to get there. As a result, each router builds a routing table based on this information, choosing the routes with the fewest hops to reach each destination.

---

## Example of Hop Count

```text
PC → Router1 → Router2 → Server
```

Hop count:
```text
2 hops
```

because the packet crosses two routers.

---

## Key Takeaway

Routing allows packets to travel between different networks.

Routers use routing protocols like:
- OSPF
- EIGRP
- BGP
- RIP

to learn routes and choose the best path for forwarding packets.

## NAT (Network Address Translation)

NAT allows multiple devices on a private network to access the Internet using a single public IP address.

It helps reduce IPv4 address exhaustion.

---

## Why NAT is Needed ? 

IPv4 supports about:

```text
4 billion IP addresses
```

With billions of devices connected to the Internet:
- computers
- smartphones
- IoT devices
- cameras
- smart appliances

IPv4 addresses started running out.

NAT helps conserve public IP addresses.

---

## Basic Idea of NAT

Inside a local network:
- devices use private IP addresses

When accessing the Internet:
- the router replaces private IPs with its public IP address

This process is called:

```text
Network Address Translation
```

---

# How NAT Works

When a device sends traffic:
1. packet reaches NAT router
2. router replaces:
   - private source IP
   - source port
3. router stores translation in a NAT table
4. packet is sent to the Internet using router's public IP

When replies return:
1. router checks NAT table
2. finds matching internal device
3. forwards packet to correct system

---

## Example Network

<img width="650" height="300" alt="image" src="https://github.com/user-attachments/assets/86444379-ee8c-462f-b612-a9ada6462efd" />

The laptop:

```text
192.168.0.129
```

opens a website using:

```text
192.168.0.129 : 15401
```

The router translates it to:

```text
212.3.4.5 : 19273
```

To the web server, the traffic appears to come from:

```text
212.3.4.5
```

The private IP address remains hidden.

---

## Why Port Numbers Change ? 

All devices share the same public IP:

```text
212.3.4.5
```

The router assigns different external port numbers to:
- separate connections
- identify devices correctly

This allows multiple devices to communicate simultaneously using one public IP.

---

## Returning Traffic

When the web server replies:

```text
212.3.4.5 : 19273
```

the router checks the NAT table:

```text
212.3.4.5 : 19273 → 192.168.0.129 : 15401
```

The packet is then forwarded to the correct device.

---

## Private vs Public IP Addresses

### Private IP Addresses

Used inside local networks.

Examples:

```text
192.168.x.x
10.x.x.x
172.16.x.x - 172.31.x.x
```

Private IPs are not routable on the Internet.

---

## Public IP Addresses

Used on the Internet.

Assigned by:
- ISPs
- public network providers

Must be globally unique.

---

## Benefits of NAT

- saves public IPv4 addresses
- allows many devices to share one public IP
- hides internal network structure
- provides basic privacy for internal systems

---

## NAT vs Routing

### Routing
Determines:
```text
where packets should go
```

### NAT
Modifies:
```text
IP addresses and port numbers
```

while traffic moves between private and public networks.

---

## Simple Traffic Flow

```text
Laptop → Router → Internet
192.168.0.129 → 212.3.4.5
```

The router performs address translation automatically.

---

## Key Takeaway

NAT allows multiple private devices to access the Internet using a single public IP address by translating internal IP addresses and port numbers through a NAT-enabled router.
