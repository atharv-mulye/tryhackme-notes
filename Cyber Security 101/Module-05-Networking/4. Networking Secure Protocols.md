# Networking Secure Protocols

## Why Secure Protocols Are Needed ?

Basic networking protocols like :

- HTTP
- SMTP
- POP3
- IMAP
- TELNET

send data in plaintext.

This means anyone capturing the network traffic may be able to see:

- Passwords
- Emails
- Credit card details
- Messages
- Files

Attackers may also modify the transferred data or pretend to be a real server.

---

## Security Problems in Plaintext Protocols

### No Confidentiality

Data is not encrypted.

Anyone monitoring packets can read the information.

Example:

- HTTP traffic can expose login passwords

### No Integrity Protection

Data can be modified during transmission.

Example:

- Payment amount changed from `100` to `800`

### No Authentication

Users may connect to a fake server instead of the real one.

---

## TLS (Transport Layer Security)

TLS is used to secure communication between devices.

It adds:

- Encryption
- Integrity checking
- Authentication

TLS protects data while it travels across the network.

---

## Secure Versions of Common Protocols

| Insecure Protocol | Secure Version |
|---|---|
| HTTP | HTTPS |
| SMTP | SMTPS |
| POP3 | POP3S |
| IMAP | IMAPS |

The `S` means Secure.

### HTTPS

HTTPS is HTTP protected with TLS.

Benefits:

- Encrypts web traffic
- Protects passwords and payment data
- Verifies the real website identity

Example:

```bash
https://example.com
```

---

## Secure Email Protocols

### SMTPS

Secure version of SMTP used for sending encrypted emails.

### POP3S

Secure version of POP3 used for securely receiving emails.

### IMAPS

Secure version of IMAP used for securely synchronizing emails.

---

## SSH (Secure Shell)

SSH replaced TELNET because TELNET sends everything in plaintext.

SSH provides:

- Secure remote access
- Encrypted communication
- Safe command execution

Example:

```bash
ssh user@server
```

---

## VPN (Virtual Private Network)

VPN creates a secure encrypted connection over an insecure network like the internet.

Benefits:

- Encrypts traffic
- Hides communication from attackers
- Protects public Wi-Fi connections

---

## Summary

| Protocol | Secure Version |
|---|---|
| HTTP | HTTPS |
| SMTP | SMTPS |
| POP3 | POP3S |
| IMAP | IMAPS |
| TELNET | SSH |

---

## Key Points

- Plaintext protocols are insecure
- TLS adds encryption and security
- HTTPS protects web traffic
- SSH securely replaces TELNET

- Secure protocols protect confidentiality, integrity, and authentication

## TLS (Transport Layer Security)

### What is TLS ?

TLS is a security protocol used to protect communication over a network.

It provides:

- Confidentiality
- Integrity
- Authentication

TLS encrypts data so attackers cannot read or modify it.

---

## Why TLS is Important ? 

Older protocols used plaintext communication.

Anyone capturing packets could see:

- Passwords
- Emails
- Chats
- Private data

Attackers could also modify the data being transferred.

TLS solves this problem using encryption.

---

## SSL and TLS History

### SSL (Secure Sockets Layer)

- Developed by Netscape
- SSL 2.0 released in 1995

---

### TLS (Transport Layer Security)

- Created by IETF in 1999
- Improved version of SSL
- TLS 1.3 released in 2018

TLS is the modern replacement for SSL.

---

## What TLS Protects

### Confidentiality

Encrypts data so only authorized users can read it.

Example:

- Protects passwords during login

### Integrity

Prevents attackers from changing transmitted data.

Example:

- Stops modification of payment amounts

### Authentication

Verifies that users are connected to the real server.

Example:

- Confirms the website is genuine

---

## TLS in Secure Protocols

TLS is added to existing protocols to make them secure.

| Insecure Protocol | Full Form | Secure Version | Full Form |
|---|---|---|---|
| HTTP | HyperText Transfer Protocol | HTTPS | HyperText Transfer Protocol Secure |
| DNS | Domain Name System | DoT | DNS over TLS |
| MQTT | Message Queuing Telemetry Transport | MQTTS | MQTT Secure |
| SIP | Session Initiation Protocol | SIPS | Session Initiation Protocol Secure |

The `S` means the protocol uses SSL/TLS security.

---

## TLS Certificates

Servers use digital certificates to prove their identity.

---

## Certificate Signing Request (CSR)

Server administrator creates a CSR and sends it to a Certificate Authority (CA).

---

## Certificate Authority (CA)

CA verifies the request and issues a signed certificate.

Example:

- Trusted organizations that validate websites

---

## Trusted Certificates

Browsers and operating systems store trusted CA certificates.

This allows devices to verify whether a server certificate is valid.

---

## How TLS Works ? 

1. Client connects to server
2. Server sends TLS certificate
3. Client verifies certificate
4. Secure encrypted connection starts

---

## Key Points

- TLS secures network communication
- TLS replaced SSL
- TLS provides:
  - Confidentiality
  - Integrity
  - Authentication
- HTTPS uses TLS
- TLS uses digital certificates
- CA signs certificates
- TLS protects passwords and sensitive data

---

## HTTPS (HyperText Transfer Protocol Secure)

### What is HTTPS ?

HTTPS is HTTP running over TLS encryption.

It secures communication between:

- Web browser
- Web server

HTTPS protects:

- Passwords
- Payment information
- Private data

---

## HTTP vs HTTPS

| HTTP | HTTPS |
|---|---|
| Data sent in plaintext | Data is encrypted |
| Not secure | Secure |
| Uses Port 80 | Uses Port 443 |
| Easy to intercept | Hard to read without decryption key |

---

## How HTTP Works

HTTP communication happens in two main steps after DNS resolution:

1. TCP three-way handshake
2. HTTP communication

Example HTTP request:

```bash
GET / HTTP/1.1
```

---

## HTTP Traffic in Wireshark

In HTTP :

- Requests and responses are visible
- Anyone capturing packets can read the data

Example visible information:

- Login credentials
- Messages
- Website content

---

## How HTTPS Works

HTTPS adds TLS encryption before HTTP communication.

Steps after DNS resolution:

1. TCP three-way handshake
2. TLS handshake/session setup
3. Encrypted HTTP communication

---

## HTTPS Connection Process

### Step 1: TCP Handshake

Creates connection between client and server.

### Step 2: TLS Handshake

TLS negotiates:

- Encryption method
- Security settings
- Certificates

Creates a secure encrypted session.

### Step 3: HTTP Data Transfer

HTTP requests and responses are exchanged securely.

Example:

```bash
GET / HTTP/1.1
```

The request is encrypted during transmission.

---

## HTTPS Traffic in Wireshark

Without the TLS key:

- Traffic appears as unreadable encrypted data
- Wireshark shows `Application Data`

Attackers cannot read the content.

---

## Decrypting HTTPS Traffic

If Wireshark has the TLS decryption key:

- Encrypted traffic can be decrypted
- HTTP requests and responses become visible

Without the key, the traffic remains protected.

---

## Key Points

- HTTPS = HTTP over TLS
- HTTP uses Port 80
- HTTPS uses Port 443
- HTTPS encrypts web traffic
- TLS protects confidentiality and integrity
- HTTP traffic is readable in plaintext
- HTTPS traffic appears encrypted
- TLS secures HTTP without changing TCP or IP

## SSH (Secure Shell)

### What is SSH ?

SSH is a secure protocol used to remotely access and manage systems over a network.

SSH replaced TELNET because TELNET sends data in plaintext.

SSH encrypts communication to protect:

- Passwords
- Commands
- Files
- Network traffic

---

## Why SSH is Important ? 

With TELNET:

- Login credentials are visible
- Attackers can capture passwords
- Traffic is not encrypted

With SSH:

- Communication is encrypted
- Data is protected from attackers
- Remote administration becomes secure

---

## SSH History

| Version | Year |
|---|---|
| SSH-1 | 1995 |
| SSH-2 | 1996 |
| OpenSSH | 1999 |

OpenSSH is the most commonly used open-source SSH implementation.

---

## Features of SSH

### Secure Authentication

SSH supports:

- Password authentication
- Public key authentication
- Two-factor authentication (2FA)

### Confidentiality

SSH encrypts all communication.

This prevents attackers from reading network traffic.

### Integrity

SSH protects data from being modified during transmission.

### Tunneling

SSH can create encrypted tunnels for other protocols.

This works similar to a VPN connection.

### X11 Forwarding

SSH allows graphical Linux applications to run remotely over the network.

---

## Connecting with SSH

Command:

```bash
ssh username@hostname
```

Example:

```bash
ssh user@192.168.1.10
```

- Connects securely to the remote system

---

## SSH Login

After connecting:

- User enters password
- Or authenticates using SSH keys

With public-key authentication, login may happen automatically.

## SFTP and FTPS

### SFTP (SSH File Transfer Protocol)

SFTP is used for secure file transfer over SSH.

It is part of the SSH protocol suite.

SFTP encrypts:

- File transfers
- Login credentials
- Commands

---

## Default Port

| Protocol | Port |
|---|---|
| SFTP | 22 |

SFTP uses the same port as SSH.

---

## Connecting with SFTP

Command:

```bash
sftp username@hostname
```

Example:

```bash
sftp user@192.168.1.10
```

- Connects securely to remote server

---

## Common SFTP Commands

### Download File

```bash
get filename
```

- Downloads file from server

### Upload File

```bash
put filename
```

- Uploads file to server

---

## Features of SFTP

- Uses SSH encryption
- Secure file transfer
- Easier to configure with OpenSSH
- Uses single secure connection

---

## FTPS (File Transfer Protocol Secure)

FTPS is FTP secured using TLS encryption.

Similar to:

- HTTP → HTTPS
- FTP → FTPS

FTPS protects:

- File transfers
- User credentials
- Network traffic

---

## Default Port

| Protocol | Port |
|---|---|
| FTPS | 990 |

---

## FTPS Features

- Uses TLS certificates
- Encrypts FTP communication
- Requires certificate setup
- Uses separate connections for:
  - Control
  - Data transfer

This can make firewall configuration harder.

---

## SFTP vs FTPS

| SFTP | FTPS |
|---|---|
| Uses SSH | Uses TLS |
| Port 22 | Port 990 |
| Part of SSH protocol | Secure version of FTP |
| Easier firewall setup | More complex firewall setup |

---

## Key Points

- SFTP = SSH File Transfer Protocol
- FTPS = File Transfer Protocol Secure
- SFTP uses SSH encryption
- FTPS uses TLS encryption
- SFTP uses Port 22
- FTPS uses Port 990
- Both provide secure file transfer

## VPN (Virtual Private Network)

### What is a VPN ?

VPN stands for Virtual Private Network.

It creates a secure private connection over the public internet.

VPN allows devices in different locations to communicate safely as if they were on the same local network.

---

## Why VPN is Needed ? 

The internet normally transfers data without built-in privacy protection.

Problems without VPN:

- Data can be intercepted
- Traffic can be monitored
- Information may be modified

VPN solves this by encrypting network communication.

---

## Meaning of VPN

### Virtual

Devices communicate over the internet as if connected to the same private network.

### Private

VPN encrypts traffic to keep communication secure and confidential.

---

## How VPN Works 

1. Device connects to VPN server
2. Secure encrypted tunnel is created
3. Data travels safely through the tunnel
4. Remote devices communicate securely

---

## VPN Benefits

- Encrypts internet traffic
- Protects sensitive data
- Secure remote access
- Safe communication between offices
- Protects data on public Wi-Fi

---

## VPN Requirements

To use a VPN:

- Internet connection
- VPN server
- VPN client

---

## Common VPN Usage

Companies use VPNs to:

- Connect branch offices
- Allow employees remote access
- Access shared company resources securely

---

## VPN Limitations

Some VPNs:

- Only provide access to private networks
- Do not route all internet traffic
- May leak the real IP address or DNS requests

Extra checks like DNS leak tests may be needed.

---

## Legal Note

VPN usage may be restricted or illegal in some countries.

Always check local laws before using a VPN.

> Finally, although in many scenarios, one would establish a VPN connection to route all the traffic over the VPN tunnel, some VPN connections don’t do this. The VPN server may be configured to give you access to a private network but not to route your traffic. Furthermore, some VPN servers leak your actual IP address, although they are expected to route all your traffic over the VPN. Depending on why you are using a VPN connection, you might need to run a few more tests, such as a DNS leak test.
> Finally, some countries consider using VPNs illegal and even punishable. Please check the local laws and regulations before using VPNs, especially while travelling.
