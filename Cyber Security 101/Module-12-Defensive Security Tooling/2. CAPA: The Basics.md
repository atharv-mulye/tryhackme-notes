# CAPA: The Basics

## What is CAPA ?

CAPA (Common Analysis Platform for Artifacts) is an open-source static malware analysis tool developed by FireEye Mandiant.

It analyzes executable files and automatically identifies their capabilities using a large set of predefined rules.

Instead of reverse engineering the entire binary manually, CAPA quickly tells you what the program is capable of doing.

---

## Static vs Dynamic Analysis

### Static Analysis
- Examines a file **without executing it**.
- Safer because the malware never runs.
- Used by CAPA.

### Dynamic Analysis
- Executes the file in an isolated environment (sandbox).
- Observes the malware's actual behavior during execution.

---

## Files Supported by CAPA

- Portable Executables (PE): Windows executable files (.exe, .dll) that contain programs or libraries.
- ELF binaries: Linux/Unix executable files used to run programs and shared libraries.
- .NET modules: Applications or libraries compiled for the Microsoft .NET runtime (CLR), such as .exe and .dll files.
- Shellcode: Small machine-code payloads designed to execute specific actions, often used in exploits.
- Sandbox reports: Logs generated by sandbox environments that record a program's behavior during execution.

---

## What Can CAPA Detect ?

CAPA identifies capabilities such as:

- Network communication
- File creation/modification
- Registry operations
- Process injection
- Process creation
- Persistence mechanisms
- Encryption
- Command execution
- Anti-analysis techniques
- Many other malicious behaviors

---

## Why Use CAPA ?

- Fast static malware analysis
- Does not execute suspicious files
- Automates years of reverse engineering knowledge
- Helps analysts quickly understand malware functionality
- Useful for malware analysis, threat hunting, and incident response

> The beauty of CAPA is that it encapsulates years of reverse engineering knowledge into an automated tool, making it accessible even to those who may not be experts in reverse engineering. This can be incredibly useful for analysts and security professionals, allowing them to quickly understand potentially malicious software's functionality without manually reverse engineering the code.
> CAPA answers the question: "What is this executable capable of doing?" without running it.

## Common Options

| Option | Purpose | Example |
|--------|---------|---------|
| `-h` | Display help and available options | `capa -h` |
| `-v` | Show verbose results | `capa.exe .\cryptbot.bin -v` |
| `-vv` | Show very detailed (very verbose) results | `capa.exe .\cryptbot.bin -vv` |

> Higher verbosity provides more analysis details but increases processing time.

---

## Reading a Saved Result

Instead of analyzing the binary again, we can view a previously saved report:

```powershell
Get-Content .\cryptbot.txt
```

This displays the same CAPA analysis output without rerunning the scan.

---

## CAPA Output Sections

- File Information — Hashes (MD5, SHA1, SHA256), OS, architecture, file format, analysis type.
- MITRE ATT&CK Mapping — Maps detected capabilities to ATT&CK tactics and techniques.
- MAEC Category — Classifies the malware's overall behavior.
- MBC (Malware Behavior Catalog) — Lists malware behaviors (e.g., HTTP communication, process creation, file operations).
- Capabilities — Human-readable list of what the executable can do (networking, persistence, anti-VM, PowerShell, file operations, etc.).

> CAPA does not determine whether a file is malicious, it reports the capabilities it discovers.

### 2. MITRE ATT&CK

MITRE ATT&CK is a knowledge base that organizes attacker behaviors into standard categories.
CAPA maps the detected capabilities to these behaviors.

> The MITRE ATT&CK (Adversarial Tactics, Techniques, and Common Knowledge) framework is a comprehensive global knowledge repository that meticulously documents the tactics and techniques employed by threat actors at every stage of a cyber-attack. It functions as a strategic playbook, providing detailed insights into attackers' methods, from gaining initial access to maintaining a presence, escalating privileges, evading defenses, moving laterally within a network, and much more. 

Example:

```terminal
┌──────────────────────┬───────────────────────────────────────────────────────────────────────────┐
│ ATT&CK Tactic        │ ATT&CK Technique                                                          │
├──────────────────────┼───────────────────────────────────────────────────────────────────────────┤
│ DEFENSE EVASION      │ Obfuscated Files or Information [T1027]                                   │
│                      │ Obfuscated Files or Information::Indicator Removal from Tools [T1027.005] │
│                      │ Virtualization/Sandbox Evasion::System Checks [T1497.001]                 │
```

### 3. MAEC (Malware Attribute Enumeration and Characterization)

MAEC is a standard used to classify malware based on its overall behavior.

Common values:

| MAEC Value | Meaning |
|------------|---------|
| Launcher | Starts or launches malicious actions (e.g., runs payloads, creates persistence, connects to C2). |
| Downloader | Downloads additional files or payloads from the Internet and executes them. |

> Malware Attribute Enumeration and Characterization is a specialized language designed to encode and communicate complex details concerning malware. It contains an extensive range of attributes, including behaviours, artefacts, and interconnections among various instances of malware. This language functions as a standardized system for tracking and analyzing the complicated complexities of malware.

Example:

```terminal
┌─────────────────────────────┬────────────────────────────────────────────────────────────────────┐
│ MAEC Category               │ MAEC Value                                                         │
├─────────────────────────────┼────────────────────────────────────────────────────────────────────┤
│ malware-category            │ launcher                                                           │
└─────────────────────────────┴────────────────────────────────────────────────────────────────────┘
```

This means the binary mainly acts as a launcher rather than performing all malicious actions itself.

| MAEC Value | Description |
|------------|-------------|
| Launcher | Exhibits behaviors that trigger specific actions similar to malware behavior. |
| Downloader | Exhibits behaviors where it downloads and executes other files, commonly seen in more complex malware. |

When CAPA tags a file with a “launcher” MAEC value, it indicates that the file demonstrates behaviour similar to but not limited to:
- Dropping additional payloads
- Activating persistence mechanisms
- Connecting to command-and-control (C2) servers
- Executing specific functions

Additionally, when CAPA tags a file with a “Downloader” MAEC value, it indicates that the file demonstrates behaviour similar but not limited to:
- Fetching additional payloads or resources from the internet
- pulling in updates
- executing secondary stages
- retrieving configuration files

## Dissecting CAPA Results Part 2 : Malware Behavior Catalogue

## What is MBC?

MBC (Malware Behavior Catalog) is a standardized framework that describes what a malware sample is capable of doing.

Unlike MITRE ATT&CK (which focuses on attacker techniques), MBC focuses on malware behaviors.

CAPA maps detected capabilities to MBC categories to make malware behavior easier to understand.

---

## MBC Format

| Format | Sample | Explanation |
|--------|--------|-------------|
| OBJECTIVE::Behavior::Method [Identifier] | `ANTI-STATIC ANALYSIS::Executable Code Obfuscation::Argument Obfuscation [B0032.020]` | `ANTI-STATIC ANALYSIS` = Objective<br>`Executable Code Obfuscation` = Behavior<br>`Argument Obfuscation` = Method<br>`B0032.020` = Identifier |
| OBJECTIVE::Behavior [Identifier] | `COMMUNICATION::HTTP Communication [C0002]` | `COMMUNICATION` = Objective<br>`HTTP Communication` = Behavior<br>`C0002` = Identifier |

> The first format contains an additional **Method** (similar to a sub-technique).

---

## Objectives

Objectives describe the overall goal of the malware.

| Objective | Purpose |
|-----------|---------|
| Anti-Behavioral Analysis | Evades sandboxes/debuggers. |
| Anti-Static Analysis | Makes static analysis difficult through obfuscation. |
| Collection | Collects information from the victim. |
| Command and Control | Communicates with attacker-controlled servers. |
| Credential Access | Steals usernames, passwords, or credentials. |
| Defense Evasion | Avoids detection by security tools. |
| Discovery | Gathers system or network information. |
| Execution | Executes malicious commands or code. |
| Exfiltration | Steals and sends data outside the network. |
| Impact | Damages or disrupts systems. |
| Lateral Movement | Spreads to other systems. |
| Persistence | Maintains long-term access. |
| Privilege Escalation | Gains higher privileges. |

---

## Micro-Objectives

Micro-objectives group common low-level actions that malware performs.

| Micro-Objective | Description |
|----------------|-------------|
| PROCESS | Process-related actions (create, terminate, inject). |
| MEMORY | Memory operations (allocate, protect, free). |
| COMMUNICATION | Network communication (HTTP, DNS, FTP, SMTP, etc.). |
| DATA | Data operations (check, encode, decode, compress). |

---

## Common MBC Behaviors

| Objective | Behavior | ID | Meaning |
|-----------|----------|----|---------|
| ANTI-BEHAVIORAL ANALYSIS | Lab Machine Detection | B0009 | Detects virtual machines or sandboxes. |
| ANTI-STATIC ANALYSIS | Executable Code Obfuscation | B0032 | Obfuscates code to hinder analysis. |
| EXECUTION | Command and Scripting Interpreter | E1059 | Executes commands or scripts (PowerShell, CMD, Bash, etc.). |
| DISCOVERY | File and Directory Discovery | E1083 | Searches files and folders. |
| DEFENSE EVASION | Obfuscated Files or Information | E1027 | Hides or encodes data to avoid detection. |

---

## Common Micro-Behaviors

| Micro-Objective | Micro-Behavior | ID | Meaning |
|----------------|----------------|----|---------|
| MEMORY | Allocate Memory | C0007 | Allocates memory for execution or unpacking. |
| PROCESS | Create Process | C0017 | Starts a new process. |
| COMMUNICATION | HTTP Communication | C0002 | Communicates over HTTP. |
| DATA | Check String | C0019 | Checks or searches strings. |
| DATA | Encode Data | C0026 | Encodes data (Base64, XOR, etc.). |
| FILE SYSTEM | Create Directory | C0046 | Creates directories. |
| FILE SYSTEM | Delete File | C0047 | Deletes files. |

---

## Common Methods

Methods provide more specific details about a behavior.

| Behavior | Method | ID | Meaning |
|----------|--------|----|---------|
| Executable Code Obfuscation | Argument Obfuscation | B0032.020 | Calculates API arguments at runtime. |
| Executable Code Obfuscation | Stack Strings | B0032.017 | Builds/decrypts strings on the stack. |
| HTTP Communication | Read Header | C0002.014 | Reads HTTP headers. |
| Encode Data | Base64 | C0026.001 | Encodes data using Base64. |
| Encode Data | XOR | C0026.002 | Encodes data using XOR. |
| Obfuscated Files or Information | Encoding-Standard Algorithm | E1027.m02 | Uses standard encoding (e.g., Base64). |

---

## Reading an MBC Result

Example:

```text
DATA
└── Encode Data::Base64 [C0026.001]
```

Interpretation:

- Objective → DATA
- Behavior → Encode Data
- Method → Base64
- Identifier → C0026.001

Conclusion:

> The binary is capable of encoding data using Base64.
