# Networking 

## Introduction

- Networking is how computers talk to each other over the internet.
- Every device needs an IP address to send/receive data.
- Data does not move directly — it travels in small pieces called packets.

---

## OSI Model 

The OSI Model is a 7-layer structure that explains how data moves from one device to another.

Think of it like steps that data follows before reaching another computer.

## OSI 7 Layers 

### Layer 1 : Physical Layer
- Real hardware layer (cables, WiFi signals)
- Sends raw bits (0s and 1s)
- Examples :
  - Ethernet cable
  - Fiber optics
  - Radio signals (WiFi)

Basically : “Wires and signals”

### Layer 2 : Data Link Layer
- Communication inside the same network
- Uses MAC address
- Ensures data moves between nearby devices

Example :
- Your laptop → WiFi router in same network

Basically : “Local delivery inside a network”

### Layer 3 : Network Layer
- Moves data between different networks
- Uses IP address
- Handles routing (choosing path)

Example :
- Your device in India → Server in another country

Basically : “Finding best path across networks”

### Layer 4 : Transport Layer
- End-to-end communication between devices
- Uses :
  - TCP (reliable)
  - UDP (fast, less reliable)
- Breaks data into smaller parts and reassembles it

Basically : “Makes sure data reaches properly”

### Layer 5 : Session Layer
- Creates and manages connection between two devices
- Keeps communication active

Example :
- Login session in apps or websites

Basically : “Starts and maintains connection”

### Layer 6 : Presentation Layer
- Changes data format so system can understand it
- Handles:
  - Encryption
  - Compression
  - Encoding (ASCII, Unicode)

Example :
- Image formats like JPG, PNG

Basically : “Translates data format”

### Layer 7 : Application Layer
- What users directly interact with
- Network services used by apps

Examples :
- HTTP (websites)
- FTP (file transfer)
- DNS (domain lookup)
- Email protocols (SMTP, IMAP)

Basically : “Apps that use the internet”

---

## OSI Model Summary 

| Layer | Name | Simple Meaning | Examples |
|------|------|----------------|----------|
| 7 | Application | User services | HTTP, FTP, DNS |
| 6 | Presentation | Format data | JPEG, PNG, encryption |
| 5 | Session | Manage connection | RPC, NFS |
| 4 | Transport | End-to-end delivery | TCP, UDP |
| 3 | Network | Routing between networks | IP, ICMP |
| 2 | Data Link | Local network communication | MAC, Ethernet |
| 1 | Physical | Hardware signals | cables, WiFi |

## TCP/IP Model 

### What is TCP/IP Model ?

- TCP/IP stands for Transmission Control Protocol / Internet Protocol
- It is a real-world networking model (used in the internet today)
- Developed by the U.S. Department of Defense (DoD) in the 1970s
- Built to keep networks working even if parts fail

Simple idea : Even if some network paths are broken, data can still find another route.

### Why TCP/IP Model Exists ? 

- More practical than OSI model
- Designed for real internet communication
- Focuses on how data actually travels

### TCP/IP Layers (Top to Bottom View)

TCP/IP has 4 main layers :

### 1. Application Layer
- Combines OSI layers 5, 6, 7
- Handles user-facing network services

Examples :
- HTTP / HTTPS (web browsing)
- FTP (file transfer)
- SMTP / IMAP (email)
- SSH / Telnet (remote login)

Basically : “Apps that use the network”

### 2. Transport Layer
- Same as OSI Layer 4
- Responsible for communication between two devices
- Controls reliability and data flow

Protocols:
- TCP → reliable, slow, ordered
- UDP → fast, no guarantee

Basically : “How data is delivered between devices”

### 3. Internet Layer
- Same as OSI Layer 3
- Handles routing across networks
- Uses IP addresses to send packets

Protocols :
- IP (Internet Protocol)
- ICMP (error messages like ping)
- IPSec (security)

Basically : “Finding path across the internet”

### 4. Link Layer
- Same as OSI Layer 2 (and part of Layer 1 conceptually)
- Handles local network communication
- Works with MAC addresses and hardware

Examples :
- Ethernet (802.3)
- WiFi (802.11)

Basically : “Local device communication”

---

## OSI vs TCP/IP Mapping

| OSI Layer | TCP/IP Layer | Examples |
|----------|-------------|----------|
| Application (7) | Application | HTTP, FTP, SSH |
| Presentation (6) | Application | Encoding, encryption |
| Session (5) | Application | Sessions, connections |
| Transport (4) | Transport | TCP, UDP |
| Network (3) | Internet | IP, ICMP |
| Data Link (2) | Link | Ethernet, WiFi |
| Physical (1) | Link (or separate physical layer) | cables, signals |

---

## Key Differences 

### OSI Model
- Theoretical model
- 7 layers
- Used for learning and understanding

### TCP/IP Model
- Real-world model
- 4 layers (sometimes 5)
- Used in actual internet systems

---

## Key Idea 

- OSI = learning model (theory)
- TCP/IP = real internet model
- Both describe how data moves, just in different structures

---

## Key Understanding

- Application layer → user services (web, email, login)
- Transport layer → TCP/UDP communication
- Internet layer → IP routing across networks
- Link layer → local network + hardware

## IP Addresses and Subnets 

### What is an IP Address ?

An IP address is a unique identifier given to each device on a network so it can communicate with other devices.

Example IPs :
- 192.168.0.1
- 172.16.159.243

These are IPv4 addresses (Internet Protocol version 4), which are the most commonly used today.

You can think of an IP address like a home address :
- It helps identify a device
- It allows data (like messages or files) to be delivered correctly
- Without it, devices cannot properly find each other on a network

---

## IPv4 Structure

An IPv4 address is made of:
- 32 bits total
- Split into 4 parts called octets
- Each octet is 8 bits
- Each octet has a value from 0 to 255

Example : 192.168.1.10

So :
- 192 = 1st octet  
- 168 = 2nd octet  
- 1 = 3rd octet  
- 10 = 4th octet  

---

## Network and Broadcast Addresses

Inside every subnet :

- `0` address → Network address  
- `255` address → Broadcast address  

Example :

- 192.168.1.0 → Network address
- 192.168.1.255 → Broadcast address


### Broadcast Address Meaning
- Used to send data to all devices in the network

### Important Note
Because of this structure, IPv4 supports about :
- ~4 billion addresses (2³²)

---

## Checking IP Address on System

### Windows

```bash 
ipconfig
```

### Linux / Unix

```bash
ifconfig
```
or
```bash
ip a s
```

---

### Example Output Meaning

From `ifconfig`:
- IP Address: `192.168.66.89`
- Subnet Mask: `255.255.255.0`
- Broadcast: `192.168.66.255`

From `ip a s` :

192.168.66.89/24

This means :
- `/24` = subnet mask 255.255.255.0
- First 24 bits are fixed for the network
- Remaining bits are for hosts (devices)

So valid host range becomes:
- 192.168.66.1 → 192.168.66.254

---

## Subnet Mask vs CIDR Notation

| Format | Meaning |
|------|--------|
| 255.255.255.0 | Subnet mask |
| /24 | CIDR notation |

Both mean the same thing :
- Network part = first 24 bits
- Host part = last 8 bits

## Private IP Addresses

Private IPs are used inside local networks and are not directly accessible from the internet.

Defined in RFC 1918 :

### Private IP Ranges :
- 10.0.0.0 – 10.255.255.255 (10/8)
- 172.16.0.0 – 172.31.255.255 (172.16/12)
- 192.168.0.0 – 192.168.255.255 (192.168/16)

> RFC 1918 is a standard defined by the Internet Engineering Task Force (IETF) that outlines specific rules regarding the use of private IP address ranges in IPv4 networks
---

### Simple Idea

- Public IP → like a home address (reachable from internet)
- Private IP → like internal house numbers inside a building

To access the internet from private IPs :
- Router uses NAT (Network Address Translation)

---

## Routing

A router is a device that moves data between networks.

Think of it like a post office :
- You give it a packet (data)
- It decides where to send it next
- It forwards it step by step until it reaches the destination

### Key Points 

- Works at Layer 3 (Network Layer)
- Uses IP addresses to make decisions
- Often data passes through multiple routers before reaching final destination

---

## Key Points

- IP address uniquely identifies devices on a network
- IPv4 = 32-bit address system
- Subnet defines network + host division
- `/24` = common subnet mask (255.255.255.0)
- Private IPs are used inside local networks
- Routers forward data between networks using IP addresses

## UDP and TCP 

### Overview

The IP address helps us reach the correct device (host) on a network.

But once we reach the device, we still need a way for programs (processes) to talk to each other.

That is where transport layer protocols come in :
- UDP (User Datagram Protocol)
- TCP (Transmission Control Protocol)

Both work at Layer 4 (Transport Layer).

---

## Port Numbers

Since one device can run many services, we use port numbers to identify them.

- IP address → identifies the device
- Port number → identifies the service/process on that device

### Port range :
- 1 to 65535 (valid ports)
- 0 is reserved

Reason:
- Port numbers are 16-bit → `2¹⁶ = 65536` values → 0–65535

---

## UDP (User Datagram Protocol)

UDP is a simple and fast transport protocol.

### Key Features :
- Connectionless (no setup needed)
- No delivery confirmation
- No guarantee packets arrive
- Works at Layer 4

### What it means in simple terms :
You send data and hope it reaches the destination.

### Real-life analogy :
Like sending normal mail without tracking:
- Faster
- Cheaper
- But no delivery confirmation

### When UDP is useful :
- Streaming
- Online games
- Voice calls (VoIP)
- DNS queries

Because speed matters more than perfect delivery.

---

## TCP (Transmission Control Protocol)

TCP is a reliable and structured transport protocol.

### Key Features :
- Connection-oriented (must establish connection first)
- Ensures data is delivered correctly
- Detects missing or duplicate packets
- Uses acknowledgements (ACKs)
- Works at Layer 4

---

### How TCP ensures reliability

TCP assigns:
- Sequence numbers → order of data
- Acknowledgement numbers → confirms received data

This helps:
- Detect missing packets
- Reorder data correctly
- Avoid duplicates

---

## TCP Three-Way Handshake

Before data transfer, TCP creates a connection using 3 steps:

### 1. SYN (Client → Server)
- Client sends a SYN packet
- Includes initial sequence number

### 2. SYN-ACK (Server → Client)
- Server responds with SYN-ACK
- Acknowledges client request
- Sends its own sequence number

### 3. ACK (Client → Server)
- Client sends ACK
- Confirms connection is established

After this : Connection is ready for data transfer

### Simple analogy:
Like making a phone call :
1. “Can you hear me?” (SYN)
2. “Yes, I can hear you, can you hear me?” (SYN-ACK)
3. “Yes” (ACK)

---

## UDP vs TCP Comparison

| Feature | UDP | TCP |
|--------|-----|-----|
| Connection | No connection | Connection required |
| Speed | Faster | Slower |
| Reliability | No guarantee | Reliable |
| Ordering | No order guarantee | Ordered delivery |
| Acknowledgement | No | Yes (ACK system) |
| Use case | Streaming, gaming | Websites, file transfer |

---

## Key Points 

- UDP = fast, but unreliable
- TCP = reliable, but slower
- Both use port numbers (1–65535) to reach correct applications
- TCP uses a 3-step handshake to establish connections

## Encapsulation 

### What is Encapsulation ?

Encapsulation is the process where each layer of the network adds its own information (called a header, and sometimes a trailer) to the data before passing it to the next layer.

This happens as data moves down the networking stack.

Each layer only focuses on its own job and does not need to know how other layers work.

---

## Why Encapsulation is Important ? 

Encapsulation helps because :
- Each network layer works independently
- Data is structured properly for transmission
- Devices can communicate across complex networks

---

## How Encapsulation Works ? 

<img width="878" height="336" alt="image" src="https://github.com/user-attachments/assets/5c6301c1-24dd-4e79-b1d2-79c985f4b917" />

### Application Layer
- User generates data (example: sending a message or search request)
- Application formats the data using protocols like HTTP/HTTPS
- Data is passed to the transport layer

### Transport Layer (TCP/UDP)
- Adds a TCP or UDP header
- This creates either:
  - TCP segment (if using TCP)
  - UDP datagram (if using UDP)
- Passes it to the network layer

### Network Layer (IP Layer)
- Adds an IP header
- Includes source and destination IP addresses
- Creates an IP packet
- Passes it to the data link layer

### Data Link Layer (Ethernet/WiFi)
- Adds both a header and a trailer
- Prepares the data for transmission over the physical network
- Sends it to the next device (usually a router)

---

## Key Idea

Each layer :
- Wraps the data received from the layer above it
- Adds its own control information

So data becomes more structured as it moves downward through the network layers.

---

## Decapsulation (Receiving Side)

At the destination :
- Each layer removes its own header (and trailer if present)
- The data moves upward through the layers
- The original application data is finally delivered to the application

---

## Life of a Packet 

When you perform an action like searching on a website :

- The browser creates a request using HTTP/HTTPS
- TCP establishes a connection and sends the request reliably
- IP adds source and destination addressing for routing
- The data link layer prepares it for physical transmission
- Routers forward the packet across networks using IP information
- At the destination, the process is reversed until the server receives the original data

---

## Key Points 

- Encapsulation = wrapping data with headers at each layer
- Each layer adds specific networking information
- Data is prepared step-by-step for transmission across networks
- At the destination, the process is reversed (decapsulation)

## TELNET

### What is TELNET ?

TELNET (Teletype Network) is a network protocol used to connect to a remote system through a text-based interface.

It allows you to:
- Connect to a remote machine
- Send commands using text
- Communicate with services running on specific TCP ports

Although it was originally used for remote administration, it is now mostly replaced by more secure protocols like SSH.

---

## Key Idea

TELNET does not care what service you connect to — it simply connects to any service that is listening on a TCP port.

So it can be used to manually interact with different network services.

---

## Common Services Used in Practice

### Echo Server
- Port: 7
- Behavior: Sends back (echoes) whatever you type

---

### Daytime Server
- Port: 13
- Behavior: Returns current date and time, then closes connection

---

### HTTP (Web Server)
- Port: 80
- Behavior: Serves web pages when proper HTTP requests are sent

---

## Using TELNET

### Basic Syntax
```bash
telnet <IP_ADDRESS> <PORT>
```

Example:
- Connect to a service running on a machine using its IP and port number

---

## Echo Server Example

When connected to the echo server:
- Whatever you type is sent back to you

Behavior:
- You send text
- Server repeats the same text back

Connection can be closed using:
- `CTRL + ]`
- Then type `quit`

---

## Daytime Server Example

When connected to port 13:
- The server sends current date and time
- Connection closes automatically after response

No manual input is needed after connection

---

## HTTP Server Example Using TELNET

TELNET can also be used to manually interact with a web server.

### Steps:
1. Connect to port 80
2. Send an HTTP request manually
3. Provide required headers
4. Press Enter twice to send the request

---

### Example Request Format:
- Request line: `GET / HTTP/1.1`
- Header: `Host: <domain>`
- Blank line to finish request

---

## What Happens Internally ? 

When using TELNET with HTTP:
- You are manually sending HTTP requests
- The server responds with raw HTTP response data
- This is how browsers normally communicate, but in an automated way

---

## Key Takeaways

- TELNET is a simple text-based remote communication tool
- It works over TCP
- It can connect to any service listening on a port
- It is useful for testing and learning network services
- It is insecure and mostly replaced by SSH in real systems
