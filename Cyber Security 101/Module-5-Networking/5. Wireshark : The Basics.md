# Wireshark: The Basics
## Introduction

Wireshark is a free and open-source network traffic analysis tool used to capture, inspect, and analyse network packets. It can monitor live network traffic and examine saved packet capture (PCAP) files, making it one of the most widely used packet analysis tools.

---

## Tool Overview

### Common Use Cases

#### Network Troubleshooting
- Identify network issues and bottlenecks.
- Investigate congestion and performance problems.
- Locate points of failure within a network.

#### Security Analysis
- Detect unusual or suspicious network activity.
- Identify unauthorized devices on the network.
- Monitor unexpected port usage and abnormal traffic patterns.

#### Protocol Investigation
- Study how network protocols operate.
- Examine response codes and packet contents.
- Understand communication between systems.

> **Note :** Wireshark is not an Intrusion Detection System (IDS). It does not actively detect attacks or modify network traffic. It simply captures and displays packets for analysis. Effective investigation depends on the analyst's knowledge and interpretation.
> It also doesn't modify packets, it reads them.Hence, detecting any anomaly or network problem highly relies on the analyst's knowledge and investigation skills

## Packet Dissection

Packet dissection is the process of breaking down a network packet and decoding its protocols and fields. Wireshark automatically interprets packet contents and displays information based on supported protocols.

This allows analysts to inspect network communications layer by layer and understand how data travels through a network.

> **Note :** Understanding the OSI model is important when analysing packet structures, as Wireshark organises packet information according to these layers.

---

## Viewing Packet Details

To inspect a packet :

1. Select a packet from the **Packet List Pane**.
2. The packet details will appear in the **Packet Details Pane**.
3. Double-clicking a packet opens its details in a separate window.

When a field is selected in the details pane, the corresponding bytes are highlighted in the **Packet Bytes Pane**, making it easier to locate specific data within the packet.

---

## Packet Structure in Wireshark

A packet is typically displayed as multiple layers that correspond to the OSI model.

Common layers include:

1. Frame Information
2. Data Link Layer (MAC Addresses)
3. Network Layer (IP Addresses)
4. Transport Layer (TCP/UDP)
5. Protocol-Specific Information
6. Application Layer Details
7. Application Data

---

## Frame Information (Layer 1)

This section contains general information about the captured packet.

### Information Available

- Frame number
- Arrival time
- Packet length
- Capture length
- Interface details

### Purpose

Provides metadata about the packet and capture process at the Physical Layer.

---

## MAC Address Information (Layer 2)

This section represents the Data Link Layer.

### Information Available

- Source MAC address
- Destination MAC address
- Ethernet frame details

### Purpose

Identifies devices communicating on the local network.

---

## IP Address Information (Layer 3)

This section represents the Network Layer.

### Information Available

- Source IP address
- Destination IP address
- IP version
- Time To Live (TTL)
- Fragmentation details

### Purpose

Shows where the packet originated and where it is being sent across networks.

---

## Transport Layer Information (Layer 4)

Displays information about the transport protocol being used.

### Common Protocols

- TCP
- UDP

### Information Available

- Source port
- Destination port
- Sequence numbers
- Acknowledgement numbers
- Flags

### Purpose

Shows how data is delivered between applications and systems.

---

## Protocol Errors and Reassembly

Sometimes network data is split across multiple packets.

### Information Available

- TCP segment reassembly details
- Missing packets
- Fragmentation information
- Protocol warnings or errors

### Purpose

Helps identify transmission issues and reconstruct complete communications.

---

## Application Protocol Details (Layer 5+)

This section contains information specific to the application protocol being used.

### Common Protocols

- HTTP
- FTP
- SMB
- DNS
- SMTP

### Information Available

Protocol-specific fields and commands.

#### Example (HTTP)

- Request method
- Response code
- Headers
- Host information

### Purpose

Allows detailed analysis of application-level communications.

---

## Application Data

This section contains the actual data exchanged by the application.

### Examples

- Web page content
- File contents
- User input
- Server responses

### Purpose

Displays the payload carried by the protocol.

---

## Packet Bytes Pane

The Packet Bytes Pane displays the raw packet contents.

### Formats Available

- Hexadecimal view
- ASCII view

### Benefits

- View raw packet data
- Verify protocol decoding
- Identify hidden or unusual content

Selecting fields in the Packet Details Pane automatically highlights their corresponding bytes.

## Finding Packets

<img width="1518" height="907" alt="66c44fd9733427ea1181ad58-1761116433011" src="https://github.com/user-attachments/assets/da2dfd5c-2138-4519-a6a8-5f9cb7176aaf" />

- Suspicious activity
- Error messages

### Search Types

Wireshark supports multiple search methods.

| Search Type | Description |
|------------|-------------|
| **Display Filter** | Searches using Wireshark filter syntax. |
| **Hex Value** | Searches for hexadecimal values. |
| **String** | Searches for text within packets. |
| **Regular Expression (Regex)** | Searches using pattern matching expressions. |

#### Note : 

- String and Regex searches are commonly used.
- Searches are case-insensitive by default.
- Case sensitivity can be enabled when needed.

### Search Locations

Searches can be performed in different packet panes.

| Pane | Purpose |
|--------|---------|
| **Packet List Pane** | Searches summary information. |
| **Packet Details Pane** | Searches decoded protocol fields. |

## Packet Filtering

Packet captures often contain a large amount of traffic, making analysis difficult. Wireshark provides powerful filtering capabilities that help analysts focus only on relevant packets.

Wireshark supports two filtering methods:

| Filter Type | Purpose |
|-------------|---------|
| **Capture Filter** | Filters packets while capturing traffic. |
| **Display Filter** | Filters packets after they have been captured. |

This section focuses on **Display Filters**, which are commonly used during packet analysis.

> **Tip :** A useful Wireshark rule is: **"If you can click it, you can usually filter it."**

---

## Apply as Filter

The quickest way to create a filter is by selecting a field within a packet.

### How It Works

1. Select a packet.
2. Right-click a field.
3. Choose **Apply as Filter**.

Wireshark automatically generates and applies the appropriate display filter.

## Filter by Port Number

Traffic can also be filtered using port numbers.

### TCP Port Filter

```text
tcp.port == <port>
```

### Example

```text
tcp.port == 80
```

Displays HTTP traffic using TCP port 80.

---

## UDP Port Filter

```text
udp.port == <port>
```

### Example

```text
udp.port == 53
```

Displays DNS traffic using UDP port 53.

---

## Filter by IP Address

To display traffic involving a specific IP address:

```text
ip.addr == <IP Address>
```

### Example

```text
ip.addr == 192.168.1.2
```

This shows all packets where the IP appears as either:

- Source IP
- Destination IP
