# Networking Secure Protocols

## Why Secure Protocols Are Needed ?

Basic networking protocols like :

- HTTP
- SMTP
- POP3
- IMAP
- TELNET

send data in plaintext.

This means anyone capturing the network traffic may be able to see:

- Passwords
- Emails
- Credit card details
- Messages
- Files

Attackers may also modify the transferred data or pretend to be a real server.

---

## Security Problems in Plaintext Protocols

### No Confidentiality

Data is not encrypted.

Anyone monitoring packets can read the information.

Example:

- HTTP traffic can expose login passwords

### No Integrity Protection

Data can be modified during transmission.

Example:

- Payment amount changed from `100` to `800`

### No Authentication

Users may connect to a fake server instead of the real one.

---

## TLS (Transport Layer Security)

TLS is used to secure communication between devices.

It adds:

- Encryption
- Integrity checking
- Authentication

TLS protects data while it travels across the network.

---

## Secure Versions of Common Protocols

| Insecure Protocol | Secure Version |
|---|---|
| HTTP | HTTPS |
| SMTP | SMTPS |
| POP3 | POP3S |
| IMAP | IMAPS |

The `S` means Secure.

### HTTPS

HTTPS is HTTP protected with TLS.

Benefits:

- Encrypts web traffic
- Protects passwords and payment data
- Verifies the real website identity

Example:

```bash
https://example.com
```

---

## Secure Email Protocols

### SMTPS

Secure version of SMTP used for sending encrypted emails.

### POP3S

Secure version of POP3 used for securely receiving emails.

### IMAPS

Secure version of IMAP used for securely synchronizing emails.

---

## SSH (Secure Shell)

SSH replaced TELNET because TELNET sends everything in plaintext.

SSH provides:

- Secure remote access
- Encrypted communication
- Safe command execution

Example:

```bash
ssh user@server
```

---

## VPN (Virtual Private Network)

VPN creates a secure encrypted connection over an insecure network like the internet.

Benefits:

- Encrypts traffic
- Hides communication from attackers
- Protects public Wi-Fi connections

---

## Summary

| Protocol | Secure Version |
|---|---|
| HTTP | HTTPS |
| SMTP | SMTPS |
| POP3 | POP3S |
| IMAP | IMAPS |
| TELNET | SSH |

---

## Key Points

- Plaintext protocols are insecure
- TLS adds encryption and security
- HTTPS protects web traffic
- SSH securely replaces TELNET
- VPN creates secure encrypted tunnels
- Secure protocols protect confidentiality, integrity, and authentication

## TLS (Transport Layer Security)

### What is TLS ?

TLS is a security protocol used to protect communication over a network.

It provides:

- Confidentiality
- Integrity
- Authentication

TLS encrypts data so attackers cannot read or modify it.

---

## Why TLS is Important ? 

Older protocols used plaintext communication.

Anyone capturing packets could see:

- Passwords
- Emails
- Chats
- Private data

Attackers could also modify the data being transferred.

TLS solves this problem using encryption.

---

## SSL and TLS History

### SSL (Secure Sockets Layer)

- Developed by Netscape
- SSL 2.0 released in 1995

---

### TLS (Transport Layer Security)

- Created by IETF in 1999
- Improved version of SSL
- TLS 1.3 released in 2018

TLS is the modern replacement for SSL.

---

## What TLS Protects

### Confidentiality

Encrypts data so only authorized users can read it.

Example:

- Protects passwords during login

### Integrity

Prevents attackers from changing transmitted data.

Example:

- Stops modification of payment amounts

### Authentication

Verifies that users are connected to the real server.

Example:

- Confirms the website is genuine

---

## TLS in Secure Protocols

TLS is added to existing protocols to make them secure.

| Insecure Protocol | Full Form | Secure Version | Full Form |
|---|---|---|---|
| HTTP | HyperText Transfer Protocol | HTTPS | HyperText Transfer Protocol Secure |
| DNS | Domain Name System | DoT | DNS over TLS |
| MQTT | Message Queuing Telemetry Transport | MQTTS | MQTT Secure |
| SIP | Session Initiation Protocol | SIPS | Session Initiation Protocol Secure |

The `S` means the protocol uses SSL/TLS security.

---

## TLS Certificates

Servers use digital certificates to prove their identity.

---

## Certificate Signing Request (CSR)

Server administrator creates a CSR and sends it to a Certificate Authority (CA).

---

## Certificate Authority (CA)

CA verifies the request and issues a signed certificate.

Example:

- Trusted organizations that validate websites

---

## Trusted Certificates

Browsers and operating systems store trusted CA certificates.

This allows devices to verify whether a server certificate is valid.

---

## How TLS Works ? 

1. Client connects to server
2. Server sends TLS certificate
3. Client verifies certificate
4. Secure encrypted connection starts

---

## Key Points

- TLS secures network communication
- TLS replaced SSL
- TLS provides:
  - Confidentiality
  - Integrity
  - Authentication
- HTTPS uses TLS
- TLS uses digital certificates
- CA signs certificates
- TLS protects passwords and sensitive data
