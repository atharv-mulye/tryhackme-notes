
# Firewall Fundamentals

## What is a Firewall ?

A Firewall is a network security device or software that monitors and filters incoming and outgoing network traffic based on predefined security rules.

Think of it as a security guard at the entrance of a building.

- Every network packet passes through the firewall.
- The firewall checks the packet against its rules.
- It either Allows or Blocks the traffic.

**Purpose**
- Prevent unauthorized access
- Allow legitimate traffic
- Protect devices and networks from attacks

## Types of Firewalls

### 1. Stateless Firewall

**OSI Layers:** Layer 3 (Network) & Layer 4 (Transport)

#### How it Works
- Checks every packet individually.
- Uses predefined rules only.
- Does **not** remember previous connections.

#### Characteristics
- Basic packet filtering
- No connection tracking
- Fast processing
- Cannot apply complex security policies

#### Example

Packet 1 from IP `1.1.1.1` is blocked.

Packet 2 from the same IP arrives.

Firewall checks it again from scratch because it has **no memory**.

> This type of firewall operates on layer 3 and layer 4 of the OSI model and works solely by filtering the data based on predetermined rules without taking note of the state of the previous connections. This means it will match every packet with the rules regardless of whether it is part of a legitimate connection. It maintains no information on the state of the previous connections to make decisions for future packets. Due to this, these firewalls can process the packets quickly. However, they cannot apply complex policies to the data based on its relationship with the previous connections. Suppose the firewall denies a few packets from a single source based on its rules. Ideally, it should drop all the future packets from this source because the previous packets could not comply with the firewall’s rules. However, the firewall keeps forgetting this, and future packets from this source will be treated as new and matched by its rules again.

---

### 2. Stateful Firewall

**OSI Layers:** Layer 3 & Layer 4

#### How it Works

- Checks packets and remembers previous connections.
- Maintains a **State Table**.
- Future packets belonging to an existing connection are processed faster.

#### State Table

Stores information such as:
- Source IP
- Destination IP
- Port
- Protocol
- Connection State

#### Characteristics

- Tracks active connections
- Recognizes trusted traffic
- Supports complex security policies
- Better security than stateless firewall

#### Example

User establishes an HTTPS connection.

Firewall records the connection.

Future packets of the same session are automatically allowed.

> Unlike stateless firewalls, this type of firewall goes beyond filtering packets by predetermined rules. It also keeps track of previous connections and stores them in a state table. This adds another layer of security by inspecting the packets based on their history with connections. Stateful firewalls operate at layer 3 and layer 4 of the OSI model. Suppose the firewall accepts a few packets from a source address based on its rules. In that case, it will take note of this connection in its stated table and allow all the future packets for this connection to automatically get allowed without inspecting each of them. Similarly, the stateful firewalls take note of the connections for which they deny a few packets, and based upon this information, they deny all the subsequent packets coming from the same source.

---

### 3. Proxy Firewall (Application Gateway)

**OSI Layer:** Layer 7 (Application Layer)

#### How it Works

Acts as an intermediary between the client and the Internet.

Instead of:

```
Client → Website
```

Communication becomes:

```
Client → Proxy Firewall → Website
```

The proxy:
- Inspects packet contents
- Hides internal IP addresses
- Applies application-level filtering

> A proxy server is a system or router that provides a gateway between users and the internet. Therefore, it helps prevent cyber attackers from entering a private network. It is a server, referred to as an “intermediary” because it goes between end-users and the web pages they visit online.

#### Characteristics

- Deep packet inspection
- Content filtering
- Application control
- Provides anonymity
- Can inspect SSL/TLS traffic

#### Example

Employee requests:

```
facebook.com
```

Proxy checks company policy.

If Facebook is blocked:

➡ Request is denied.

> The problem with previous firewalls was their inability to inspect the contents of a packet. Proxy firewalls, or application-level gateways, act as intermediaries between the private network and the Internet and operate on the OSI model’s layer 7. They inspect the content of all packets as well. The requests made by users in a network are forwarded by this proxy after inspection and masking them with their own IP address to provide anonymity for the internal IP addresses. Content filtering policies can be applied to these firewalls to allow/deny incoming and outgoing traffic based on their content.

---

### 4. Next-Generation Firewall (NGFW)

**OSI Layers:** Layer 3 – Layer 7

The most advanced firewall.

#### Features

- Deep Packet Inspection (DPI)
- Intrusion Prevention System (IPS)
- SSL/TLS Decryption
- Threat Intelligence Integration
- Heuristic Analysis
- Application Awareness
- Malware Detection

#### Characteristics

- Advanced threat protection
- Detects sophisticated attacks
- Blocks attacks in real time
- Uses behavioral analysis
- Protects against zero-day threats

#### Example

An encrypted HTTPS download contains malware.

NGFW:

- Decrypts traffic
- Inspects file
- Detects malware
- Blocks download


> This is the most advanced type of firewall that operates from layer 3 to layer 7 of the OSI model, offering deep packet inspection and other functionalities that enhance the security of incoming and outgoing network traffic. It has an intrusion prevention system that blocks malicious activities in real time. It offers heuristic analysis by analyzing the patterns of attacks and blocking them instantly before reaching the network. NGFWs have SSL/TLS decryption capabilities, which inspect the packets after decrypting them and correlate the data with the threat intelligence feeds to make efficient decisions.

| Firewall | OSI Layer | Remembers Connections? | Inspects Packet Content? | Best Use |
|-----------|-----------|------------------------|--------------------------|----------|
| Stateless | Layer 3–4 | ❌ No | ❌ No | Fast basic filtering |
| Stateful | Layer 3–4 | ✅ Yes | ❌ No | Enterprise networks |
| Proxy | Layer 7 | ✅ Yes | ✅ Yes | Web filtering & application control |
| NGFW | Layer 3–7 | ✅ Yes | ✅ Yes | Advanced enterprise security |

| Firewall | Characteristics |
|----------|-----------------|
| **Stateless Firewall** | • Basic filtering<br>• No tracking of previous connections<br>• Efficient for high-speed networks |

## Firewall Rules

Firewall rules define which network traffic is Allowed, Denied, or Forwarded based on specific conditions.

## Components of a Firewall Rule

| Component | Description |
|-----------|-------------|
| **Source Address** | IP address of the device sending the traffic. |
| **Destination Address** | IP address of the device receiving the traffic. |
| **Port** | Port number used by the service (e.g., 80, 22, 443). |
| **Protocol** | Communication protocol (TCP, UDP, ICMP, etc.). |
| **Action** | What the firewall should do (Allow, Deny, Forward). |
| **Direction** | Whether the rule applies to Inbound, Outbound, or Forwarded traffic. |

---

## Types of Actions

### 1. Allow

Permits matching traffic to pass through the firewall.

#### Example

| Action | Source | Destination | Protocol | Port | Direction |
|--------|--------|-------------|----------|------|-----------|
| Allow | 192.168.1.0/24 | Any | TCP | 80 | Outbound |

**Meaning:** Allow all devices in the internal network to access websites using HTTP (Port 80).

### 2. Deny

Blocks matching traffic.

#### Example

| Action | Source | Destination | Protocol | Port | Direction |
|--------|--------|-------------|----------|------|-----------|
| Deny | Any | 192.168.1.0/24 | TCP | 22 | Inbound |

**Meaning:** Block all incoming SSH (Port 22) connections to the internal network.

### 3. Forward

Redirects traffic to another device or network segment.

#### Example

| Action | Source | Destination | Protocol | Port | Direction |
|--------|--------|-------------|----------|------|-----------|
| Forward | Any | 192.168.1.8 | TCP | 80 | Inbound |

**Meaning:** Forward all incoming HTTP traffic to the web server at **192.168.1.8**.

---

## Direction of Firewall Rules

### 1. Inbound Rules

Apply to **incoming traffic** entering the network.

**Example:**
- Allow incoming HTTP (Port 80) traffic to a web server.

### 2. Outbound Rules

Apply to **outgoing traffic** leaving the network.

**Example:**
- Block all outgoing SMTP (Port 25) traffic except from the mail server.

### 3. Forward Rules

Apply to traffic being **forwarded to another device or network**.

**Example:**
- Forward incoming HTTP (Port 80) traffic to an internal web server.

## Windows Defender Firewall

### What is Windows Defender Firewall?

Windows Defender Firewall is the built-in firewall in Microsoft Windows.

It monitors and filters incoming and outgoing network traffic based on firewall rules.

### Features
- Built into Windows
- Create Allow/Deny rules
- Create custom inbound/outbound rules
- Different settings for different network types
- Enabled by default

## Network Profiles

Windows automatically detects the type of network using Network Location Awareness (NLA) and applies the appropriate firewall profile.

### 1. Private Network

Used for trusted networks such as:

- Home Wi-Fi
- Office LAN

Usually allows more communication between devices.

> This includes the firewall configurations to apply when connected to our home network. 

### 2. Public (Guest) Network

Used for untrusted networks such as:

- Coffee shops
- Airports
- Hotels
- Public Wi-Fi

Usually configured to:
- Block most incoming connections
- Allow only essential outgoing traffic

> This includes the firewall configurations to apply when connected to a public or untrusted network like coffee shops, restaurants, or similar. For example, when connecting to public networks, you can configure firewall settings to block all incoming network connections and allow only some outgoing connections that are essential for you. These settings will apply to the public network profile and will not be implemented when you are in your private home network.

## Linux Firewall

Linux provides built-in firewall functionality to monitor and control incoming and outgoing network traffic.

Unlike Windows Defender Firewall, Linux uses the Netfilter framework along with different firewall management utilities.

## Netfilter

Netfilter is the core firewall framework in the Linux kernel.

It provides:

- Packet Filtering
- Network Address Translation (NAT)
- Connection Tracking

Most Linux firewall tools are built on top of Netfilter.

---

## Linux Firewall Utilities

| Utility | Description |
|----------|-------------|
| **iptables** | Traditional Linux firewall utility based on Netfilter. Supports packet filtering, NAT, and firewall rules. |
| **nftables** | Successor to iptables. More efficient, flexible, and easier to manage. |
| **firewalld** | Dynamic firewall manager that uses zones and predefined rule sets. Built on Netfilter. |
| **ufw (Uncomplicated Firewall)** | Beginner-friendly interface for configuring firewall rules. Internally uses iptables/nftables. |

---

## UFW (Uncomplicated Firewall)

**UFW** is a simple command-line firewall management tool.

It simplifies creating firewall rules without writing complex iptables commands.

---

## Common UFW Commands

### Check Firewall Status

```bash
sudo ufw status
```

Example:

```text
Status: inactive
```

---

### Enable Firewall

```bash
sudo ufw enable
```

Example:

```text
Firewall is active and enabled on system startup
```

---

### Disable Firewall

```bash
sudo ufw disable
```

---

## Allow All Outgoing Traffic

```bash
sudo ufw default allow outgoing
```

Meaning:

- Allow all outgoing connections by default.
- Unless another rule specifically blocks them.

---

## Deny Incoming SSH Traffic

SSH uses:

- Port **22**
- Protocol **TCP**

Command:

```bash
sudo ufw deny 22/tcp
```

Meaning:

- Block all incoming SSH connections.

---

## View Firewall Rules

```bash
sudo ufw status numbered
```

Example:

```text
To              Action      From
--              ------      ----
[1] 22/tcp      DENY IN     Anywhere
[2] 22/tcp(v6)  DENY IN     Anywhere(v6)
```

The numbers help identify rules for deletion.

---

## Delete a Firewall Rule

Delete Rule Number **2**

```bash
sudo ufw delete 2
```

Example:

```text
Deleting:
deny 22/tcp

Proceed with operation (y|n)? y

Rule deleted
```
