# JavaScript Essentials

## What is JavaScript ?

JavaScript (JS) is a scripting language used to make web pages interactive and dynamic.

It works together with:

- HTML → Structure
- CSS → Styling
- JavaScript → Functionality

### Common Uses

- Form validation
- Button click actions
- Animations
- Dynamic content updates
- API requests

---

## Variables

### What are Variables ?

Variables are containers used to store data values.

Each variable has a name that can be used to access its value later.

### Variable Types

#### var

```javascript
var name = "Atharv";
```

- Function-scoped
- Older way of declaring variables

#### let

```javascript
let age = 20;
```

- Block-scoped
- Value can be changed

#### const

```javascript
const country = "India";
```

- Block-scoped
- Value cannot be reassigned

---

## Data Types

### What are Data Types ?

Data types define the kind of value stored in a variable.

### Common Data Types

#### String

Stores text.

```javascript
let name = "Atharv";
```

#### Number

Stores numeric values.

```javascript
let age = 20;
```

#### Boolean

Stores true or false.

```javascript
let passed = true;
```

#### Null

Represents an empty value.

```javascript
let data = null;
```

#### Undefined

Variable declared but no value assigned.

```javascript
let city;
```

#### Object

Stores multiple related values.

```javascript
let student = {
  name: "Atharv",
  age: 20
};
```

---

## Functions

### What is a Function ?

A function is a reusable block of code designed to perform a specific task.

### Syntax

```javascript
function functionName() {
    // code
}
```

### Example

```javascript
function greet() {
    console.log("Hello");
}

greet();
```

### Function with Parameter

```javascript
function PrintResult(rollNum) {
    console.log("Student " + rollNum + " passed");
}

PrintResult(101);
```

### Benefits

- Reusable code
- Easier maintenance
- Reduces repetition

---

## Loops

### What is a Loop ?

A loop repeatedly executes a block of code until a condition becomes false.

### for Loop

```javascript
for(let i = 1; i <= 5; i++) {
    console.log(i);
}
```

Output:

```text
1
2
3
4
5
```

### while Loop

```javascript
let i = 1;

while(i <= 5) {
    console.log(i);
    i++;
}
```

### do...while Loop

```javascript
let i = 1;

do {
    console.log(i);
    i++;
} while(i <= 5);
```

### Example: Print Student Results

```javascript
const rollNumbers = [101, 102, 103];

function PrintResult(rollNum) {
    console.log("Student " + rollNum + " passed");
}

for(let i = 0; i < rollNumbers.length; i++) {
    PrintResult(rollNumbers[i]);
}
```

### Benefits

- Reduces repetitive code.
- Efficient for processing multiple items.
- Commonly used with arrays and data.

## Request-Response Cycle

### What is the Request-Response Cycle ?

The request-response cycle describes how a client and server communicate.

### Flow

```text
Browser (Client)
        ↓ Request
Web Server
        ↓ Response
Browser (Client)
```

### Example

1. User visits a website.
2. Browser sends an HTTP request.
3. Server processes the request.
4. Server sends an HTTP response.
5. Browser displays the result.

### Example

```text
User opens login page
        ↓
Browser sends request
        ↓
Server returns webpage
        ↓
Browser displays webpage
```

### Key Points

- Client initiates the request.
- Server processes the request.
- Server returns a response.
- Foundation of web communication.

## Integrating JavaScript in HTML

## What is JavaScript Integration ?

JavaScript can be added to HTML pages to make them dynamic and interactive.

JavaScript works with:

- HTML → Structure
- CSS → Styling
- JavaScript → Functionality

There are two main ways to add JavaScript to HTML:

1. Internal JavaScript
2. External JavaScript

---

## Internal JavaScript

### What is Internal JavaScript ?

Internal JavaScript is written directly inside the HTML document using the `<script>` tag.

### Example

```html
<!DOCTYPE html>
<html>
<body>

<p id="result"></p>

<script>
    let x = 5;
    let y = 10;
    let result = x + y;

    document.getElementById("result").innerHTML =
    "The result is: " + result;
</script>

</body>
</html>
```

### How It Works

1. Variables `x` and `y` are created.
2. Their values are added.
3. The result is displayed inside the HTML element with id `result`.

### Advantages

- Easy for beginners.
- Useful for small projects.
- Everything is contained in one file.

### Disadvantages

- Makes HTML files larger.
- Difficult to maintain in large projects.

---

## External JavaScript

### What is External JavaScript ?

External JavaScript is stored in a separate `.js` file and linked to the HTML document.

### JavaScript File (script.js)

```javascript
let x = 5;
let y = 10;
let result = x + y;

document.getElementById("result").innerHTML =
"The result is: " + result;
```

### HTML File

```html
<!DOCTYPE html>
<html>
<body>

<p id="result"></p>

<script src="script.js"></script>

</body>
</html>
```

### How It Works

1. Browser loads the HTML page.
2. Browser finds the `src` attribute.
3. Browser loads `script.js`.
4. JavaScript executes and updates the page.

### Advantages

- Cleaner HTML code.
- Easier maintenance.
- Reusable across multiple pages.
- Preferred for large projects.

### Disadvantages

- Requires an additional file.
- External file must be accessible.

---

## Internal vs External JavaScript

| Feature | Internal JS | External JS |
|----------|------------|------------|
| Location | Inside HTML file | Separate `.js` file |
| Maintenance | Harder | Easier |
| Reusability | Low | High |
| Best For | Small projects | Large projects |

## Bypassing Control Flow Statements

## What is Control Flow ?

Control flow determines the order in which JavaScript code executes.

It allows programs to:

- Make decisions
- Repeat actions
- Execute different code paths based on conditions

### Common Control Flow Structures

- `if...else`
- `switch`
- `for`
- `while`
- `do...while`

## if...else Statement

### What is if...else ?

The `if...else` statement executes different code blocks depending on whether a condition is true or false.

### Syntax

```javascript
if (condition) {
    // runs if true
} else {
    // runs if false
}
```

### Example

```javascript
let age = 20;

if (age >= 18) {
    console.log("You are an adult.");
} else {
    console.log("You are a minor.");
}
```

### Output

```text
You are an adult.
```

---

```javascript
if (age >= 18) {

    "You are a minor.";
}
```

### How It Works

1. User enters their age.

3. If age is 18 or above → Adult.
4. Otherwise → Minor.

Input:

```text
20
```

## Client-Side Authentication Example

### Vulnerable Login Code

```javascript
let username = prompt("Enter your username:");
let password = prompt("Enter your password:");

if (username === "admin" &&
    password === "ComplexPassword") {

    document.write(
    "You are successfully authenticated!");
} else {
    document.write(
    "Authentication failed.");
}
```

### How It Works

The login succeeds only when:

```text
Username = admin
Password = ComplexPassword
```

Otherwise:

```text
Authentication failed
```

---

## Why Client-Side Authentication is Insecure

The entire JavaScript code is sent to the user's browser.

Anyone can:

- View the source code
- Read the login logic
- See hardcoded credentials
- Modify JavaScript behavior

### Example

Attacker views source code:

```javascript
if (username === "admin" &&
    password === "ComplexPassword")
```

The credentials are exposed directly.

---

## Security Issue

### Bad Practice

```javascript
if(username === "admin" &&
   password === "ComplexPassword")
```

Reason:

- Authentication happens in the browser.
- Users control the browser.
- JavaScript can be viewed and modified.

---

## Secure Approach

Authentication should always be performed on the server side.

### Secure Flow

```text
User enters credentials
        ↓
Browser sends request
        ↓
Server verifies credentials
        ↓
Server returns response
```

The browser should never contain:

- Real passwords
- Authentication logic
- Sensitive secrets

---

## Key Security Lesson

Never trust client-side JavaScript for security decisions.

Anything running in the browser can be:

- Viewed
- Modified
- Bypassed

Client-side validation improves user experience, but security checks must always be enforced on the server.

---

### Control Flow

Common structures:

## Exploring Minified and Obfuscated JavaScript

## What is JavaScript Minification ?

Minification is the process of reducing the size of JavaScript files by removing unnecessary characters such as:

- Spaces
- Line breaks
- Comments
- Extra formatting

This makes files smaller and improves webpage loading speed.

### Example

#### Original Code

```javascript
function hi() {
    alert("Welcome to THM");
}

hi();
```

#### Minified Code

```javascript
function hi(){alert("Welcome to THM")}hi();
```

### Benefits

- Smaller file size
- Faster page loading
- Reduced bandwidth usage

---

## What is JavaScript Obfuscation ?

Obfuscation is the process of making JavaScript difficult for humans to read and understand while keeping its functionality unchanged.

Common techniques include:

- Renaming variables
- Renaming functions
- Adding unnecessary code
- Converting readable code into complex expressions

### Example

<img width="1240" height="650" alt="image" src="https://github.com/user-attachments/assets/a58c4c1e-c46d-47f5-913f-45655dedf46b" />

## Minification vs Obfuscation

| Feature | Minification | Obfuscation |
|-----------|------------|------------|
| Reduces File Size | Yes | Sometimes |
| Improves Performance | Yes | No |
| Makes Code Harder to Read | Slightly | Significantly |
| Used for Protection | No | Yes |

---

## Why Developers Use Obfuscation ? 

- Protect source code logic
- Make reverse engineering harder
- Hide implementation details
- Increase difficulty for attackers analyzing code

### Important Note

Obfuscation does **not** provide real security.

Attackers can still:

- Read the code
- Analyze the logic
- Deobfuscate the script

To:

## Security Perspective

### Common Mistake

Some developers believe obfuscation protects sensitive information.

Example:

```javascript
const apiKey = "SECRET_KEY";
```

Even if obfuscated:

```javascript
var _0x1234="SECRET_KEY";
```

The browser still receives the code.

An attacker can eventually recover it.

### Rule

```text
Obfuscation hides code.
It does NOT secure code.
```

Sensitive data should never be stored in client-side JavaScript.

---

## Pentesting Notes

When analyzing JavaScript:

1. Check all loaded `.js` files.
2. Look for minified or obfuscated code.
3. Search for:
   - API keys
   - Hidden endpoints
   - Authentication logic
   - Sensitive information
4. Deobfuscate code when necessary.

## JavaScript Best Practices

## Why are Best Practices Important ?

Following JavaScript security best practices helps:

- Reduce attack surface
- Protect sensitive information
- Improve application security
- Prevent common vulnerabilities

---

## Avoid Relying on Client-Side Validation Only

### What is Client-Side Validation ?

Client-side validation uses JavaScript in the browser to check user input before sending it to the server.

### Example

```javascript
if(password.length < 8){
    alert("Password too short");
}
```

### Security Issue

Users can:

- Disable JavaScript
- Modify JavaScript code
- Bypass validation checks

### Best Practice

Always validate input on the server as well.

### Secure Approach

```text
Client Validation
        +
Server Validation
```

### Key Takeaway

```text
Never trust user input.
Always validate on the server.
```

---

## Use Only Trusted Libraries

### What are JavaScript Libraries ?

Libraries are pre-written JavaScript code that developers include to add functionality.

### Example

```html
<script src="library.js"></script>
```

### Security Risk

Attackers may publish malicious libraries with names similar to legitimate ones.

Example:

```text
jquery.js      ← Legitimate
jquerry.js     ← Malicious
```

### Best Practices

- Download libraries from trusted sources.
- Verify library authenticity.
- Keep libraries updated.
- Remove unused libraries.

### Key Takeaway

```text
Only use trusted and verified libraries.
```

---

## Avoid Hardcoded Secrets

### What are Hardcoded Secrets ?

Sensitive information directly written into JavaScript code.

### Bad Practice

```javascript
const privateAPIKey =
"pk_TryHackMe-1337";
```

### Why is it Dangerous?

Anyone can:

```text
View Source
Inspect Element
Developer Tools
```

And see the secret.

### Risks

- API key theft
- Account compromise
- Unauthorized access

### Best Practice

Store secrets on the server instead of client-side JavaScript.

### Key Takeaway

```text
Never store passwords, API keys,
or tokens in JavaScript files.
```

---

## Minify and Obfuscate JavaScript

### Minification

Removes unnecessary characters such as:

- Spaces
- Comments
- Line breaks

#### Example

Before:

```javascript
function hi() {
    alert("Hello");
}
```

After:

```javascript
function hi(){alert("Hello")}
```

### Benefits

- Smaller file size
- Faster loading

---

### Obfuscation

Makes code harder to read and understand.

#### Example

Before:

```javascript
function hi() {
    alert("Hello");
}
```

After:

```javascript
function _0x1234(){
alert("Hello");
}
```

### Benefits

- Hides application logic
- Slows reverse engineering efforts

### Limitation

```text
Obfuscation ≠ Security
```

Attackers can still deobfuscate code.

---

## Security Checklist

### Input Validation

✅ Validate on server side

❌ Rely only on JavaScript validation

---

### Libraries

✅ Use trusted libraries

❌ Include unknown third-party scripts

---

### Secrets

✅ Store secrets on the server

❌ Hardcode API keys or passwords

---

### Production Code

✅ Minify JavaScript

✅ Obfuscate JavaScript

❌ Deploy readable source code unnecessarily

---

## Summary

### JavaScript Security Best Practices

1. Do not rely solely on client-side validation.
2. Always perform server-side validation.
3. Use only trusted JavaScript libraries.
4. Never hardcode passwords, API keys, or tokens.
5. Minify JavaScript for better performance.
6. Obfuscate JavaScript to make analysis harder.
7. Remember that client-side code can always be viewed and modified.

### Key Security Principle

```text
Anything sent to the browser
should be considered visible
to the user and attacker.
```
