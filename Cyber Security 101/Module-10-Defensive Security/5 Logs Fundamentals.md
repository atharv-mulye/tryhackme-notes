# Logs Fundamentals

## What are Logs ?

Logs are digital records (footprints) of activities performed by users, applications, systems, or networks.

Every action whether normal or malicious can generate a log entry.

Logs help security teams understand:

- What happened?
- When did it happen?
- Who performed it?
- Where did it happen?
- How did it happen?

> **Logs = Digital footprints of system activities.**

---

## Why are Logs Important ?

Logs help security teams detect, investigate, and troubleshoot incidents.

## Common Use Cases

| Use Case | Purpose |
|----------|---------|
| **Security Monitoring** | Detect suspicious or malicious activities in real time. |
| **Incident Investigation & Digital Forensics** | Determine what happened and perform Root Cause Analysis (RCA). |
| **Troubleshooting** | Identify and fix system or application errors. |
| **Performance Monitoring** | Monitor application and system performance. |
| **Auditing & Compliance** | Maintain activity records for legal and compliance requirements. |

## Windows Event Logs Analysis

Windows records almost every activity that occurs in the operating system. These records are called Windows Event Logs and are stored in different log files based on the type of activity.

Windows Event Logs are important for:
- Troubleshooting system issues
- Detecting security incidents
- Monitoring system health
- Digital forensics
- Auditing user activities

---

## Main Windows Log Types

### 1. Application Log
Stores events generated by applications installed on Windows.

**Contains:**
- Application errors
- Warnings
- Compatibility issues
- Application crashes
- Updates

### 2. System Log
Stores events generated by the Windows operating system.

**Contains:**
- Driver loading
- Hardware events
- System startup/shutdown
- Windows services
- System errors

### 3. Security Log
The most important log for security investigations.

**Contains:**
- Successful logins
- Failed logins
- User account changes
- Password reset attempts
- Security policy changes
- Privilege changes

Besides these, Windows also maintains many application-specific logs for services like DNS, PowerShell, Windows Defender, Task Scheduler, etc.

## Web Server Access Logs Analysis

Whenever a user interacts with a website (opening a page, logging in, uploading a file, etc.), the web server records the request in an Access Log.

Access logs help administrators and security analysts:
- Monitor website traffic

For Apache web servers, the default access log is usually located at:

```bash

```

## Why Log Rotation ?

Large log files become difficult to manage.

Operating systems periodically **rotate logs**, meaning:

- Old logs are archived
- New log files are created

Benefits:
- Easier management
- Faster searching
- Better storage utilization

### What does "Old logs are archived" mean ?

It means that instead of deleting old log files, the system **saves them with a different name** and starts a new, empty log file.

#### Example

Initially:

```text
access.log
```

After log rotation:

```text
access.log      ← New log (currently receiving new requests)
access.log.1    ← Yesterday's log
access.log.2.gz ← Older compressed log
access.log.3.gz ← Even older compressed log
```

- **`access.log`** → Current log being written.
- **`access.log.1`** → Previous log.
- **`access.log.2.gz`** → Older compressed archived log.
- **`.gz`** → Compressed format used to save disk space.

#### Why archive logs ?

- Prevents one log file from becoming too large.
- Saves disk space by compressing older logs.
- Makes searching and analysis easier.
- Preserves historical logs for auditing, incident response, and digital forensics.

> **Simple definition:**  
> **Archiving old logs means moving old logs into separate (often compressed) files for long-term storage instead of deleting them.**

## Extra Concepts: Log Tampering, Admin Accounts & IP Spoofing

## 1. Can attackers delete logs to cover their tracks?

**Yes.** Attackers often try to hide their activities after compromising a system. This is known as **anti-forensics**.

### Common Anti-Forensics Techniques

- Delete or clear logs
- Modify (tamper with) logs
- Disable logging services
- Disable or uninstall Antivirus/EDR
- Delete command history
- Use fileless malware
- Use legitimate admin tools (Living-off-the-Land)
- Change file timestamps (Timestomping)
- Use VPNs, Tor, or proxies
- Delete temporary user accounts
- Flood logs with fake events

> **Note:** Simply deleting logs is often suspicious because security teams can detect that logs were cleared.

---

## 2. If an attacker gains Administrator access, will logs show "Administrator"?

**Yes.**

Windows records **which account performed an action**, not **who the actual human was**.

Example:

```text
Event ID: 4624
User: Administrator
Login: Successful
```

```text
User: Administrator
Action: Disabled Antivirus
```

```text
User: Administrator
Action: Created New User
```

The logs only show that the **Administrator account** performed these actions.

---

## 3. How do investigators know it was an attacker?

Investigators correlate multiple sources of evidence instead of trusting only the username.

They check:

- Login time
- Source IP
- Device used
- User's normal behavior
- VPN logs
- MFA logs
- EDR telemetry
- Firewall logs
- Network activity
- Malware evidence

### Example

Normal Admin:

- Logs in at 9:00 AM
- Office laptop
- Office IP

Attacker:

- Logs in at 2:00 AM
- Foreign IP
- Downloads 50 GB of data
- Creates new admin account
- Disables Defender

Although the logs say:

```text
User: Administrator
```

The surrounding evidence indicates the account was compromised.

---

## 4. What if the attacker also uses the admin's laptop?

This becomes harder to detect because:

- Correct username ✅
- Correct device ✅
- Possibly correct IP ✅

Investigators then rely on:

- User behavior analytics (UEBA)
- Command history
- Running processes
- Malware traces
- Memory forensics
- File access patterns
- Registry changes
- Network activity

## IP Spoofing

## What is IP Spoofing?

**IP Spoofing** is the technique of forging (faking) the source IP address in network packets.

Example:

Real IP:

```text
203.0.113.50
```

Spoofed IP:

```text
192.168.1.100
```

The packet falsely claims it came from `192.168.1.100`.

---

## Can attackers spoof their IP while logging into SSH, RDP, HTTPS, or VPN?

**No (generally).**

These protocols require **two-way communication**.

Example:

```text
Attacker  ----->  Server
      Login Request

Server  ----->  Sends Response

Attacker -----> Replies

Server -----> Authenticates
```

If the attacker spoofs the IP:

```text
Attacker -----> Server
(fake IP)

Server -----> Sends reply to fake IP
```

The attacker never receives the server's reply.

The connection fails.

---

## Where is IP Spoofing commonly used?

IP spoofing is mainly useful in attacks where **no response is required**, such as:

- DoS attacks
- DDoS attacks
- DNS Amplification
- NTP Amplification
- SSDP Amplification

---

## How do attackers actually hide their IP?

Instead of IP spoofing, attackers commonly use:

- VPN
- Tor
- Proxy servers
- Compromised servers (Jump Boxes)
- Botnets

Example attack path:

```text
Attacker
      ↓
VPN
      ↓
Compromised Server
      ↓
Tor Exit Node
      ↓
Victim
```

The victim usually sees only the **last visible IP**, not the attacker's real IP.

---

## Key Takeaways

- Logs record **which account** performed an action, not necessarily **who** performed it.
- Attackers often use **anti-forensics** to make investigations harder.
- Deleting logs is only one anti-forensics technique and can itself raise suspicion.
- Investigators correlate logs from multiple systems (SIEM, EDR, firewalls, VPNs, DNS, etc.) to uncover attacks.
- **IP spoofing is generally not useful for interactive logins** (SSH, RDP, HTTPS, VPN) because these protocols require two-way communication.
- Attackers typically hide behind **VPNs, Tor, proxies, or compromised intermediary systems**, rather than relying on IP spoofing.

## Can We Identify the Human Attacker?

## Short Answer

**Usually, NO.**

Logs generally **cannot identify the real human** behind an attack.

Instead, they help investigators understand **how the attack happened**.

---

## What Can We Usually Determine?

## 1. Entry Point (Initial Access) 

How did the attacker first get into the environment?

Examples:
- Phishing email
- Stolen credentials
- VPN compromise
- Exploited vulnerability
- Weak password
- Exposed RDP/SSH
- Infected USB device

---

## 2. Attack Timeline 

What happened and in what order?

Example:

```text
02:00 - Phishing email received
02:03 - Attachment opened
02:04 - Malware executed
02:05 - Reverse shell established
02:08 - Privilege escalation
02:12 - Administrator account compromised
02:20 - Data exfiltration
```

---

## 3. Attacker's Actions 

What did the attacker do?

Examples:
- Created new users
- Installed malware
- Disabled Antivirus/Defender
- Deleted backups
- Stole sensitive files
- Moved laterally
- Cleared logs

---

## 4. Affected Systems 

Which systems were compromised?

Examples:
- Employee workstation
- Domain Controller
- Database server
- File server

---

## 5. Data Accessed or Stolen 

Investigators can often determine:
- Which files were opened
- Which databases were accessed
- Which data was downloaded
- Amount of data transferred

---

## What Is Difficult to Determine?

Logs usually **cannot directly tell us:**

- Real human identity
- Physical location
- Nationality
- Real IP address (if hidden using VPN/Tor/Proxy)

Finding the real attacker often requires:
- ISP cooperation
- VPN provider logs
- Cloud provider logs
- Threat intelligence
- Law enforcement investigation

## Key Takeaway

> **Logs usually identify the account, device, IP address, and attack path—not the real human.**

Their primary purpose is to reconstruct the attack, identify the entry point, understand the attacker's actions, and help contain and recover from the incident.
