# SOC Fundamentals

## What is a SOC ?

A **Security Operations Center (SOC)** is a dedicated team and facility responsible for **continuously monitoring, detecting, analyzing, and responding** to cybersecurity threats within an organization.

- Operates **24×7**
- Protects an organization's networks, systems, endpoints, and data
- Detects suspicious activities before they cause damage

> **Primary Goal :** **Detect → Investigate → Respond**

---

## Why is a SOC Needed ?

Organizations store large amounts of sensitive data.

Threat actors continuously:
- Discover new vulnerabilities
- Exploit weak systems
- Steal sensitive information
- Deploy malware/ransomware

Traditional security measures alone are not enough.

A SOC provides:
- Continuous monitoring
- Faster threat detection
- Faster incident response
- Reduced business impact

---

## Detection

The SOC continuously looks for security issues.

### 1. Detect Vulnerabilities

A **vulnerability** is a weakness that attackers can exploit.

Example:
- Missing Windows security patches
- Outdated software
- Weak application configuration


### 2. Detect Unauthorized Activity

Detect users performing actions they shouldn't.

Example:
- Stolen employee credentials
- Login from another country
- Impossible travel
- Login at unusual times

### 3. Detect Policy Violations

Organizations define security policies.

SOC detects violations like:

- Downloading pirated software
- Using unauthorized USB drives
- Sending confidential files insecurely

### 4. Detect Intrusions

Identify attackers already inside the network.

Examples:

- Web server compromise
- Malware infection
- Privilege escalation
- Command & Control traffic

---

## Response

Once an attack is detected, SOC assists in:

- Containment
- Eradication
- Recovery
- Root Cause Analysis (RCA)

Goal :

```
Detect
   ↓
Contain
   ↓
Remove Threat
   ↓
Recover Systems
   ↓
Prevent Future Attack
```

# SOC Team Structure

## SOC Analyst Level 1 (L1)

First responder.

Responsibilities:

- Monitor alerts
- Perform alert triage
- Identify false positives
- Escalate real threats

Think of L1 as:

```
Security Alert
      │
      ▼
 SOC Analyst L1
```

---

## SOC Analyst Level 2 (L2)

Performs deeper investigations.

Responsibilities:

- Analyze complex alerts
- Correlate logs
- Investigate suspicious activity

---

## SOC Analyst Level 3 (L3)

Highly experienced analyst.

Responsibilities:

- Threat hunting
- Incident Response
- Malware analysis
- Containment
- Recovery

Handles high-severity incidents.

---

## Security Engineer

Responsible for security infrastructure.

Tasks:

- Deploy SIEM
- Configure EDR
- Manage Firewalls
- Maintain security tools

---

## Detection Engineer

Creates detection rules.

Example:

```
IF
User logs in from India

AND

5 minutes later logs in from USA

THEN

Generate Alert
```

---

## SOC Manager

Manages the SOC team.

Responsibilities:

- Team management
- Incident coordination
- Reporting
- Communicating with the CISO

# Alert Triage

The first activity after receiving an alert.

Goal:

Determine:

- Is it malicious?
- How severe is it?
- Who should handle it?

---

# The 5 Ws of Alert Triage

Every investigation answers:

| W | Meaning |
|----|----------|
| What | What happened? |
| When | When did it happen? |
| Where | Which system was affected? |
| Who | Which user/device was involved? |
| Why | Why did it happen? |

Example:

Alert:

```
Malware detected on GEORGE-PC
```

| Question | Answer |
|-----------|---------|
| What | Malware detected |
| When | 5 June 2024, 13:20 |
| Where | GEORGE-PC |
| Who | George |
| Why | Downloaded pirated software |

---

# Reporting

If an alert is confirmed malicious:

SOC creates a ticket.

A report should include:

- 5 Ws
- Timeline
- Severity
- Evidence (screenshots/logs)
- Recommendations

---

# Incident Response

For critical attacks:

SOC initiates Incident Response.

Typical steps:

```
Detection
      │
Containment
      │
Eradication
      │
Recovery
      │
Lessons Learned
```

---

# Digital Forensics

Performed after major incidents.

Purpose:

- Find root cause
- Recover evidence
- Understand attacker actions

Artifacts analyzed include:

- Logs
- Memory
- Disk
- Network traffic

# SIEM (Security Information and Event Management)

Most important SOC tool.

Functions:

- Collect logs
- Correlate events
- Generate alerts
- Centralized monitoring

Example:

```
Firewall Logs
Windows Logs
Linux Logs
VPN Logs
Cloud Logs
       │
       ▼
      SIEM
       │
       ▼
Security Alerts
```

**SIEM provides Detection only.**

Examples:

- Splunk
- Microsoft Sentinel
- IBM QRadar
- Elastic SIEM

---

# EDR (Endpoint Detection and Response)

Protects endpoints like:

- Laptops
- PCs
- Servers

Capabilities:

- Real-time monitoring
- Malware detection
- Process monitoring
- Automated response
- Isolation of infected devices

Example:

```
Laptop
    │
EDR Agent
    │
Detect Malware
    │
Isolate Device
```

Examples:

- Microsoft Defender for Endpoint
- CrowdStrike Falcon
- SentinelOne

---

# Firewall

Controls network traffic.

Purpose:

- Allow authorized traffic
- Block unauthorized traffic
- Detect suspicious connections

Example:

```
Internet
    │
 Firewall
    │
Company Network
```
