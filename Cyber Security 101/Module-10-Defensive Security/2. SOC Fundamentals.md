# SOC Fundamentals

## What is a SOC ?

A Security Operations Center (SOC) is a dedicated team and facility responsible for continuously monitoring, detecting, analyzing, and responding to cybersecurity threats within an organization.

- Operates 24×7
- Protects an organization's networks, systems, endpoints, and data
- Detects suspicious activities before they cause damage

> Primary Goal : Detect → Investigate → Respond

---

## Why is a SOC Needed ?

Organizations store large amounts of sensitive data.

Threat actors continuously:
- Discover new vulnerabilities
- Exploit weak systems
- Steal sensitive information
- Deploy malware/ransomware

Traditional security measures alone are not enough.

A SOC provides:
- Continuous monitoring
- Faster threat detection
- Faster incident response
- Reduced business impact

## Detection

The SOC continuously looks for security issues.

### 1. Detect Vulnerabilities

A vulnerability is a weakness that attackers can exploit.

Example:
- Missing Windows security patches
- Outdated software
- Weak application configuration


### 2. Detect Unauthorized Activity

Detect users performing actions they shouldn't.

Example:
- Stolen employee credentials
- Login from another country
- Impossible travel
- Login at unusual times

### 3. Detect Policy Violations

Organizations define security policies.

SOC detects violations like:

- Downloading pirated software
- Using unauthorized USB drives
- Sending confidential files insecurely

### 4. Detect Intrusions

Identify attackers already inside the network.

Examples:

- Web server compromise
- Malware infection
- Privilege escalation
- Command & Control traffic

### People

Technology helps detect threats, but people make the final decisions.

Security tools can generate thousands of alerts, many of which are false positives. Human analysts investigate these alerts, determine which ones are real threats, and decide the appropriate response.

#### Example

Imagine a city-wide fire alarm system.

- Every fire alarm is sent to one control center.
- Many alarms are triggered by cooking smoke instead of an actual fire.
- If firefighters responded to every alarm without verification, they would waste time and resources.

Similarly, in a SOC :

```
 Security Tools
      │
Thousands of Alerts
      │
      ▼
 SOC Analysts
      │
 Determine:
✔ Real Threat
✖ False Positive
      │
      ▼
Incident Response
```

Without people, security teams would spend time responding to harmless events instead of real attacks.

### Alert Outcomes in SOC

When a security tool generates (or does not generate) an alert, there are **four possible outcomes**.

| Term | Meaning | Example |
|------|---------|---------|
| **True Positive (TP)** | A real threat exists, and the security tool correctly detects it. | Antivirus detects actual malware. |
| **False Positive (FP)** | The security tool reports a threat, but there is no actual threat (false alarm). | Antivirus flags a safe file as malware. |
| **True Negative (TN)** | No threat exists, and the security tool correctly generates no alert. | Normal user login is ignored. |
| **False Negative (FN)** | A real threat exists, but the security tool fails to detect it. **(Most dangerous)** | Malware infects a system without being detected. |

#### SOC Analyst Level 1 (L1)

**Role :** First responder

**Responsibilities :**

- Monitor security alerts
- Perform initial alert triage
- Identify false positives
- Escalate genuine threats
- Create incident tickets and reports

#### SOC Analyst Level 2 (L2)

**Role :** Investigator

**Responsibilities :**

- Perform deeper investigations
- Correlate logs from multiple sources
- Confirm attacks
- Recommend remediation
- Support L1 analysts

#### SOC Analyst Level 3 (L3)

**Role :** Threat Hunter & Incident Responder

**Responsibilities :**

- Threat hunting
- Malware analysis
- Incident response
- Containment, eradication, and recovery
- Root cause analysis
- Mentor junior analysts

#### Security Engineer

**Role :** Deploy and maintain security infrastructure.

**Responsibilities :**

- Install and configure SIEM
- Deploy EDR
- Configure firewalls
- Maintain IDS/IPS
- Troubleshoot security tools

#### Detection Engineer

**Role :** Create and improve detection rules.

**Responsibilities :**

- Develop SIEM detection rules
- Reduce false positives
- Improve detection coverage
- Tune security alerts

Example:

```
IF user logs in from India
AND 5 minutes later logs in from USA
THEN Generate Alert
```

#### SOC Manager

**Role :** Manage daily SOC operations.

**Responsibilities :**

- Lead the SOC team
- Coordinate incident handling
- Review reports
- Define SOC processes
- Communicate with the CISO
- Ensure smooth SOC operations

#### CISO (Chief Information Security Officer)

**Role :** Highest-ranking cybersecurity executive.

**Responsibilities :**

- Define the organization's cybersecurity strategy
- Manage cyber risks and compliance
- Approve security policies and budgets
- Oversee the SOC and other security teams
- Report cybersecurity posture to senior management and the board

> **Difference :**  
> **SOC Manager** manages the **day-to-day operations** of the SOC, while the **CISO** is responsible for the **overall cybersecurity strategy and governance** of the organization.

## Process

A Process is a predefined set of steps the SOC team follows to consistently detect, investigate, report, and respond to security incidents.

### 1. Alert Triage

**Alert Triage** is the first step after an alert is generated.

#### Purpose
- Determine whether the alert is real or a false positive.
- Assess the severity.
- Prioritize the alert.
- Decide whether it should be escalated.

#### The 5 Ws of Alert Triage

| Question | Meaning | Example |
|----------|---------|---------|
| **What?** | What happened? | A malicious file was detected on one of the hosts inside the organization’s network |
| **When?** | When did it occur? | The file was detected at 13:20 on June 5, 2024 |
| **Where?** | Which system/device was affected? | The file was detected in the directory of the host: "GEORGE PC" |
| **Who?** | Which user or account was involved? | The file was detected for the user George |
| **Why?** | What caused the incident? | After the investigation, it was found that the file was downloaded from a pirated software-selling website. The investigation with the user revealed that they downloaded the file as they wanted to use a software for free |

> **Goal :** Understand the incident completely before taking action.

### 2. Reporting

Once an alert is confirmed as malicious, it must be reported and escalated.

#### Purpose
- Notify higher-level analysts.
- Create an incident ticket.
- Maintain documentation.
- Track incident progress.

#### A good report should include :
- 5 Ws
- Severity level
- Investigation findings
- Indicators of Compromise (IOCs)
- Screenshots/logs as evidence
- Recommended actions

### 3. Incident Response (IR)

If an alert is confirmed as a **security incident**, the Incident Response team takes over.

#### Goal
Contain the attack and restore normal operations.

#### Basic Incident Response Lifecycle

1. Detection
2. Analysis
3. Containment
4. Eradication
5. Recovery
6. Lessons Learned

**Example:**
- Malware detected
- Isolate infected computer
- Remove malware
- Restore files
- Document the incident

### 4. Digital Forensics

Digital Forensics is the process of collecting and analyzing digital evidence to determine:

- What happened?
- How it happened?
- When it happened?
- Who performed it?
- What was affected?

#### Purpose
- Find the root cause.
- Preserve evidence.
- Support legal investigations if required.
- Improve future defenses.

#### Evidence Sources
- System logs
- Event logs
- Memory dumps
- Disk images
- Browser history
- Network captures (PCAP)
- Emails

## Technology

Technology is the third pillar of a SOC. It refers to the security tools and solutions that help the SOC team detect, investigate, and respond to cyber threats.

Without these tools, analysts would have to manually monitor every device and application, which is time-consuming and inefficient.

### Why is Technology Important ?

An organization's network contains :

- Servers
- Computers
- Laptops
- Mobile devices
- Applications
- Databases
- Cloud services
- Network devices

Security tools collect information from all these systems into a **centralized location**, making monitoring and incident response much easier.

```text
Servers      PCs      Firewalls      Cloud
    │          │           │            │
    └──────────┴───────────┴────────────┘
                    │
                    ▼
          Security Solutions
                    │
                    ▼
              SOC Analysts
```

## Common SOC Technologies

### 1. SIEM (Security Information and Event Management)

**Purpose:** Centralized log collection and threat detection.

#### How it works

1. Collects logs from multiple devices (called **log sources**).
2. Correlates events from different sources.
3. Applies detection rules.
4. Generates alerts for suspicious activity.

```text
Firewall Logs
Windows Logs
Linux Logs
VPN Logs
Cloud Logs
      │
      ▼
     SIEM
      │
      ▼
 Security Alerts
```

#### Features

- Centralized log collection
- Event correlation
- Detection rules
- Threat intelligence
- User Behavior Analytics (UBA)
- Machine learning support (modern SIEMs)

> **Note:** SIEM mainly provides **Detection**, not automatic response.

#### Examples

- Splunk
- Microsoft Sentinel
- IBM QRadar
- Elastic SIEM

### 2. EDR (Endpoint Detection and Response)

**Purpose:** Detect and respond to threats on endpoints.

#### What are Endpoints ?

Any device connected to the network, such as:

- Laptop
- Desktop
- Server
- Workstation

#### Features

- Real-time monitoring
- Historical activity
- Malware detection
- Process monitoring
- File monitoring
- Automated response
- Device isolation
- Remote investigation

```text
Laptop
   │
EDR Agent
   │
Detect Malware
   │
Isolate Device
```

Unlike SIEM, **EDR provides both Detection and Response**.

#### Examples

- Microsoft Defender for Endpoint
- CrowdStrike Falcon
- SentinelOne

### 3. Firewall

**Purpose:** Protect the network perimeter.

A firewall acts as a **barrier** between trusted and untrusted networks.

```text
Internet
    │
 Firewall
    │
Company Network
```

#### Responsibilities

- Monitor network traffic
- Allow legitimate traffic
- Block unauthorized traffic
- Detect suspicious connections
- Enforce security policies

## Other SOC Technologies

### Antivirus (AV)

Detects, blocks, and removes malware.

Example:
- Windows Defender
- Avast
- Bitdefender

### EPP (Endpoint Protection Platform)

Protects endpoints using multiple security technologies.

Includes:

- Antivirus
- Firewall
- Device control
- Encryption
- Threat prevention

> Think of EPP as **preventive protection**.

### IDS (Intrusion Detection System)

Monitors network traffic and **detects** suspicious activity.

- Generates alerts
- Does **not** block attacks

> IDS = Detect only.

### IPS (Intrusion Prevention System)

Monitors network traffic and **automatically blocks** malicious activity.

> IPS = Detect + Prevent.

### XDR (Extended Detection and Response)

Combines data from multiple security sources.

Examples:

- Endpoints
- Email
- Cloud
- Identity
- Network

Provides better visibility than EDR.

> XDR = EDR + Multiple Security Sources.

### SOAR (Security Orchestration, Automation and Response)

Automates repetitive SOC tasks.

Examples:

- Open tickets automatically
- Block malicious IPs
- Isolate infected devices
- Notify analysts
- Run incident response playbooks

Purpose:

Reduce analyst workload and speed up incident response.
