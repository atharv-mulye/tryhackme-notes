# Incident Response Fundamentals

## What is Incident Response (IR) ?

Incident Response (IR) is the structured process of preparing for, detecting, responding to, and recovering from cybersecurity incidents.

Its goal is to:

- Minimize damage
- Contain the attack
- Recover systems
- Prevent similar incidents in the future

> **Incident Response manages a cyber incident from beginning to end.**

---

## Event → Alert → Incident

Every action performed on a computer generates an **event**.

These events are collected as **logs** by security solutions.

When suspicious activity is detected, a security tool generates an **alert**.

Security analysts investigate the alert.

- If harmless → **False Positive**
- If malicious → **True Positive (Incident)**

```text
User/System Activity
        │
        ▼
      Event
        │
        ▼
       Logs
        │
        ▼
Security Tool (SIEM/EDR)
        │
        ▼
      Alert
        │
        ▼
   Investigation
   │           │
   ▼           ▼
 False       True
Positive   Positive
(discard)      │
               ▼
            Incident
```

---

## Key Terms

### 1. Event

An **Event** is any action performed by a user, application, or system.

#### Examples

- User login
- File opened
- Process started
- USB connected

### 2. Log

A **Log** is a recorded event stored for monitoring and investigation.

### 3. Alert

An **Alert** is generated when a security solution detects suspicious activity.

Not every alert is malicious.

### 4. False Positive (FP)

An alert that **appears malicious but is actually harmless**.

#### Example

A backup uploads a large amount of data to cloud storage, triggering a data exfiltration alert.

> **False Positive = Safe activity flagged as malicious.**

### 5. True Positive (TP)

An alert that is **confirmed to be malicious**.

#### Example

A phishing email containing malware is detected.

> **True Positive = Real attack detected.**

### 6. Incident

An **Incident** is a confirmed **True Positive** that requires response.

Examples:

- Malware infection
- Data breach
- Phishing attack

## Incident Severity

Incidents are prioritized according to their impact.

| Severity | Priority | Description |
|----------|----------|-------------|
| **Critical** | Highest | Major business impact, immediate response required |
| **High** | High | Serious security issue |
| **Medium** | Moderate | Needs investigation and response |
| **Low** | Lowest | Minor impact |

> **Response Priority:** Critical → High → Medium → Low

## Types of Security Incidents

### 1. Malware Infection

Malicious software infects a system.

> Malware is a malicious program that can damage a system, network, or application. The majority of incidents are associated with malware infections. There are different types of malware, each with a unique potential to cause damage. Malware infections are mostly caused by files that can be text, documents, executables, etc.

#### Examples

- Virus
- Worm
- Trojan
- Ransomware
- Spyware

**Impact**

- File deletion
- Data theft
- Encryption
- System compromise

---

### 2. Security Breach

Unauthorized access to confidential systems or data.

>  Security Breaches arise when an unauthorized person gets access to confidential data (something we don’t want them to see or have). Security Breaches are of the utmost importance as many businesses rely on their confidential data, which must only be accessible to authorized personnel. 

#### Example

An attacker gains access to a company's customer database.

**Impact**

- Confidentiality compromised
- Unauthorized access

---

### 3. Data Leak

Sensitive information becomes exposed.

Can happen due to:

- Human error
- Misconfiguration
- Cyber attack

> Data leaks are incidents in which confidential information of an individual or an organization is exposed to unauthorized entities. Many attackers use data leaks for reputational damage to their victims or use this technique to threaten their victims and get what they need from them. Unlike Security Breaches, data leaks can also be unintentionally caused by human errors or misconfigurations.

#### Example

Employee uploads confidential documents to a public cloud folder.

---

### 4. Insider Attack

Attack performed by someone **inside the organization**.

### Examples

- Disgruntled employee
- Contractor
- Administrator

**Impact**

- Data theft
- Malware deployment
- Sabotage

>  Incidents from within an organization are known as insider attacks. Think about a disgruntled employee infecting the whole network through a USB on his last day. This is an example of an insider attack. Someone within your organization intentionally initiating an attack comes under this category. These attacks can be hazardous, as an insider always has greater access to resources than an outsider.

---

### 5. Denial of Service (DoS)

Attacker floods a system with fake requests until legitimate users cannot access it.

#### Goal

Reduce or completely stop service availability.

**Impact**

- Website unavailable
- Business disruption

> Availability is one of the three pillars of cyber security. Defensive security solutions and people constantly find ways to protect information; they ensure that the data is available to the people simultaneously. This is because there is no point in protecting something that is unavailable to us. Denial of Service attacks, or DoS attacks, are incidents where the attacker floods a system/network/application with false requests, eventually making it unavailable to legitimate users. This happens due to the exhaustion of resources available to entertain the requests.

## Incident Response Process

To respond to cybersecurity incidents effectively, organizations follow Incident Response (IR) Frameworks.

The two most widely used frameworks are :

- **SANS** – **SysAdmin, Audit, Network, and Security Institute**
- **NIST** – **National Institute of Standards and Technology**

Both frameworks provide a structured approach for handling security incidents.

---

## SANS Incident Response Framework (PICERL)

The SANS framework has **6 phases**.

**Memory Trick:** **PICERL**

- **P** → Preparation
- **I** → Identification
- **C** → Containment
- **E** → Eradication
- **R** → Recovery
- **L** → Lessons Learned

## 1. Preparation

Build everything needed **before** an incident occurs.

### Activities

- Create Incident Response Team
- Develop Incident Response Plan
- Deploy security tools
- Employee security awareness training
- Backup important systems

### Example

Train employees to recognize phishing emails.

---

## 2. Identification

Detect and confirm that an incident has occurred.

### Activities

- Monitor alerts
- Investigate suspicious activity
- Determine attack scope
- Confirm incident

### Example

SIEM detects large outbound data transfer caused by malware.

---

## 3. Containment

Prevent the attack from spreading.

### Activities

- Isolate infected systems
- Disable compromised accounts
- Block malicious IPs
- Disconnect affected devices

### Example

Disconnect the compromised computer from the network.

---

## 4. Eradication

Completely remove the threat.

### Activities

- Delete malware
- Remove malicious files
- Patch vulnerabilities
- Close attacker access

### Example

Run malware removal tools and install security patches.

---

## 5. Recovery

Restore affected systems to normal operation.

### Activities

- Restore backups
- Rebuild systems
- Verify systems are clean
- Return services to production

### Example

Restore deleted files from backup.

---

## 6. Lessons Learned

Review the incident to improve future security.

### Activities

- Root Cause Analysis (RCA)
- Document findings
- Improve security controls
- Update procedures
- Conduct post-incident review

### Example

Update phishing detection rules after a phishing attack.

---

## SANS Incident Response Summary

| Phase | Purpose | Example |
|--------|---------|---------|
| **Preparation** | Get ready before an attack | Security awareness training |
| **Identification** | Detect and confirm incident | SIEM detects malware |
| **Containment** | Stop the attack from spreading | Isolate infected PC |
| **Eradication** | Remove the threat | Delete malware |
| **Recovery** | Restore normal operations | Recover from backup |
| **Lessons Learned** | Improve future security | Update security policies |

## NIST Incident Response Framework

<img width="1000" height="500" alt="image" src="https://github.com/user-attachments/assets/72fe718e-2625-4a42-bef3-49675a8f638b" />

NIST simplifies Incident Response into **4 phases**.

| Phase | Description |
|--------|-------------|
| **Preparation** | Prepare people, processes, and technology |
| **Detection & Analysis** | Detect and investigate incidents |
| **Containment, Eradication & Recovery** | Stop attack, remove threat, restore systems |
| **Post-Incident Activity** | Review incident and improve security |

---

## SANS vs NIST

| SANS (6 Phases) | NIST (4 Phases) |
|-----------------|-----------------|
| Preparation | Preparation |
| Identification | Detection & Analysis |
| Containment | Containment, Eradication & Recovery |
| Eradication | Containment, Eradication & Recovery |
| Recovery | Containment, Eradication & Recovery |
| Lessons Learned | Post-Incident Activity |

> **NIST combines multiple SANS phases into fewer stages.**

## Incident Response Plan (IRP)

An **Incident Response Plan (IRP)** is a formal document that explains **how an organization responds to security incidents**.

It provides step-by-step procedures to follow **before, during, and after** an incident.

## Key Components of an Incident Response Plan

- Roles and responsibilities
- Incident response methodology
- Communication plan
- Escalation process
- Contact information
- Reporting procedures
- Recovery procedures

---

## Incident Response Techniques

During the Identification (SANS) or Detection & Analysis (NIST) phase, security teams use various tools to detect incidents quickly.

## Common Security Solutions

| Tool | Full Form | Purpose |
|------|-----------|---------|
| **SIEM** | Security Information and Event Management | Collects and correlates logs from multiple sources to detect incidents. |
| **AV** | Antivirus | Detects and removes known malware using signatures and regular scans. |
| **EDR** | Endpoint Detection and Response | Monitors endpoints, detects advanced threats, and can automatically contain and remove them. |

> **SIEM → Detects across the network**  
> **AV → Detects known malware**  
> **EDR → Detects + Responds on endpoints**

## Playbook

A **Playbook** is a **high-level set of guidelines** that describes how to respond to a specific type of security incident.

It answers:

- What should be done?
- Who should do it?
- In what order?

### Example : Phishing Email Playbook

1. Notify all the stakeholders of the phishing email incident
2. Determine if the email was malicious by conducting header and body analysis of the email
3. Look for any attachments with the email and analyze them
4. Determine if anybody opened the attachments
5. Isolate the infected systems from the network
6. Block the email sender

---

## Runbook

A **Runbook** is a **detailed, step-by-step procedure** used to perform a specific task in an incident.

It explains **exactly how** to perform each action.

### Example

**Playbook Step:** Isolate infected system

**Runbook:**

1. Open EDR console.
2. Search for the endpoint.
3. Select the device.
4. Click **Isolate Device**.
5. Verify network isolation.

---

## Playbook vs Runbook

| Playbook | Runbook |
|----------|---------|
| High-level guidance | Detailed execution steps |
| Describes **what to do** | Describes **how to do it** |
| Covers an entire incident | Covers a specific task |
| Flexible | Very detailed and repeatable |
