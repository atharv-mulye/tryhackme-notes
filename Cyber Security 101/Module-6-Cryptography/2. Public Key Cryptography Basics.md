# Public Key Cryptography Basics

## Introduction

Public Key Cryptography (Asymmetric Encryption) helps solve problems that symmetric encryption cannot easily handle, such as:

- Authentication
- Authenticity
- Integrity
- Secure Key Exchange

It uses two keys instead of one:

```text
Public Key  → Shared with everyone
Private Key → Kept secret
```

---

## Security Goals

When communicating online, we want four things :

| Goal | Meaning |
|---------|---------|
| Authentication | Verify who we are talking to |
| Authenticity | Verify message came from the claimed sender |
| Integrity | Ensure data wasn't modified |
| Confidentiality | Prevent unauthorized access |

---

## Real-World Example

Imagine discussing secret business plans at a coffee shop.

### Authentication

```text
You see the person directly.
```

You know who they are.

### Authenticity

```text
You know the words are coming from them.
```

Nobody else is pretending to speak for them.

### Integrity

```text
Nobody can change their words
before they reach you.
```

### Confidentiality

```text
Others cannot overhear
your conversation.
```

## Why Use Asymmetric Encryption?

Symmetric encryption is fast but has one major problem:

```text
How do we securely share the secret key ?
```

If someone intercepts the key:

```text
Security is lost.
```

Asymmetric cryptography solves this issue.

## RSA

RSA is one of the most popular public-key cryptography algorithms.

## What Makes RSA Secure ?

1. RSA relies on :

```text
Prime Number Factorization
```

2. Multiplication is easy.

Example:

```text
113 × 127 = 14351
```

3. Finding the original primes from :

```text
14351
```

is much harder.

---

4. For RSA :

```text
Huge Prime × Huge Prime
```

creates:

```text
Very Huge Number
```

Factoring that number becomes practically impossible.

---

## Server Authentication

When connecting to a server for the first time, SSH shows a warning like:

```terminal
root@TryHackMe# ssh 10.10.244.173
The authenticity of host '10.10.244.173 (10.10.244.173)' can't be established.
ED25519 key fingerprint is SHA256:lLzhZc7YzRBDchm02qTX0qsLqeeiTCJg5ipOT0E/YM8.

Are you sure you want to continue connecting (yes/no/[fingerprint])? yes
Warning: Permanently added '10.10.244.173' (ED25519) to the list of known hosts.
```
### Why Does This Happen ?

Your SSH client has never seen this server before.

It cannot verify:

```text
Is this the real server?
```

or

```text
Is someone pretending to be the server?
```

This protects against:

```text
Man-In-The-Middle (MITM) Attacks
```

## What is a Fingerprint ?

A fingerprint is a short unique identifier derived from the server's public key.

Example:

```text
SHA256:lLzhZc7YzRBDchm02qTX0qsLqeeiTCJg5ipOT0E/YM8
```

Think of it as:

```text
Server's digital identity card
```

---

## First Connection

If you trust the server:

```text
yes
```

SSH stores the fingerprint locally.

---

## Future Connections

SSH compares:

```text
Stored Fingerprint
```

with

```text
Current Fingerprint
```

If they match:

```text
Connection continues silently.
```

---

## If Fingerprint Changes

SSH will display a warning.

Possible reasons:

- Server reinstalled
- SSH keys regenerated
- MITM attack attempt

Always investigate unexpected changes.

## Generating SSH Keys

ssh-keygen is the program usually used to generate key pairs. It supports various algorithms, as shown on its manual page below.

```Terminal
root@TryHackMe# man ssh-keygen
[...]
-t dsa | ecdsa | ecdsa-sk | ed25519 | ed25519-sk | rsa
Specifies the type of key to create. The possible values are “dsa”, “ecdsa”, “ecdsa-sk”, “ed25519”, “ed25519-sk”, or “rsa”.
[...]
```
The following are some of the options available : 
- DSA (Digital Signature Algorithm) is a public-key cryptography algorithm specifically designed for digital signatures.
- ECDSA (Elliptic Curve Digital Signature Algorithm) is a variant of DSA that uses elliptic curve cryptography to provide smaller key sizes for equivalent security.
- ECDSA-SK (ECDSA with Security Key) is an extension of ECDSA. It incorporates hardware-based security keys for enhanced private key protection.
- Ed25519 is a public-key signature system using EdDSA (Edwards-curve Digital Signature Algorithm) with Curve25519.
- Ed25519-SK (Ed25519 with Security Key) is a variant of Ed25519. Similar to ECDSA-SK, it uses a hardware-based security key for improved private key protection.

Now let’s generate a key pair with the default options.
Generate an Ed25519 key:

```bash
ssh-keygen -t ed25519
```

## Digital Signatures and Certificates

In the physical world, we use signatures to:

- Approve documents
- Accept terms and conditions

- Opening a bank account

---

## What is a Digital Signature ?

A digital signature is a cryptographic method used to verify:

- Authenticity
- Integrity
- Ownership

It proves:
- Who created the file
- Whether the file was modified after signing.

---

| Goal | Purpose |
|--------|---------|

| Authenticity | Confirm the message came from the claimed sender |
| Integrity | Detect modifications |
| Non-Repudiation | Sender cannot deny signing it |

## Real-World Digital Signature Process

Encrypting an entire file would be slow.

Instead, Hash the file first

### Step 1


### Step 2

Generate Hash



### Step 4

## Verification

Receiver :

### Calculate Hash

```text
SHA256(received file)
```

### Decrypt Signature

Using sender's:

```text
Public Key
```

### Compare Both Hashes

If:

```text
Hash1 = Hash2
```

then :

✅ File is genuine

✅ File was not modified

```text

```

Benefits:

- Faster
- More efficient
- Easier verification

## PGP and GPG

Pretty Good Privacy (PGP) is a cryptographic system designed to secure data using encryption and digital signatures. It helps protect sensitive information from unauthorized access and ensures data integrity.

GnuPG (GPG) is a free and open-source implementation of the OpenPGP standard. It is commonly used for securing emails, encrypting files, and digitally signing data.

---

## Why GPG is Important ? 

GPG provides two primary security functions:

### Encryption

Encryption keeps data confidential. A sender encrypts a message using the recipient's public key, and only the recipient's private key can decrypt it.

### Digital Signatures

Digital signatures help verify:

- The sender's identity
- The integrity of the message

This ensures that the data has not been modified after it was sent.

---

## Generating a GPG Key Pair

A GPG key pair consists of:

- **Public Key** - Shared with others for encryption
- **Private Key** - Kept secret for decryption and signing

**Command :**
```bash
gpg --full-gen-key
```

During setup, GPG asks for:

1. Key type (RSA, ECC, etc.)
2. Key purpose (signing only or signing + encryption)
3. Cryptographic algorithm or curve
4. Expiration period
5. User information:
   - Name
   - Email address
   - Optional comment

- Usage: Sign and Encrypt
- Curve: Curve25519
- Expiration: No expiration

|------------|---------|
| pub | Public key information |
| ed25519 | Signing algorithm |
| SC | Sign and Certify permissions |
| uid | User identity attached to the key |
| sub | Encryption subkey |
| E | Encryption capability |

## Private Key Protection

Private keys can be protected with a passphrase, similar to SSH private keys.

Benefits of using a passphrase:

- Adds an extra layer of security
- Prevents unauthorized access if the key is stolen
- Protects encrypted communications

In Capture The Flag (CTF) challenges, passphrase-protected GPG keys can sometimes be attacked using:

```bash
gpg2john
john
```

The provided key in this example does not use a passphrase.

## Practical Example

### Sharing Your Public Key

To receive encrypted messages, share your public key with trusted contacts.

Anyone with your public key can encrypt messages for you, but only your private key can decrypt them.

---

### Importing a Backup Key

If you move to a new system, you can restore your existing key pair by importing a backup.

```bash
gpg --import backup.key
```

This allows you to continue accessing previously encrypted messages.

---

### Decrypting Messages

To decrypt an encrypted file:

```bash
gpg --decrypt confidential_message.gpg
```

GPG automatically uses the matching private key to recover the original content.

## Key Takeaways

- PGP is used for encryption and digital signatures.
- GPG is an open-source implementation of the OpenPGP standard.
- Public keys are shared; private keys must remain secret.
- Encryption protects confidentiality.
- Digital signatures provide authenticity and integrity.
- Private keys can be secured using passphrases.
- Keeping secure backups of GPG keys is essential.
- Importing keys and decrypting files are common real-world tasks.

## Conclusion 

- Cryptography is used to secure data and communication using encryption and other security techniques.
- Cryptanalysis is the process of finding weaknesses in cryptographic systems to break or bypass security.
- A brute-force attack tries every possible password or key until the correct one is found.
- A dictionary attack uses a list of common words and passwords instead of trying every combination.
- Public key cryptography uses two keys:
  - Public Key (shared with others)
  - Private Key (kept secret)
- Asymmetric encryption allows secure communication without sharing the private key.
- Key exchange methods help two parties establish a secure connection.
- Digital signatures verify the sender's identity and ensure data integrity.
- GPG/PGP can be used to encrypt files, decrypt messages, and create digital signatures.
- Strong passwords and proper key management are important for maintaining security.
