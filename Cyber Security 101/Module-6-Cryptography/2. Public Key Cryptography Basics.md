# Public Key Cryptography Basics

## Introduction

Public Key Cryptography (Asymmetric Encryption) helps solve problems that symmetric encryption cannot easily handle, such as:

- Authentication
- Authenticity
- Integrity
- Secure Key Exchange

It uses two keys instead of one:

```text
Public Key  → Shared with everyone
Private Key → Kept secret
```

---

## Security Goals

When communicating online, we want four things :

| Goal | Meaning |
|---------|---------|
| Authentication | Verify who we are talking to |
| Authenticity | Verify message came from the claimed sender |
| Integrity | Ensure data wasn't modified |
| Confidentiality | Prevent unauthorized access |

---

## Real-World Example

Imagine discussing secret business plans at a coffee shop.

### Authentication

```text
You see the person directly.
```

You know who they are.

### Authenticity

```text
You know the words are coming from them.
```

Nobody else is pretending to speak for them.

### Integrity

```text
Nobody can change their words
before they reach you.
```

### Confidentiality

```text
Others cannot overhear
your conversation.
```

## Cryptography's Role

|----------------|------------------|
| Confidentiality | Symmetric Encryption |
| Authentication | Asymmetric Encryption |
| Authenticity | Asymmetric Encryption |

## Why Use Asymmetric Encryption?

Symmetric encryption is fast but has one major problem:

```text
How do we securely share the secret key ?
```

If someone intercepts the key:

```text
Security is lost.
```

Asymmetric cryptography solves this issue.

## RSA

RSA is one of the most popular public-key cryptography algorithms.

## What Makes RSA Secure ?

1. RSA relies on :

```text
Prime Number Factorization
```

2. Multiplication is easy.

Example:

```text
113 × 127 = 14351
```

3. Finding the original primes from :

```text
14351
```

is much harder.

---

4. For RSA :

```text
Huge Prime × Huge Prime
```

creates:

```text
Very Huge Number
```

Factoring that number becomes practically impossible.

---

## Server Authentication

When connecting to a server for the first time, SSH shows a warning like:

```terminal
root@TryHackMe# ssh 10.10.244.173
The authenticity of host '10.10.244.173 (10.10.244.173)' can't be established.
ED25519 key fingerprint is SHA256:lLzhZc7YzRBDchm02qTX0qsLqeeiTCJg5ipOT0E/YM8.
This key is not known by any other name.
Are you sure you want to continue connecting (yes/no/[fingerprint])? yes
Warning: Permanently added '10.10.244.173' (ED25519) to the list of known hosts.
```
### Why Does This Happen ?

Your SSH client has never seen this server before.

It cannot verify:

```text
Is this the real server?
```

or

```text
Is someone pretending to be the server?
```

This protects against:

```text
Man-In-The-Middle (MITM) Attacks
```

---

## What is a Fingerprint ?

A fingerprint is a short unique identifier derived from the server's public key.

Example:

```text
SHA256:lLzhZc7YzRBDchm02qTX0qsLqeeiTCJg5ipOT0E/YM8
```

Think of it as:

```text
Server's digital identity card
```

---

## First Connection

If you trust the server:

```text
yes
```

SSH stores the fingerprint locally.

---

## Future Connections

SSH compares:

```text
Stored Fingerprint
```

with

```text
Current Fingerprint
```

If they match:

```text
Connection continues silently.
```

---

## If Fingerprint Changes

SSH will display a warning.

Possible reasons:

- Server reinstalled
- SSH keys regenerated
- MITM attack attempt

Always investigate unexpected changes.

## Generating SSH Keys

ssh-keygen is the program usually used to generate key pairs. It supports various algorithms, as shown on its manual page below.

```Terminal
root@TryHackMe# man ssh-keygen
[...]
-t dsa | ecdsa | ecdsa-sk | ed25519 | ed25519-sk | rsa
Specifies the type of key to create. The possible values are “dsa”, “ecdsa”, “ecdsa-sk”, “ed25519”, “ed25519-sk”, or “rsa”.
[...]
```
The following are some of the options available : 
- DSA (Digital Signature Algorithm) is a public-key cryptography algorithm specifically designed for digital signatures.
- ECDSA (Elliptic Curve Digital Signature Algorithm) is a variant of DSA that uses elliptic curve cryptography to provide smaller key sizes for equivalent security.
- ECDSA-SK (ECDSA with Security Key) is an extension of ECDSA. It incorporates hardware-based security keys for enhanced private key protection.
- Ed25519 is a public-key signature system using EdDSA (Edwards-curve Digital Signature Algorithm) with Curve25519.
- Ed25519-SK (Ed25519 with Security Key) is a variant of Ed25519. Similar to ECDSA-SK, it uses a hardware-based security key for improved private key protection.

Now let’s generate a key pair with the default options.
Generate an Ed25519 key:

```bash
ssh-keygen -t ed25519
```

## Passphrase Protection

Example:

```bash

```

```text

```

---

## Important Concept

The passphrase:

```text
DOES NOT authenticate you to the server
```

It only:

```text
Protects your private key locally
```

---

## Without Passphrase

If someone steals:

```text
id_ed25519
```

they may immediately access servers.

---

## With Passphrase

Attacker must:

1. Steal key
2. Crack passphrase

before using it.

---

## Cracking SSH Passphrases

Tools such as:

```text
John the Ripper
```

can attempt to crack weak passphrases.

Therefore use:

- Long passphrases
- Complex passphrases

## Digital Signatures and Certificates

In the physical world, we use signatures to:

- Approve documents
- Accept terms and conditions
- Authorize transactions
- Confirm ownership or receipt

Examples:

- Opening a bank account
- Signing contracts
- Registering at a library

In the digital world, handwritten signatures cannot provide real security.

Instead, we use Digital Signatures

---

## What is a Digital Signature ?

A digital signature is a cryptographic method used to verify:

- Authenticity
- Integrity
- Ownership

It proves:
- Who created the file
- Whether the file was modified after signing.

---

## Goals of Digital Signatures

| Goal | Purpose |
|--------|---------|
| Authentication | Verify the sender's identity |
| Authenticity | Confirm the message came from the claimed sender |
| Integrity | Detect modifications |
| Non-Repudiation | Sender cannot deny signing it |

---

## How Digital Signatures Work

Digital signatures use :

Private Key + Public Key

from asymmetric cryptography.

---

### Signing Process

The sender:

```text
Uses Private Key
```

to create a signature.

### Verification Process

The receiver:

```text
Uses Public Key
```

to verify the signature.

## Real-World Digital Signature Process

Encrypting an entire file would be slow.

Instead, Hash the file first

### Step 1

Original File

```text
report.pdf
```

### Step 2

Generate Hash

```text
SHA256(report.pdf)
```

Example:

```text
A1B2C3D4...
```

### Step 3

Encrypt Hash Using Private Key

Signature is created.

### Step 4

Send :

Original File + Digital Signature


---

## Verification

Receiver :

### Calculate Hash

```text
SHA256(received file)
```

### Decrypt Signature

Using sender's:

```text
Public Key
```

### Compare Both Hashes

If:

```text
Hash1 = Hash2
```

then :

✅ File is genuine

✅ File was not modified

# Why Use Hashes ?

Instead of signing:

```text
Entire 100MB file
```

we sign:

```text
Small fixed-size hash
```

Benefits:

- Faster
- More efficient
- Easier verification
