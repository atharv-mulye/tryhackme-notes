# John the Ripper : The Basics

## Introduction

John the Ripper (JtR) is one of the most popular password-cracking tools used in cybersecurity and penetration testing.

### Why John the Ripper is Popular ?

- Supports a wide variety of hash types
- Fast password-cracking capabilities
- Open-source and widely used by security professionals
- Supports dictionary attacks, brute-force attacks, and custom wordlists
- Available on Linux, Windows, and macOS

John is commonly used to recover passwords from password hashes during security assessments, CTFs, and forensic investigations.

---

## Basic Terms

Before using John the Ripper, it is important to understand a few key cryptography concepts.

## What are Hashes ?

A hash is a fixed-length representation of data created using a hashing algorithm.

### Characteristics

- Input can be any size
- Output has a fixed length
- Same input always produces the same hash
- Small changes in input create completely different hashes

### Example : MD5 Hashing

Input :

```text
polo
```

MD5 Output :

```text
b53759f3ce692de7aff1b5779d3964da
```

Input :

```text
polomints
```

MD5 Output :

```text
584b6e4f4586e136bc280f27f9c64f3b
```

Although the inputs are similar, the resulting hashes are completely different.

---

## Common Hashing Algorithms

| Algorithm | Description |
|------------|-------------|
| MD4 | Older hashing algorithm |
| MD5 | Fast but insecure |
| SHA1 | Deprecated due to collision attacks |
| SHA256 | Secure SHA-2 family algorithm |
| SHA512 | Stronger SHA-2 variant |
| NTLM | Common Windows password hash |

---

## What Makes Hashes Secure ?

Hash functions are designed as **one-way functions**.

### Easy Direction

```text
Input → Hash
```

Easy and fast to calculate.

### Hard Direction

```text
Hash → Original Input
```

Computationally difficult and often impractical.

Because of this property, hashes are commonly used for:

- Password storage
- Integrity verification
- Digital signatures
- Authentication systems

---

## Understanding P vs NP 

Hashing security is related to a well-known computer science concept called **P vs NP**.

### P (Polynomial Time)

Problems that can be solved efficiently.

Example:

```text
Sorting a list of numbers
```

As the list grows, processing time increases at a manageable rate.

---

### NP (Non-deterministic Polynomial Time)

Problems where:

- Verifying a solution is easy
- Finding the solution is difficult

Example:

```text
Finding the original password from a hash
```

Checking a password candidate is easy:

```text
Password → Hash → Compare
```

Finding the correct password without guessing is difficult.

---

## Where John the Ripper Comes In ?

Although hashes cannot be reversed directly, passwords can still be recovered through guessing attacks.

### Basic Idea

1. Take a password candidate.
2. Hash it using the same algorithm.
3. Compare the generated hash with the target hash.
4. Repeat until a match is found.

If a match is found:

```text
Generated Hash = Target Hash
```

The original password has been recovered.

## Dictionary Attacks

A dictionary attack uses a list of possible passwords.

Example wordlist:

```text
password
123456
letmein
admin
qwerty
```

John hashes each word and compares it against the target hash.

### Advantages

- Faster than brute force
- Effective against weak passwords
- Commonly uses wordlists such as:

```text
rockyou.txt
```

---

## Brute-Force Attacks

Instead of using a wordlist, John can try every possible password combination.

Example:

```text
a
aa
ab
ac
...
```

### Characteristics

- Slower than dictionary attacks
- More thorough
- Can eventually find complex passwords

---

## Why John the Ripper is Useful ?

John the Ripper helps security professionals:

- Audit password strength
- Test password policies
- Recover forgotten passwords
- Perform forensic investigations
- Complete CTF challenges

- John the Ripper is a powerful password-cracking tool.
- It supports many different hash formats.
- Hashes are one-way functions and cannot be directly reversed.
- Passwords are recovered through guessing attacks.
- Dictionary attacks use wordlists.
- Brute-force attacks try every possible combination.
- Common hash types include MD5, SHA1, SHA256, SHA512, and NTLM.

2. Select an appropriate wordlist.
3. Choose the correct John format (if required).

## Automatic Hash Cracking

John can often detect the hash type automatically.

### Syntax

```bash

```

### Example


### How It Works

- Reads passwords from the wordlist
- Automatically attempts to identify the hash type
- Hashes each password candidate
- Compares generated hashes with the target hash

### Advantages

- Fast and simple
- No need to manually identify the hash

### Disadvantages

- Automatic detection is not always accurate
- Some hash formats may be misidentified

## Cracking Windows Authentication Hashes

Windows stores user passwords as **NTHashes (NTLM hashes)** rather than plaintext passwords. If an attacker gains access to these hashes, they may attempt to crack them to recover the original passwords or use them directly in certain attacks.

John the Ripper can be used to crack NTLM hashes using dictionary attacks or brute-force attacks.

---

## What is NTHash (NTLM) ?

**NTHash** is the password hashing format used by modern Windows operating systems.

It is commonly called:

- NTLM Hash
- NTHash
- NT Password Hash

### Key Facts

- Used to store Windows user passwords
- Based on the MD4 hashing algorithm
- Stores hashes instead of plaintext passwords
- Found in Windows authentication databases

---

## Why is it Called NTLM ?

The name comes from:

```text
NT = New Technology
LM = LAN Manager
```

### Historical Background

- Older Windows systems used **LM (LAN Manager)** hashes.
- Newer systems introduced **NT hashes**.
- The term **NTLM** became commonly used to describe Windows authentication hashing.

Although LM hashes are largely obsolete today, the NTLM name remains widely used.

---

## Where Are NTLM Hashes Stored ?

Windows stores account information in the:

### SAM Database

**SAM (Security Account Manager)**

Contains:

- Usernames
- Password hashes
- Account information

---

## Obtaining NTLM Hashes

Attackers or penetration testers may extract NTLM hashes from:

### SAM Database

```text
C:\Windows\System32\config\SAM
```

### Active Directory Database

```text
NTDS.dit
```

Used in domain environments.

### Memory Dumping Tools

Example:

```text
Mimikatz
```

Can extract credentials and hashes from memory.

---

## Pass-the-Hash Attack

Sometimes the password does not need to be cracked.

Instead, attackers may use:

### Pass-the-Hash (PtH)

### Concept

Use the NTLM hash directly for authentication.

```text
Hash → Authentication
```

Instead of:

```text
Hash → Crack Password → Login
```

### Advantages

- Faster than password cracking
- No need to know the actual password
- Common in Windows environments

---

## When Should You Crack the Hash ?

Cracking is useful when:

- Password reuse is suspected
- Weak password policies exist
- The actual password is needed
- Further credential attacks are planned

Examples:

- VPN access
- Email access
- Password spraying
- Lateral movement

## Cracking `/etc/shadow` Hashes

On Linux systems, password hashes are stored in the:

```text
/etc/shadow
```

file.

This file contains:

- Password hashes
- Password aging information
- Password expiration settings
- Account-related security information

Since it contains sensitive data, it is normally readable only by the **root** user.

---

## What is `/etc/shadow` ?

The `/etc/shadow` file stores password hashes for local Linux accounts.

### Example Entry

```text
root:$6$2nwjN454g.dv4HN/$m9Z/r2xVfweYVkrr.v5Ft8Ws3/YYksfNwq96UL1FX0OJjY1L6l.DS3KEVsZ9rOVLB/ldTeEL/OIhJZ4GMFMGA0:18576::::::
```

### Structure

```text
username:hash:last_change:min:max:warn:inactive:expire
```

The most important fields for password cracking are:

| Field | Description |
|---------|-------------|
| Username | User account name |
| Hash | Stored password hash |

---

## Why is `/etc/passwd` Also Needed ?

John the Ripper cannot directly use `/etc/shadow` entries efficiently.

It expects account information from:

```text
/etc/passwd
```

and password hashes from:

```text
/etc/shadow
```

Therefore, both files must be combined first.

---

## What is `unshadow` ?

`unshadow` is a utility included with John the Ripper.

Its purpose is to:

- Merge `/etc/passwd` and `/etc/shadow`
- Produce a format John understands
- Prepare Linux password hashes for cracking

---

## Basic Syntax

```bash
unshadow <passwd_file> <shadow_file>
```

### Parameters

| Parameter | Description |
|------------|-------------|
| passwd_file | Copy of `/etc/passwd` |
| shadow_file | Copy of `/etc/shadow` |

---

## Example

### Files

#### local_passwd

```text
root:x:0:0::/root:/bin/bash
```

#### local_shadow

```text
root:$6$2nwjN454g.dv4HN/$m9Z/r2xVfweYVkrr.v5Ft8Ws3/YYksfNwq96UL1FX0OJjY1L6l.DS3KEVsZ9rOVLB/ldTeEL/OIhJZ4GMFMGA0:18576::::::
```

---

## Combine Them

```bash
unshadow local_passwd local_shadow > unshadowed.txt
```

### Result

```text
unshadowed.txt
```

contains data formatted specifically for John the Ripper.

---

## Cracking the Hash

Once the files are merged, use John to crack the password.

### Basic Command

```bash
john --wordlist=/usr/share/wordlists/rockyou.txt unshadowed.txt
```

John will:

1. Read the hash.
2. Detect the algorithm.
3. Test passwords from the wordlist.
4. Compare generated hashes against the target.

---

## Specifying the Format

Sometimes automatic detection fails.

In that case, manually specify the format.

### Example

```bash
john --wordlist=/usr/share/wordlists/rockyou.txt --format=sha512crypt unshadowed.txt
```

---

## Understanding `$6$`

Example hash:

```text
$6$2nwjN454g.dv4HN$...
```

The prefix identifies the algorithm.

| Prefix | Algorithm |
|----------|------------|
| `$1$` | md5crypt |
| `$2a$`, `$2b$`, `$2y$` | bcrypt |
| `$5$` | sha256crypt |
| `$6$` | sha512crypt |
| `$y$` | yescrypt |

Since the example begins with:

```text
$6$
```

John should use:

```bash
--format=sha512crypt
```

## Single Crack Mode

Single Crack Mode is a special mode in John the Ripper that attempts to crack passwords using information already known about the target user.

Instead of relying on large wordlists like `rockyou.txt`, John generates password candidates based on:

- Username
- User information
- GECOS fields
- Common password patterns

This mode is particularly effective against weak passwords that are derived from personal information.

---

## What is Word Mangling ?

Word mangling is the process of modifying known words to generate likely password candidates.

John applies predefined **mangling rules** to create multiple password variations.

---

## Example

Suppose the username is:

```text
Markus
```

John may generate passwords such as:

```text
Markus1
Markus2
Markus123
```

Different capitalization:

```text
MArkus
MARkus
MARKus
```

Special character variations:

```text
Markus!
Markus@
Markus$
Markus*
```

These modifications are called **word mangling**.

---

## Why Word Mangling Works ? 

Many users create weak passwords based on:

- Their username
- Their name
- Company names
- Common words
- Simple number additions

Examples:

```text
john123
admin123
mike2024
sarah!
```

Since these passwords follow predictable patterns, John can generate them automatically.

---

## What is GECOS ?

GECOS stands for:

```text
General Electric Comprehensive Operating System
```

In Unix/Linux systems, the GECOS field stores information about a user.

Examples include:

- Full name
- Office location
- Phone number
- Other user details

---

## GECOS Location

Example `/etc/passwd` entry:

```text
mike:x:1000:1000:Mike Smith:/home/mike:/bin/bash
```

Fields:

```text
username:password:uid:gid:GECOS:home:shell
```

The fifth field:

```text
Mike Smith
```

is the GECOS field.

---

## How John Uses GECOS

When cracking passwords, John can extract useful information such as:

```text
Mike
Smith
MikeSmith
mike
```

It then applies mangling rules:

```text
Mike123
Smith1
MikeSmith!
mike2024
```

This significantly increases the chance of finding weak passwords.

## Custom Rules

John the Ripper allows you to create **custom password mutation rules** to generate more realistic password candidates.

Instead of relying solely on a wordlist, John can modify words dynamically based on patterns you define.

This is useful when:

- You know how users create passwords.
- The target organization enforces password complexity.
- Users follow predictable password patterns.

---

## Why Use Custom Rules ?

Many organizations require passwords to contain:

- Lowercase letters
- Uppercase letters
- Numbers
- Symbols

For example, users might choose:

```text
polopassword
```

but due to complexity requirements, they change it to:

```text
Polopassword1!
```

Although this satisfies the policy, it follows a predictable pattern.

Attackers can exploit these patterns using custom rules.

---

## Common Password Patterns

Users often create passwords like:

```text
Password1!
Welcome123@
Admin2024#
Summer99$
```

Typical behavior :

| Modification | Example |
|-------------|----------|
| Capitalize first letter | Password |
| Add numbers at end | Password1 |
| Add symbols at end | Password1! |
| Add year | Password2024 |
| Add common symbols | Password@ |

These predictable habits make custom rules effective.

---

## Where Are Custom Rules Stored ?

Custom rules are stored inside:

```text
john.conf
```

Common locations :

### Linux Installations

```text
/etc/john/john.conf
```

### Linux (Built From Source)

```text
/opt/john/john.conf
```

### John Installation Directory

```text
run/john.conf
```

### Windows Installations

```text
C:\John\run\john.ini
```

or

```text
C:\Program Files\John\run\john.ini
```

---

## Finding the Configuration File

If you are unsure where the configuration file is located:

```bash
find / -name john.conf 2>/dev/null
```

or

```bash
locate john.conf
```

---

## Good Practice

Instead of modifying existing rules directly, create your own custom section:

```text
[List.Rules:MyCustomRule]
```

This makes rule management easier and helps avoid conflicts with built-in rules.

---

## Rule Structure

Every custom rule begins with:

```text
[List.Rules:RuleName]
```

Example:

```text
[List.Rules:PoloPassword]
```

This creates a rule named:

```text
PoloPassword
```

---

## Common Rule Modifiers

### 1. `c`

Capitalizes the first character.

Example:

```text
password
```

becomes:

```text
Password
```

### 2. `Az`

Appends characters to the end.

Example:

```text
Password
```

becomes:

```text
Password1
```

### 3. `A0`

Prepends characters to the beginning.

Example:

```text
Password
```

becomes:

```text
1Password
```

---

```text
[ ]
```

### Numbers



### Single Number

```text

```


### Uppercase and Lowercase

```text

```

Produces:


```text

```

Produces:

```text
A-Z
```

### Lowercase Only

```text
[a-z]
```

Produces:

```text
a-z
```

### Specific Character

```text
[a]
```

Produces:

```text
a
```

### Symbols

```text
[!£$%@]
```

Produces:

```text
!
£
$
%
@
```

## Example Rule

Target password pattern:

```text
Polopassword1!
```

Base word:

```text
polopassword
```

Rule:

```text
[List.Rules:PoloPassword]

cAz"[0-9][!£$%@]"
```

```text
polopassword
```


### `[0-9]`

Add one number.

Examples:

```text

Polopassword9
```

### `[!£$%@]`

Add one symbol.

Examples:

```text
Polopassword1!

```

## Using Custom Rules

After saving the rule in `john.conf`, use:

```bash
john --wordlist=<wordlist> --rule=PoloPassword <hashfile>
```

---

### Example

```bash
john --wordlist=/usr/share/wordlists/rockyou.txt \
--rule=PoloPassword \
hashes.txt
```

## Why Custom Rules Are Powerful ? 

Without rules:

```text
password
```

Only one candidate is tested.

With rules:

```text
Password1
Password2
Password1!
Password2024
Password@
Password99$
```

Thousands of realistic password variations can be generated automatically.

### Advantages

✅ More targeted than brute force

✅ Faster than testing every possible password

✅ Exploits common user behavior

✅ Works well against password complexity requirements

✅ Can be customized for specific organizations

## Custom Rule Modifiers

| Modifier | Purpose | Example Input | Output |
|-----------|-----------|--------------|---------|
| `c` | Capitalizes the first letter | `password` | `Password` |
| `Az` | Appends characters to the end | `password` + `1` | `password1` |
| `A0` | Prepends characters to the beginning | `password` + `1` | `1password` |

---

## Character Sets

| Character Set | Meaning | Example Values |
|--------------|---------|----------------|
| `[0-9]` | Any digit from 0 to 9 | `0,1,2...9` |
| `[0]` | Only the digit 0 | `0` |
| `[A-z]` | Uppercase and lowercase letters | `A-Z, a-z` |
| `[A-Z]` | Uppercase letters only | `A-Z` |
| `[a-z]` | Lowercase letters only | `a-z` |
| `[a]` | Only the character `a` | `a` |
| `[!£$%@]` | Common symbols | `!, £, $, %, @` |

---

## Example Rule

```text
[List.Rules:PoloPassword]

cAz"[0-9][!£$%@]"
```

### Rule Breakdown

| Component | Action |
|------------|---------|
| `c` | Capitalize first letter |
| `Az` | Append characters to the end |
| `[0-9]` | Add a number (0-9) |
| `[!£$%@]` | Add a symbol |

---

## Key Takeaways

- Custom rules allow John to generate password variations dynamically.
- Rules are stored in `john.conf`.
- Common modifiers:
  - `c` → Capitalize first letter
  - `Az` → Append characters
  - `A0` → Prepend characters
- Character sets define what gets added.
- Custom rules are useful when users follow predictable password patterns.
- Organizations enforcing complexity requirements often create passwords that are still predictable.
- Rules can dramatically improve cracking efficiency compared to using a plain wordlist.

> Custom Rules in John the Ripper allow attackers and penetration testers to generate realistic password candidates based on known user behavior. By applying transformations such as capitalization, adding numbers, and appending symbols, John can create thousands of password variations from a single wordlist entry. This approach is especially effective against passwords that meet complexity requirements but still follow predictable patterns like `Password1!` or `Welcome2024@`.

## Cracking Password-Protected ZIP Files

John the Ripper can crack passwords protecting ZIP archives.

Since John cannot directly process ZIP files, we first convert the ZIP file into a hash format that John understands using the **zip2john** utility.

---

## zip2john

`zip2john` extracts password hash information from a ZIP file and converts it into a format that can be used by John.

### Syntax

```bash
zip2john [options] <zip_file> > <output_file>
```

### Parameters

| Parameter | Description |
|------------|-------------|
| `zip2john` | Extracts ZIP password hashes |
| `[options]` | Optional ZIP checksum settings |
| `<zip_file>` | ZIP archive to extract the hash from |
| `>` | Redirects output to a file |
| `<output_file>` | Stores the extracted hash |

---

## Extract ZIP Hash

Example:

```bash
zip2john secret.zip > zip_hash.txt
```

This creates:

```text
zip_hash.txt
```

containing the ZIP password hash.

---

## Crack the ZIP Password

Once the hash is extracted, use John with a wordlist:

```bash
john --wordlist=/usr/share/wordlists/rockyou.txt zip_hash.txt
```

### Components

| Option | Purpose |
|----------|----------|
| `john` | Starts John the Ripper |
| `--wordlist` | Specifies the password list |
| `rockyou.txt` | Common password wordlist |
| `zip_hash.txt` | ZIP hash generated by zip2john |

---

## Workflow

### Step 1

Extract the ZIP hash:

```bash
zip2john secret.zip > zip_hash.txt
```

### Step 2

Run John against the extracted hash:

```bash
john --wordlist=/usr/share/wordlists/rockyou.txt zip_hash.txt
```

### Step 3

Wait for John to find the password.

### Step 4

Display cracked passwords:

```bash
john --show zip_hash.txt
```

## Cracking SSH Private Key Passwords

### Overview

SSH supports **key-based authentication**, allowing users to log in using a private key instead of a password.

The most common private key file is:

```text
id_rsa
```

To protect the private key from unauthorized use, it is often encrypted with a **passphrase**.

If you obtain a password-protected SSH private key during a security assessment or CTF, John the Ripper can attempt to recover the passphrase.

---

## What is an SSH Private Key ?

Common SSH key files:

| File | Purpose |
|---------|---------|
| `id_rsa` | RSA private key |
| `id_rsa.pub` | RSA public key |
| `id_ed25519` | Ed25519 private key |
| `id_ed25519.pub` | Ed25519 public key |

The private key must remain secret.

If it is protected with a passphrase, the correct passphrase is required before the key can be used.

---

## ssh2john

John cannot directly crack an SSH private key.

First, the key must be converted into a hash format using:

```text
ssh2john
```

or

```text
ssh2john.py
```

---

## Syntax

```bash
ssh2john <private_key> > <output_file>
```

### Parameters

| Parameter | Description |
|------------|-------------|
| `ssh2john` | Converts SSH private keys into John-compatible hashes |
| `<private_key>` | SSH private key file |
| `>` | Redirect output |
| `<output_file>` | Stores extracted hash |

---

## Extract SSH Key Hash

Example:

```bash
ssh2john id_rsa > id_rsa_hash.txt
```

Some systems use the Python version:

```bash
python3 /opt/john/ssh2john.py id_rsa > id_rsa_hash.txt
```

or

```bash
python3 /usr/share/john/ssh2john.py id_rsa > id_rsa_hash.txt
```

This creates:

```text
id_rsa_hash.txt
```

containing the SSH key hash.

---

## Crack the Passphrase

After extracting the hash:

```bash
john --wordlist=/usr/share/wordlists/rockyou.txt id_rsa_hash.txt
```

### Components

| Option | Purpose |
|----------|----------|
| `john` | Starts John the Ripper |
| `--wordlist` | Specifies password list |
| `rockyou.txt` | Common password wordlist |
| `id_rsa_hash.txt` | Hash extracted by ssh2john |

---

## Workflow

### Step 1

Obtain the SSH private key:

```text
id_rsa
```

### Step 2

Convert it to a John-compatible hash:

```bash
ssh2john id_rsa > id_rsa_hash.txt
```

### Step 3

Run John:

```bash
john --wordlist=/usr/share/wordlists/rockyou.txt id_rsa_hash.txt
```

### Step 4

Display the recovered passphrase:

```bash
john --show id_rsa_hash.txt
```

### Step 5

Use the key for SSH authentication:

```bash
ssh -i id_rsa user@target
```
