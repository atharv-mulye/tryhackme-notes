# John the Ripper : The Basics

## Introduction

John the Ripper (JtR) is one of the most popular password-cracking tools used in cybersecurity and penetration testing.

### Why John the Ripper is Popular ?

- Supports a wide variety of hash types
- Fast password-cracking capabilities
- Open-source and widely used by security professionals
- Supports dictionary attacks, brute-force attacks, and custom wordlists
- Available on Linux, Windows, and macOS

John is commonly used to recover passwords from password hashes during security assessments, CTFs, and forensic investigations.

---

## Basic Terms

Before using John the Ripper, it is important to understand a few key cryptography concepts.

## What are Hashes ?

A hash is a fixed-length representation of data created using a hashing algorithm.

### Characteristics

- Input can be any size
- Output has a fixed length
- Same input always produces the same hash
- Small changes in input create completely different hashes

### Example : MD5 Hashing

Input :

```text
polo
```

MD5 Output :

```text
b53759f3ce692de7aff1b5779d3964da
```

Input :

```text
polomints
```

MD5 Output :

```text
584b6e4f4586e136bc280f27f9c64f3b
```

Although the inputs are similar, the resulting hashes are completely different.

---

## Common Hashing Algorithms

| Algorithm | Description |
|------------|-------------|
| MD4 | Older hashing algorithm |
| MD5 | Fast but insecure |
| SHA1 | Deprecated due to collision attacks |
| SHA256 | Secure SHA-2 family algorithm |
| SHA512 | Stronger SHA-2 variant |
| NTLM | Common Windows password hash |

---

## What Makes Hashes Secure ?

Hash functions are designed as **one-way functions**.

### Easy Direction

```text
Input → Hash
```

Easy and fast to calculate.

### Hard Direction

```text
Hash → Original Input
```

Computationally difficult and often impractical.

Because of this property, hashes are commonly used for:

- Password storage
- Integrity verification
- Digital signatures
- Authentication systems

---

## Understanding P vs NP 

Hashing security is related to a well-known computer science concept called **P vs NP**.

### P (Polynomial Time)

Problems that can be solved efficiently.

Example:

```text
Sorting a list of numbers
```

As the list grows, processing time increases at a manageable rate.

---

### NP (Non-deterministic Polynomial Time)

Problems where:

- Verifying a solution is easy
- Finding the solution is difficult

Example:

```text
Finding the original password from a hash
```

Checking a password candidate is easy:

```text
Password → Hash → Compare
```

Finding the correct password without guessing is difficult.

---

## Where John the Ripper Comes In ?

Although hashes cannot be reversed directly, passwords can still be recovered through guessing attacks.

### Basic Idea

1. Take a password candidate.
2. Hash it using the same algorithm.
3. Compare the generated hash with the target hash.
4. Repeat until a match is found.

If a match is found:

```text
Generated Hash = Target Hash
```

The original password has been recovered.

---

## Dictionary Attacks

A dictionary attack uses a list of possible passwords.

Example wordlist:

```text
password
123456
letmein
admin
qwerty
```

John hashes each word and compares it against the target hash.

### Advantages

- Faster than brute force
- Effective against weak passwords
- Commonly uses wordlists such as:

```text
rockyou.txt
```

---

## Brute-Force Attacks

Instead of using a wordlist, John can try every possible password combination.

Example:

```text
a
aa
ab
ac
...
```

### Characteristics

- Slower than dictionary attacks
- More thorough
- Can eventually find complex passwords

---

## Why John the Ripper is Useful ?

John the Ripper helps security professionals:

- Audit password strength
- Test password policies
- Recover forgotten passwords
- Perform forensic investigations
- Complete CTF challenges

---

## Key Takeaways

- John the Ripper is a powerful password-cracking tool.
- It supports many different hash formats.
- Hashes are one-way functions and cannot be directly reversed.
- Passwords are recovered through guessing attacks.
- Dictionary attacks use wordlists.
- Brute-force attacks try every possible combination.
- Common hash types include MD5, SHA1, SHA256, SHA512, and NTLM.
- Understanding hashes is essential before using John effectively.

> John the Ripper is a versatile and widely used password-cracking tool that works by generating password guesses, hashing them, and comparing them to a target hash. While hashing algorithms are designed to be one-way functions, weak passwords can still be recovered using dictionary attacks, brute-force attacks, and custom cracking techniques. Understanding how hashes work is the foundation for using John the Ripper effectively.

## Cracking Basic Hashes

John the Ripper can crack password hashes using different methods. The most common approach is a **dictionary attack**, where John hashes words from a wordlist and compares them against the target hash.

Before cracking a hash, it is important to:

1. Identify the hash type.
2. Select an appropriate wordlist.
3. Choose the correct John format (if required).

## Basic John Syntax

General syntax:

```bash
john [options] [file]
```

### Components

| Component | Description |
|------------|-------------|
| `john` | Launches John the Ripper |
| `[options]` | Additional settings and attack modes |
| `[file]` | File containing the target hash |

## Automatic Hash Cracking

John can often detect the hash type automatically.

### Syntax

```bash
john --wordlist=<wordlist> <hash_file>
```

### Example

```bash
john --wordlist=/usr/share/wordlists/rockyou.txt hash.txt
```

### How It Works

- Reads passwords from the wordlist
- Automatically attempts to identify the hash type
- Hashes each password candidate
- Compares generated hashes with the target hash

### Advantages

- Fast and simple
- No need to manually identify the hash

### Disadvantages

- Automatic detection is not always accurate
- Some hash formats may be misidentified

Once the hash type is known, explicitly specify the format.

### Syntax

## Cracking Windows Authentication Hashes

Windows stores user passwords as **NTHashes (NTLM hashes)** rather than plaintext passwords. If an attacker gains access to these hashes, they may attempt to crack them to recover the original passwords or use them directly in certain attacks.

John the Ripper can be used to crack NTLM hashes using dictionary attacks or brute-force attacks.

---

## What is NTHash (NTLM) ?

**NTHash** is the password hashing format used by modern Windows operating systems.

It is commonly called:

- NTLM Hash
- NTHash
- NT Password Hash

### Key Facts

- Used to store Windows user passwords
- Based on the MD4 hashing algorithm
- Stores hashes instead of plaintext passwords
- Found in Windows authentication databases

---

## Why is it Called NTLM ?

The name comes from:

```text
NT = New Technology
LM = LAN Manager
```

### Historical Background

- Older Windows systems used **LM (LAN Manager)** hashes.
- Newer systems introduced **NT hashes**.
- The term **NTLM** became commonly used to describe Windows authentication hashing.

Although LM hashes are largely obsolete today, the NTLM name remains widely used.

---

## Where Are NTLM Hashes Stored ?

Windows stores account information in the:

### SAM Database

**SAM (Security Account Manager)**

Contains:

- Usernames
- Password hashes
- Account information

---

## Obtaining NTLM Hashes

Attackers or penetration testers may extract NTLM hashes from:

### SAM Database

```text
C:\Windows\System32\config\SAM
```

### Active Directory Database

```text
NTDS.dit
```

Used in domain environments.

### Memory Dumping Tools

Example:

```text
Mimikatz
```

Can extract credentials and hashes from memory.

---

## Pass-the-Hash Attack

Sometimes the password does not need to be cracked.

Instead, attackers may use:

### Pass-the-Hash (PtH)

### Concept

Use the NTLM hash directly for authentication.

```text
Hash → Authentication
```

Instead of:

```text
Hash → Crack Password → Login
```

### Advantages

- Faster than password cracking
- No need to know the actual password
- Common in Windows environments

---

## When Should You Crack the Hash ?

Cracking is useful when:

- Password reuse is suspected
- Weak password policies exist
- The actual password is needed
- Further credential attacks are planned

Examples:

- VPN access
- Email access
- Password spraying
- Lateral movement

## Cracking `/etc/shadow` Hashes

On Linux systems, password hashes are stored in the:

```text
/etc/shadow
```

file.

This file contains:

- Password hashes
- Password aging information
- Password expiration settings
- Account-related security information

Since it contains sensitive data, it is normally readable only by the **root** user.

---

## What is `/etc/shadow` ?

The `/etc/shadow` file stores password hashes for local Linux accounts.

### Example Entry

```text
root:$6$2nwjN454g.dv4HN/$m9Z/r2xVfweYVkrr.v5Ft8Ws3/YYksfNwq96UL1FX0OJjY1L6l.DS3KEVsZ9rOVLB/ldTeEL/OIhJZ4GMFMGA0:18576::::::
```

### Structure

```text
username:hash:last_change:min:max:warn:inactive:expire
```

The most important fields for password cracking are:

| Field | Description |
|---------|-------------|
| Username | User account name |
| Hash | Stored password hash |

---

## Why is `/etc/passwd` Also Needed ?

John the Ripper cannot directly use `/etc/shadow` entries efficiently.

It expects account information from:

```text
/etc/passwd
```

and password hashes from:

```text
/etc/shadow
```

Therefore, both files must be combined first.

---

## What is `unshadow` ?

`unshadow` is a utility included with John the Ripper.

Its purpose is to:

- Merge `/etc/passwd` and `/etc/shadow`
- Produce a format John understands
- Prepare Linux password hashes for cracking

---

## Basic Syntax

```bash
unshadow <passwd_file> <shadow_file>
```

### Parameters

| Parameter | Description |
|------------|-------------|
| passwd_file | Copy of `/etc/passwd` |
| shadow_file | Copy of `/etc/shadow` |

---

## Example

### Files

#### local_passwd

```text
root:x:0:0::/root:/bin/bash
```

#### local_shadow

```text
root:$6$2nwjN454g.dv4HN/$m9Z/r2xVfweYVkrr.v5Ft8Ws3/YYksfNwq96UL1FX0OJjY1L6l.DS3KEVsZ9rOVLB/ldTeEL/OIhJZ4GMFMGA0:18576::::::
```

---

## Combine Them

```bash
unshadow local_passwd local_shadow > unshadowed.txt
```

### Result

```text
unshadowed.txt
```

contains data formatted specifically for John the Ripper.

---

## Cracking the Hash

Once the files are merged, use John to crack the password.

### Basic Command

```bash
john --wordlist=/usr/share/wordlists/rockyou.txt unshadowed.txt
```

John will:

1. Read the hash.
2. Detect the algorithm.
3. Test passwords from the wordlist.
4. Compare generated hashes against the target.

---

## Specifying the Format

Sometimes automatic detection fails.

In that case, manually specify the format.

### Example

```bash
john --wordlist=/usr/share/wordlists/rockyou.txt --format=sha512crypt unshadowed.txt
```

---

## Understanding `$6$`

Example hash:

```text
$6$2nwjN454g.dv4HN$...
```

The prefix identifies the algorithm.

| Prefix | Algorithm |
|----------|------------|
| `$1$` | md5crypt |
| `$2a$`, `$2b$`, `$2y$` | bcrypt |
| `$5$` | sha256crypt |
| `$6$` | sha512crypt |
| `$y$` | yescrypt |

Since the example begins with:

```text
$6$
```

John should use:

```bash
--format=sha512crypt
```

## Complete Workflow

### Step 1 : Obtain Files

```text
/etc/passwd
/etc/shadow
```

### Step 2: Merge Files

```bash
unshadow passwd shadow > unshadowed.txt
```

### Step 3: Crack Passwords

```bash
john --wordlist=/usr/share/wordlists/rockyou.txt unshadowed.txt
```

or

```bash
john --wordlist=/usr/share/wordlists/rockyou.txt \
--format=sha512crypt \
unshadowed.txt
```

### Step 4: View Results

```bash
john --show unshadowed.txt
```

Displays recovered passwords.
Using --show: When you ran john --show, it displayed the cracked password in the format username:password_hash:last_change:min:max:warn:inactive:expire:reserved

#### Example

<img width="1706" height="485" alt="image" src="https://github.com/user-attachments/assets/ea10678a-4f87-417b-b77b-54144accb3c2" />

The output root:1234:18576:::::: is a representation of the cracked password for the root user in the format typically found in /etc/shadow. Here's what each part means :
- root: The username associated with the hash (in this case, the root user).
- 1234: The cracked password for the root user.
- 18576: This is the last password change date (in days since a certain epoch), indicating when the password was last updated. ( the 18576 is the last password change date, stored as the number of days since January 1, 1970 (the Unix epoch) )
- The remaining fields are placeholders that are usually used in the /etc/shadow format but are not filled in this case, indicating that there are no specific settings (like account expiration, minimum/maximum age, etc.) defined.

## Key Takeaways

- Linux stores password hashes in `/etc/shadow`.
- `/etc/shadow` is normally accessible only by root.
- John requires both `/etc/passwd` and `/etc/shadow`.
- The `unshadow` tool combines these files into a usable format.
- The resulting file can be cracked directly with John.
- Hash prefixes help identify the algorithm used.
- `$6$` indicates SHA-512 Crypt (`sha512crypt`).
- `rockyou.txt` is commonly used for dictionary attacks.

> Password hashes on Linux systems are stored in `/etc/shadow`, while account information is stored in `/etc/passwd`. Before cracking these hashes, John the Ripper requires both files to be merged using the `unshadow` utility. Once combined, John can perform dictionary attacks against the hashes using a wordlist such as `rockyou.txt`. Understanding hash prefixes like `$6$` helps determine the correct cracking format and improves the chances of successful password recovery.
