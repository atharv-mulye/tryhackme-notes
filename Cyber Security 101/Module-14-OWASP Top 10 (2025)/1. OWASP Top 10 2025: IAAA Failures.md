# OWASP Top 10 2025: IAAA Failures

## Introduction

The three OWASP Top 10 (2025) categories related to failures in **Identity, Authentication, Authorisation, and Accountability (IAAA).**

These security mechanisms control:
- Who a user is.
- How their identity is verified.
- What they are allowed to do.
- How their actions are recorded.

Weak implementations can allow attackers to access other users' data, gain unauthorized privileges, or hide their activities.

---

## What is IAAA ?

IAAA is a security model that describes how applications manage users and their actions.

The four components work in order, and each depends on the previous one.

### Identity

Identity uniquely represents a user or service.

Examples:
- Username
- Email address
- User ID

Identity answers:

> **Who are you?**

### Authentication

Authentication verifies that a user really owns the claimed identity.

Common authentication methods:

- Password
- OTP (One-Time Password)
- Passkey
- Biometric authentication

Authentication answers:

> **Can you prove who you are?**

### Authorisation

Authorisation determines what an authenticated user is allowed to access or perform.

Examples:
- Read files
- Edit profile
- Delete users
- Access admin panel

Authorisation answers:

> **What are you allowed to do?**

### Accountability

Accountability records user activities for monitoring and investigation.

Typical information recorded:

- User
- Action performed
- Time
- IP address
- Device

Accountability answers:

> **Who did what, when, and from where?**

---

## Relationship Between IAAA

The process follows this order:

```
  Identity
      ↓
Authentication
      ↓
Authorisation
      ↓
Accountability
```

Without identifying and authenticating a user, authorization and accountability cannot work correctly.

## A01: Broken Access Control

### Definition

Broken Access Control occurs when an application fails to properly restrict access to resources or actions.

The server should verify permissions **on every request**.

### Common Cause

The application trusts information sent by the client instead of validating permissions on the server.

### IDOR (Insecure Direct Object Reference)

IDOR is one of the most common access control vulnerabilities.

Example:

```
/profile?id=7
```

If changing the request to

```
/profile?id=6
```

displays another user's profile without permission, the application is vulnerable.

## Types of Privilege Escalation

### Horizontal Privilege Escalation

A user accesses another user with the same privilege level.

Example:
- Viewing another customer's orders.

### Vertical Privilege Escalation

A user gains higher privileges than intended.

Example:
- Normal user accessing admin-only pages.

## Prevention

- Perform server-side authorization checks.
- Never trust client-side validation.
- Verify permissions for every request.
- Use the principle of least privilege.

---

## A07: Authentication Failures

### Definition

Authentication Failures occur when an application cannot correctly verify a user's identity.

Attackers may log in as another user or bypass authentication.

## Common Authentication Weaknesses

### Username Enumeration

Different error messages reveal whether a username exists.

Example:

```
Username not found
```

vs

```
Incorrect password
```

This allows attackers to identify valid accounts.

### Weak Passwords

Poor password policies increase the chance of successful guessing attacks.

Examples:
- password123
- admin
- qwerty

### Missing Rate Limiting

Unlimited login attempts allow brute-force attacks.

Prevention:
- Rate limiting
- Temporary account lockout
- CAPTCHA

### Authentication Logic Flaws

Errors in login or registration logic can allow attackers to bypass authentication.

Examples:
- Session confusion
- Registration bugs
- Password reset flaws

### Insecure Session Management

Poor session handling allows attackers to hijack authenticated users.

Examples:
- Predictable session IDs
- Session fixation
- Unexpired sessions
- Insecure cookies

## Prevention

- Enforce strong passwords.
- Implement rate limiting.
- Use Multi-Factor Authentication (MFA).
- Rotate session IDs after login or privilege changes.
- Secure session cookies.
- Display generic login error messages.

## A09: Logging & Alerting Failures

### Definition

Logging & Alerting Failures occur when security events are not properly recorded or monitored.

Without logs, organizations cannot detect or investigate attacks.

## Why Logging is Important ? 

Logs help security teams:

- Detect attacks.
- Investigate incidents.
- Track malicious users.
- Meet compliance requirements.

## Important Events to Log

- Successful login
- Failed login
- Password changes
- Role changes
- Permission changes
- Admin actions
- Account lockouts
- Authentication failures

## Common Logging Failures

- Missing authentication logs
- Poor error messages
- No brute-force detection
- No alerts for suspicious activity
- Short log retention
- Logs stored where attackers can modify them

## Good Logging Practices

- Log all important security events.
- Store logs securely.
- Centralize logs.
- Protect logs from modification.
- Retain logs for future investigations.
- Generate alerts for suspicious behavior.

---

## Summary

| OWASP Category | Description | Main Risk |
|----------------|-------------|-----------|
| A01: Broken Access Control | Improper permission checks | Unauthorized access |
| A07: Authentication Failures | Weak identity verification | Account compromise |
| A09: Logging & Alerting Failures | Missing monitoring and logging | Undetected attacks |

---

## Key Takeaways

- **Identity** identifies a user.
- **Authentication** verifies the user's identity.
- **Authorisation** determines what the user can access.
- **Accountability** records user actions for auditing and investigation.
- Broken Access Control often leads to IDOR and privilege escalation.
- Authentication Failures commonly result from weak passwords, session flaws, and brute-force attacks.
- Proper logging and alerting are essential for detecting, investigating, and responding to security incidents.
- Always enforce server-side access control, secure authentication mechanisms, and comprehensive security logging.
