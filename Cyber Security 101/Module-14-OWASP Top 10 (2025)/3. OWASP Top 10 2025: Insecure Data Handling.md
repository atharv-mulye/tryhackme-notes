# OWASP Top 10 2025: Insecure Data Handling

## Introduction

Three OWASP Top 10 (2025) categories related to protecting sensitive data and securely handling user input.

Categories covered:

- **A04:** Cryptographic Failures
- **A05:** Injection
- **A08:** Software or Data Integrity Failures

---

## A04: Cryptographic Failures

### Definition

Cryptographic Failures occur when sensitive information is not properly protected through encryption, hashing, or secure key management.

Poor cryptographic implementation can expose confidential data to attackers.

## Common Causes

- Storing passwords without hashing
- Using weak or outdated algorithms (MD5, SHA-1, DES)
- Hardcoded encryption keys or secrets
- Weak key management
- Sending sensitive data without encryption
- Creating custom encryption algorithms ("rolling your own cryptography")

## Why It Matters ? 

Weak cryptography can lead to:

- Password theft
- Data breaches
- Account compromise
- Exposure of confidential information

## Prevention

- Use strong hashing algorithms like **bcrypt**, **scrypt**, or **Argon2** for passwords.
- Use trusted cryptographic libraries instead of creating custom algorithms.
- Protect encryption keys using secure key management systems.
- Never store secrets in source code or public repositories.
- Encrypt sensitive data both in transit and at rest.

## A05: Injection

### Definition

Injection occurs when an application processes untrusted user input as executable commands or queries.

Attackers can manipulate application behavior by supplying specially crafted input.

## Common Types of Injection

### SQL Injection (SQLi)

Malicious SQL commands are inserted into database queries.

### Command Injection

User input is executed as operating system commands.

### Server-Side Template Injection (SSTI)

User input is interpreted by a template engine, allowing code execution.

### AI Prompt Injection

Attackers manipulate prompts to influence AI model behavior or bypass restrictions.

## Why It Matters ? 

Injection attacks can allow attackers to:

- Access sensitive data
- Execute arbitrary commands
- Bypass authentication
- Modify or delete database records
- Take control of servers

## Prevention

- Treat all user input as untrusted.
- Use parameterized queries or prepared statements for databases.
- Avoid executing user input directly in system commands.
- Validate input type, length, and format.
- Sanitize and escape dangerous characters.
- Use secure APIs instead of shell commands whenever possible.

## A08: Software or Data Integrity Failures

### Definition

Software or Data Integrity Failures occur when applications trust software, updates, or data without verifying their authenticity or integrity.

Applications should always verify that code and data have not been modified.

## Common Causes

- Installing unverified software updates
- Trusting third-party code without validation
- Loading scripts from untrusted sources
- Accepting modified configuration files
- Missing integrity checks
- Weak CI/CD security

## Why It Matters ? 

Attackers can:

- Inject malicious code
- Distribute infected software updates
- Modify application behavior
- Compromise systems through trusted components

## Prevention

- Verify software updates before installation.
- Use cryptographic hashes and digital signatures.
- Only trust verified sources.
- Secure CI/CD pipelines.
- Protect important files from unauthorized modification.
- Validate configuration files, templates, binaries, and application data before use.

---

## Summary

| OWASP Category | Description | Main Risk |
|----------------|-------------|-----------|
| A04: Cryptographic Failures | Weak or incorrect use of cryptography | Sensitive data exposure |
| A05: Injection | Executing untrusted user input | Code execution and data compromise |
| A08: Software or Data Integrity Failures | Trusting unverified code or data | Supply chain and integrity attacks |

---

## Key Takeaways

- Always use modern cryptographic algorithms and secure key management.
- Never create your own encryption algorithms.
- Treat every user input as untrusted.
- Prevent injection attacks using parameterized queries, input validation, and secure APIs.
- Verify the integrity and authenticity of software, updates, and critical data before trusting them.
- Secure CI/CD pipelines and software supply chains to prevent integrity-related attacks.
