## Why Modify `/etc/resolv-dnsmasq` ?

### Purpose

This room uses **custom subdomains and virtual hosts (vhosts)** that only exist inside the TryHackMe lab environment.

Examples:

```text
blog.thm
admin.thm
shop.thm
```

Public DNS servers cannot resolve these names.

Add the lab DNS server:

```text
nameserver 10.49.138.228
```

This tells the AttackBox to use the lab's DNS server for hostname resolution.

> Now instead of our attackbox going to normal public DNS servers it will go to our target machine to be our DNS server

---

### Why It Is Needed ? 

Without this configuration:

- Subdomains cannot be resolved
- VHosts may not work
- Browser access may fail
- Gobuster DNS/VHost enumeration may not work correctly

---

### Why Restart `dnsmasq` ?

```bash
/etc/init.d/dnsmasq restart
```

`dnsmasq` is the local DNS resolver on the AttackBox.

Restarting it applies the new DNS configuration.

---

### DNS Resolution Flow

```text
User requests blog.thm
        ↓
AttackBox (dnsmasq)
        ↓
10.49.138.228 (Lab DNS Server)
        ↓
Returns correct IP
        ↓
Browser/Gobuster can access the site
```

---

### Key Note

This is **not a Gobuster requirement**.

It is a **DNS configuration step** required because the lab uses internal domains, subdomains, and virtual hosts that only the lab DNS server knows about.

## What is Gobuster ?

Gobuster is an open-source reconnaissance and enumeration tool written in Go (Golang).

It is commonly used during:
- Reconnaissance
- Enumeration
- Scanning
- Penetration Testing
- Bug Bounty Hunting

Gobuster uses **wordlists + brute force** to discover hidden resources.

Gobuster is included by default in distributions like Kali Linux. Let’s start by looking at Gobuster’s help page. This help page gives us a good overview of its functionalities and options.

Enter the following command : gobuster --help. You should get the help page for the Gobuster tool as shown below:

## Key Concepts

### Enumeration

Enumeration means discovering and listing resources that exist on a target.

Examples:
- Directories
- Files
- Subdomains
- Virtual Hosts (VHosts)
- Storage Buckets

Example:

```text
/admin
/login
/uploads
/images
```

### Brute Force

Brute force means trying every possibility until a match is found.

Gobuster:
1. Takes a wordlist
2. Tries each word
3. Checks whether the resource exists

Example wordlist:

```text
admin
login
images
uploads
```

Gobuster tests:

```text
http://target/admin
http://target/login
http://target/images
http://target/uploads
```

## Gobuster Dir Mode (Directory & File Enumeration)

### Purpose
- Enumerates hidden directories and files on a website.
- Uses a wordlist to brute-force possible paths.
- Helps discover admin panels, backups, APIs, uploads, configs, etc.
- Returns HTTP status codes to indicate accessible resources.

### Important Flags

| Flag | Long Flag | Description |
|--------|------------|-------------|
| -c | --cookies | Send cookies with requests (e.g., session ID). |
| -x | --extensions | Search for specific file extensions (.php, .js, etc.). |
| -H | --headers | Add custom headers to requests. |
| -k | --no-tls-validation | Ignore invalid/self-signed HTTPS certificates. |
| -n | --no-status | Hide status codes in output. |
| -P | --password | Password for authenticated requests. |
| -s | --status-codes | Show only specified status codes. |
| -b | --status-codes-blacklist | Hide specified status codes. |
| -U | --username | Username for authenticated requests. |
| -r | --followredirect | Follow HTTP redirects (301, 302). |

### Basic Syntax

```bash
gobuster dir -u "http://target.com" -w /path/to/wordlist
```

### Required Flags
- `dir` → Directory enumeration mode
- `-u` → Target URL
- `-w` → Wordlist

---

## Example 1 : Directory Enumeration

```bash
gobuster dir -u "http://www.example.thm" -w /usr/share/wordlists/dirbuster/directory-list-2.3-medium.txt -r
```

### What Happens ?
- Uses directory enumeration mode.
- Starts from `http://www.example.thm`.
- Tries every word in the wordlist.
- Follows redirects automatically.

---

## Example 2 : Search for PHP & JS Files

```bash
gobuster dir -u "http://www.example.thm" -w /usr/share/wordlists/dirbuster/directory-list-2.3-medium.txt -x .php,.js
```
>Meaning: Enumerates hidden directories and looks for .php and .js files on www.example.thm using the specified wordlist

### What Happens ?
Gobuster checks:

```text
http://www.example.thm/admin
http://www.example.thm/admin.php
http://www.example.thm/admin.js
```

for every word in the wordlist.

---

## URL Base Path Example

Suppose a website has:

```text
http://example.thm/
├── admin/
├── images/
├── resources/
│   ├── docs/
│   └── backups/
```

### Enumerating from Root

```bash
gobuster dir -u http://example.thm -w wordlist.txt
```

Gobuster checks:

```text
http://example.thm/admin
http://example.thm/images
http://example.thm/resources
```

### Enumerating Only `/resources`

```bash
gobuster dir -u http://example.thm/resources -w wordlist.txt
```

Gobuster now checks:

```text
http://example.thm/resources/docs
http://example.thm/resources/backups
```

instead of starting from the website root.

### Protocol is Required

✅ Correct:

```bash
gobuster dir -u http://example.thm -w wordlist.txt
```

❌ Wrong:

```bash
gobuster dir -u example.thm -w wordlist.txt
```

(No `http://` → scan fails)

### Hostname vs IP

Suppose:

```text
192.168.1.10
├── site1.com
└── site2.com
```

Using:

```bash
gobuster dir -u http://192.168.1.10
```

may scan the wrong website.

Better:

```bash
gobuster dir -u http://site1.com
```

### Not Recursive

If Gobuster finds:

```text
/admin
```

it does NOT automatically scan inside `/admin`.

You must run:

```bash
gobuster dir -u http://example.thm/admin -w wordlist.txt
```

to discover:

```text
/admin/login
/admin/users
/admin/config
```

---

## Important Notes

- URL must include protocol (`http://` or `https://`).
- Prefer hostname over IP when possible.
- One IP can host multiple websites (Virtual Hosting).
- Gobuster is **not recursive**.
  - If `/admin/` is found:
    ```bash
    gobuster dir -u "http://site.com/admin" -w wordlist.txt
    ```
- Status codes help identify valid resources:
  - `200` → Accessible
  - `301/302` → Redirect
  - `403` → Exists but forbidden
  - `404` → Not found

## Gobuster DNS Mode (Subdomain Enumeration)

### Purpose
- Discover hidden subdomains of a target domain.
- Useful because different subdomains may have different applications and vulnerabilities.
- Example:

```text
tryhackme.thm
├── www.tryhackme.thm
├── mobile.tryhackme.thm
└── api.tryhackme.thm
```

A vulnerability may exist on `mobile.tryhackme.thm` even if `tryhackme.thm` is secure.

### Common Flags

| Flag | Long Flag | Description |
|--------|------------|-------------|
| -d | --domain | This flag configures the domain you want to enumerate |
| -w | --wordlist | Wordlist containing subdomain names. |
| -i | --show-ips | Including this flag shows IP addresses that the domain and subdomains resolve to |
| -c | --show-cname | Show CNAME Records (cannot be used with the -i flag) |
| -r | --resolver | This flag configures a custom DNS server to use for resolving |

### Basic Syntax

```bash
gobuster dns -d example.thm -w wordlist.txt
```

### Required Flags
- `dns` → DNS enumeration mode
- `-d` → Target domain
- `-w` → Wordlist

### Example

```bash
gobuster dns -d example.thm -w /usr/share/wordlists/SecLists/Discovery/DNS/subdomains-top1million-5000.txt
```
> Meaning : Enumerates (discovers) subdomains of example.thm by trying each word from the wordlist as a possible subdomain (e.g., www.example.thm, blog.example.thm, shop.example.thm)

### How It Works ? 

Suppose the wordlist contains:

```text
www
shop
academy
api
```

Gobuster tries:

```text
www.example.thm
shop.example.thm
academy.example.thm
api.example.thm
```

and checks whether they exist.

## Gobuster VHOST Enumeration

### What is a Virtual Host (VHOST) ?
- Multiple websites hosted on the same server/IP.
- Server decides which website to show based on the **Host** header.

### Example
Same IP: `10.10.10.10`

- `www.example.thm` → Main website
- `blog.example.thm` → Blog website
- `shop.example.thm` → Shop website

All use the same IP but serve different content.

---

## DNS vs VHOST

| DNS Mode | VHOST Mode |
|-----------|-----------|
| Performs DNS lookups | Sends HTTP requests |
| Finds DNS subdomains | Finds hidden virtual hosts |
| Uses `-d` | Uses `-u` |
| Checks DNS records | Checks server responses |

### DNS Example

```bash
gobuster dns -d example.thm -w wordlist.txt
```

Checks:

- blog.example.thm
- shop.example.thm
- admin.example.thm

### VHOST Example

```bash
gobuster vhost -u http://10.10.10.10 -w wordlist.txt
```

Sends requests like:

```http
GET / HTTP/1.1
Host: blog.example.thm
```

```http
GET / HTTP/1.1
Host: shop.example.thm
```

## How VHOST Enumeration Works ?

Request:

```http
GET / HTTP/1.1
Host: www.example.thm
```

### Host Header Breakdown

| Part | Meaning |
|--------|---------|
| `www` | Wordlist entry |
| `example` | Second-level domain |
| `thm` | Top-level domain |

Gobuster changes the first part (`www`) using entries from the wordlist.

---

## Basic Syntax

```bash
gobuster vhost -u http://TARGET_IP -w wordlist.txt
```

## Common Flags

| Flag | Purpose |
|--------|---------|
| `-u` | Target URL/IP |
| `-w` | Wordlist |
| `--domain` | Domain to append |
| `--append-domain` | Adds domain to wordlist entries |
| `-r` | Follow redirects |
| `--exclude-length` | Filter false positives |
| `-m` | HTTP method |

---

## Example Command

```bash
gobuster vhost -u http://10.10.10.10 --domain example.thm -w subdomains-top1million-5000.txt --append-domain --exclude-length 250-320
```

> Meaning : Enumerates virtual hosts on 10.10.10.10 using a wordlist, appends .example.thm to each entry, and filters out likely false positives with response lengths between 250-320

### What Happens ?

1. Connects to `10.10.10.10`
2. Reads words from the wordlist
3. Creates:
   - blog.example.thm
   - shop.example.thm
   - admin.example.thm
4. Places them in the `Host` header
5. Sends requests
6. Reports valid virtual hosts

---

## Why Use `--append-domain` ?

Without it:

```text
Host: blog
Host: shop
Host: admin
```

❌ Invalid

With it:

```text
Host: blog.example.thm
Host: shop.example.thm
Host: admin.example.thm
```

✅ Valid

---

## Why Use `--exclude-length` ?

Many servers return the same error page for invalid hosts.

Example:

```text
test.example.thm   → 404 Size 279
abc.example.thm    → 404 Size 279
random.example.thm → 404 Size 279
```

These are false positives.

Using:

```bash
--exclude-length 279
```

removes them from the output.

## Gobuster Modes: Why They Matter

Gobuster helps discover **hidden attack surfaces** during reconnaissance and enumeration.

| Mode | Finds | Why Important |
|--------|--------|-------------|
| **DIR** | Hidden directories and files | Reveals admin panels, backups, APIs, configs, sensitive files |
| **DNS** | Subdomains | Finds forgotten or less secure subdomains |
| **VHOST** | Virtual hosts (hidden websites on same server) | Finds websites not visible through DNS |

---

## 1. DIR Enumeration

**Purpose:** Find hidden directories and files.

### Example

```text
example.com/admin
example.com/api
example.com/backup
```

### Why Important?

- Discover admin panels
- Find backup files
- Locate API endpoints
- Reveal sensitive resources

---

## 2. DNS Enumeration

**Purpose:** Find subdomains of a target domain.

### Example

```text
www.example.com
dev.example.com
shop.example.com
api.example.com
```

### Why Important?

- Finds forgotten services
- Finds development/test environments
- Different subdomains may have different security levels
- Expands attack surface

---

## 3. VHOST Enumeration

**Purpose:** Find hidden websites hosted on the same server/IP.

### Example

```text
www.example.com
blog.example.com
internal.example.com
```

All may exist on:

```text
10.10.10.10
```

### Why Important?

- Finds websites not listed in DNS
- Discovers hidden admin portals
- Reveals internal applications
- Uncovers additional attack surfaces
