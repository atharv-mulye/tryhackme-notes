# SQL Injection 

## Introduction

### What is a Database ?

A database is an organized collection of data that can be:
- Store data
- Retrieve data
- Modify data
- Delete data

It keeps information in a structured format, making data management fast and efficient.

---

## Why Do Websites Use Databases ?

Most websites need to store user or application data.

### Examples

- **Login Page**

  - Stores usernames and passwords.
  - Verifies credentials during login.

- **Shopping Website**

  - Stores products, prices, and stock.

- **Book Search**

  - Searches the database for matching books and displays the results.

Without a database, websites would have no way to remember users or store information.

---

## How a Website Communicates with a Database ? 

```
  User
   │
   ▼
Website (Login/Search Form)
   │
   ▼
SQL Query
   │
   ▼
DBMS (MySQL, PostgreSQL, etc.)
   │
   ▼
Database
   │
   ▼
Result Returned
   │
   ▼
Website Displays Result
```

### Example

**User enters:**

```
Username: admin
Password: password123
```

The website may generate an SQL query like:

```sql
SELECT * FROM users
WHERE username='admin'
AND password='password123';
```

The database checks whether such a user exists and returns the result.

---

## What is a DBMS ?

A DBMS (Database Management System) is software that manages databases.

It understands SQL (Structured Query Language) and executes SQL queries sent by applications.

### Common DBMS

| DBMS                 | Full Form                    |
| -------------------- | ---------------------------- |
| MySQL                | My Structured Query Language |
| PostgreSQL           | PostgreSQL                   |
| SQLite               | SQLite                       |
| Microsoft SQL Server | Microsoft SQL Server         |

---

## What is SQL ?

SQL (Structured Query Language) is the language used to communicate with databases.

It allows applications to:

- Retrieve data (`SELECT`)
- Insert data (`INSERT`)
- Update data (`UPDATE`)
- Delete data (`DELETE`)
- Create databases/tables (`CREATE`)
- Remove databases/tables (`DROP`)

> Its language builds the interaction between a website and its database
---

## Why Learn This ?

Applications communicate with databases using SQL queries.

If user input is not properly validated, an attacker may manipulate these SQL queries.

This vulnerability is called SQL Injection (SQLi), which tools like SQLMap automate for testing and exploitation.

---

## Key Takeaways

- **Database** → Stores application data.
- **Website** → Sends user input to the database.
- **DBMS** → Executes SQL queries.
- **SQL** → Language used to interact with databases.
- **SQL Injection (SQLi)** → Occurs when attackers manipulate SQL queries through user input.

## SQL Injection (SQLi) Vulnerability

## What is SQL Injection ?

SQL Injection (SQLi) is a web vulnerability that occurs when an application does not properly validate or sanitize user input before including it in an SQL query.

This allows an attacker to inject their own SQL code, causing the database to execute unintended commands.

---

## How Login Normally Works ? 

Suppose a user enters:

**Username:** `John`

**Password:** `Un@detectable444`

The application creates the SQL query:

```sql
SELECT * FROM users
WHERE username = 'John'
AND password = 'Un@detectable444';
```

### What happens ?

- Database checks if **both** username and password match.
- If both are correct → Login successful 
- Otherwise → Login fails 

Because `AND` requires **both conditions** to be true.

---

## Vulnerable Login Example

Suppose the application **does not sanitize user input**.

Attacker enters:

**Username**

```
John
```

**Password**

```
abc' OR 1=1;-- -
```

The SQL query becomes:

```sql
SELECT * FROM users
WHERE username = 'John'
AND password = 'abc'
OR 1=1;-- -';
```

---

## How the Attack Works ?

### Step 1

Original condition:

```sql
username='John'
AND
password='abc'
```

Password is incorrect 

---

### Step 2

Injected condition:

```sql
OR 1=1
```

Since

```sql
1 = 1
```

is **always TRUE**, the entire WHERE condition becomes TRUE.

---

### Step 3

The database returns a valid user record.

The attacker is logged in **without knowing the real password**.

---

## Why `'` (Single Quote) is Important ?

The single quote (`'`) closes the original password string.

Without it:

```
abc OR 1=1
```

would simply be treated as the password.

With it:

```sql
password='abc'
OR 1=1
```

the attacker successfully injects a new SQL condition.

---

## Why `-- -` is Used ? 

`--` starts an SQL comment.

Everything after it is ignored by the database.

Example:

```sql
password='abc'
OR 1=1;-- -'
```

becomes effectively:

```sql
password='abc'
OR 1=1
```

This prevents the remaining `'` from causing a syntax error.

---

## Why the Attack Works ?

The application directly inserts user input into an SQL query without validation or parameterization.

As a result, the database executes the attacker's injected SQL instead of treating it as plain text.

---

## Impact of SQL Injection

A successful SQL Injection attack may allow an attacker to:

- Bypass authentication
- Read sensitive data
- Modify database records
- Delete data
- Execute administrative operations
- In some cases, execute OS commands (depending on DBMS configuration)

---

## Quick Memory Trick

- **Normal User:** Input becomes **data**.
- **Attacker:** Input becomes **SQL code**.

SQL Injection happens when the database cannot distinguish between the two.

---

## Key Points

- SQL Injection occurs due to **improper input validation/sanitization**.
- Attackers inject SQL code into application inputs.
- `'` closes the original string.
- `OR 1=1` is always TRUE and bypasses conditions.
- `--` comments out the remaining query.
- SQL Injection can lead to complete database compromise.
