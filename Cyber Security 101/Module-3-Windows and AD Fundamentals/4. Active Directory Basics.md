# Active Directory Basics

## Introduction

Active Directory (AD) is a Microsoft service used to manage users, computers, and permissions in a Windows network from a central location.

Instead of setting up each computer separately, AD allows administrators to control everything from one place.

### Key Functions :
- Authentication : Verifies user identity 
- Authorization : Controls access to resources

> In simple terms : Active Directory knows who you are and what you can access.

---

## Why Active Directory is Needed ?

### Small Network Scenario

In a small setup (e.g, few users and computers) :
- User accounts are created on each machine
- Settings are configured manually
- Issues are handled individually

Easy to manage due to small size

### Large Network Scenario

In a large organization :
- Many users and computers exist
- Systems may be in different locations
- Managing each device manually becomes difficult

Problems :
- Time-consuming management  
- Inconsistent configurations  
- Difficult security enforcement

## Domain Controller (DC)

A Domain Controller is a server that runs Active Directory.

### Responsibilities :
- Authenticates users  
- Stores directory data  
- Applies security policies  

> Key Difference :  
> Active Directory = Service  
> Domain Controller = Server running that service

### 1. Centralized User Management
- Manage all users from one place  
- No need to create accounts on each computer  

### 2. Security Policy Management
- Apply rules across all systems

### 3. Scalability

## Active Directory

### Overview

Active Directory Domain Services (AD DS) is the core part of Active Directory.

It acts like a central database that stores information about all objects in a network.

### Common Objects in AD :
- Users  
- Groups  
- Computers (Machines)  
- Printers  
- Shared resources
- many others

> In simple terms : AD DS keeps track of everything inside the network.

---

## Users

Users are one of the most important objects in Active Directory.

They are known as security principals, which means :
- They can log in (authenticate)
- They can be given permissions to access resources

### Types of Users

#### 1. Human Users
- Represent real people (employees, students, etc.)
- Used to log into systems and access resources  

#### 2. Service Accounts
- Used by applications or services (e.g., web servers, databases)
- Not meant for human login  
- Have limited permissions only for their task  

---

## Machines (Computer Objects)

Every computer that joins a domain gets a machine account in Active Directory.

Machines are also security principals.

### Key Points :
- Each machine has its own account  
- Accounts have limited permissions  
- Used mainly by the system itself  

### Important Features :
- Passwords are automatically changed  
- Passwords are very long and complex (~120 characters)  
- Not meant for manual login  

### Naming Rule :
- Machine accounts end with `$`

**Example :**
- Computer Name : `DC01`  
- Machine Account : `DC01$`  

---

## Security Groups

Security Groups are used to manage permissions efficiently.

Instead of assigning permissions to each user, you assign them to a group.

### Benefits :
- Easier management  
- Saves time  
- Consistent access control  

### Features :
- Can contain users  
- Can contain machines  
- Can contain other groups  

> Security Groups are also security principals

---

## Default Security Groups

Some important built-in groups in a domain :

| Group Name          | Description |
|--------------------|------------|
| Domain Admins      | Full control over the domain / Users of this group have administrative privileges over the entire domain. By default, they can administer any computer on the domain, including the DCs. |
| Server Operators   | Manage Domain Controllers (limited) / Users in this group can administer Domain Controllers. They cannot change any administrative group memberships.|
| Backup Operators   | Can access all files for backup / Users in this group are allowed to access any file, ignoring their permissions. They are used to perform backups of data on computers. |
| Account Operators  | Can create/modify user accounts / Users in this group can create or modify other accounts in the domain.|
| Domain Users       | All users in the domain / Includes all existing user accounts in the domain.|
| Domain Computers   | All computers in the domain / Includes all existing computers in the domain. |
| Domain Controllers | All domain controllers / Includes all existing DCs on the domain. |

## Security Groups vs Organizational Units (OUs)

Both are used to organize objects, but they serve different purposes:

### Organizational Units (OUs)
- Used to apply policies
- A user can belong to only one OU  

### Security Groups
- Used to assign permissions
- A user can belong to multiple groups  

> Simple difference :
> - OUs : for management & policies  
> - Groups : for access & permissions  

---

## Key idea

- AD DS stores all network objects  
- Users and machines are security principals  
- Groups simplify permission management  
- OUs help organize and apply policies
- OUs control configuration
- Groups control access

## Updating Organizational Units (OUs)

### Deleting Unused OUs

Sometimes departments are removed, so their OUs must also be deleted.

### Problem :

<img width="350" height="150" alt="image" src="https://github.com/user-attachments/assets/bd0f53ee-51a3-46f8-b975-a2b426d6fe0e" />

You may get an error when trying to delete an OU

### Reason :
- OUs are protected from accidental deletion by default

### Solution :
1. Open ADUC
2. Go to View → Enable Advanced Features
3. Right-click the OU → Properties
4. Go to Object tab
5. Uncheck :
   - Protect object from accidental deletion
6. Try deleting the OU again

Note : Deleting an OU will also delete all users, groups, and sub-OUs inside it.

## Testing Delegation (Using PowerShell)

Since Phillip doesn’t have access to ADUC, he uses PowerShell.

### Reset User Password :
```
Set-ADAccountPassword sophie -Reset -NewPassword (Read-Host -AsSecureString -Prompt 'New Password') -Verbose
```

Since we wouldn't want Sophie to keep on using a password we know, we can also force a password reset at the next logon with the following command 


### Force Password Change at Next Login :
```
Set-ADUser -ChangePasswordAtLogon $true -Identity sophie -Verbose
```

## Managing Computers in Active Directory

By default, when a computer joins a domain, it is placed in the Computers container.

### Problem :
- All devices are stored in one place  
- No separation based on usage  
- Difficult to apply different policies  

---

## Why Organize Computers ?

Different types of machines need different security rules and configurations.

Example :
- A server should have stricter policies than a regular user PC  

---

## Common Computer Categories

### 1. Workstations
- Used by employees for daily tasks  
- Includes laptops and desktop PCs  
- Used for browsing, work, etc.  

> Should NOT have admin/privileged users logged in  

---

### 2. Servers
- Provide services (web, database, file sharing, etc.)  
- Used by users or other systems  

> Require stricter control and monitoring  

---

### 3. Domain Controllers
- Manage the entire domain  
- Store user credentials (hashed passwords)  
- Handle authentication  

> Most sensitive systems in the network  

---

## Best Practice : Use OUs for Organization

Instead of keeping everything in Computers, create separate OUs.

### Suggested Structure :

## Steps to Organize Computers

1. Open ADUC
2. Right-click domain (`thm.local`)  
3. Create new OUs :
   - Workstations
   - Servers

4. Go to Computers container  
5. Move devices :
   - Laptops & PCs → Workstations OU  
   - Servers → Servers OU 

---

## Why This Helps ? 

- Apply different policies to each group  
- Improve security  
- Better management and visibility  

---

## Example

| Device Type | OU |
|------------|----|
| User PC    | Workstations |
| Laptop     | Workstations |
| Web Server | Servers |
| File Server| Servers |

---

## Key Points 

- Default Computers container is not ideal for management  
- Devices should be grouped based on purpose  
- Use OUs like Workstations and Servers
- Makes policy management easier and more secure  

> Key Idea : Organize computers to apply the right policies to the right systems
