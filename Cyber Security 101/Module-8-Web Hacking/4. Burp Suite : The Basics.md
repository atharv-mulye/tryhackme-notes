# Burp Suite: The Basics

## What is Burp Suite ?
- Java-based web application penetration testing framework.
- Industry-standard tool for testing web apps, mobile apps, and APIs.
- Intercepts HTTP/HTTPS traffic between browser and server.
- Allows viewing, modifying, forwarding, and analyzing requests/responses.
- Essential for manual web security testing.

## Core Functionality
- Capture web traffic.
- Inspect requests and responses. 
- Modify data before it reaches the server.
- Test application security and behavior.
- Route traffic to different Burp modules.

## Burp Suite Editions

### Community Edition (Free)
- Free for non-commercial use.
- Includes core testing features.
- Suitable for learning and basic assessments.

### Professional Edition (Paid)
- Everything in Community Edition plus:
  - Automated vulnerability scanner.
  - Faster Intruder (fuzzing/brute-forcing).
  - Project saving and report generation.
  - Built-in API integration.
  - Full extension support.
  - Burp Collaborator access.

### Enterprise Edition (Paid)
- Designed for organizations.
- Automated continuous vulnerability scanning.
- Runs on a server.
- Regularly scans web applications for security issues.
- Similar to infrastructure scanners like Nessus.

## Why Burp Suite is Important ? 
- Intercepts and manipulates web traffic.
- Helps identify vulnerabilities.
- Supports both manual and automated testing.
- Widely used by penetration testers and security professionals.

---

## Burp Community Features

### Proxy
- Intercept and modify HTTP/HTTPS requests and responses.
- Core feature of Burp Suite.
- Analyze traffic between browser and server.

### Repeater
- Capture, edit, and resend requests.
- Useful for manual testing.
- Great for SQLi, XSS, and endpoint testing.

### Intruder
- Automates sending multiple requests.
- Used for brute-forcing and fuzzing.
- Rate-limited in Community Edition.

### Decoder
- Encode and decode data.
- Supports formats like URL, Base64, Hex, etc.
- Useful for payload preparation and analysis.

### Comparer
- Compare two pieces of data.
- Supports word-level and byte-level comparison.
- Helps identify differences quickly.

### Sequencer
- Tests randomness of tokens.
- Commonly used for session cookies.
- Detects weak token generation mechanisms.

### Extensions (Extender)
- Add extra functionality through plugins.
- Supports:
  - Java
  - Python (Jython)
  - Ruby (JRuby)

### BApp Store
- Marketplace for Burp extensions.
- Install third-party modules easily.
- Some extensions require Professional Edition.

### Example Extension
- **Logger++**
  - Enhanced logging functionality.
  - Better traffic analysis and tracking.

### Quick Memory Tip
- **P-R-I-D-C-S**
  - **P**roxy → Intercept traffic
  - **R**epeater → Resend requests
  - **I**ntruder → Fuzz/Bruteforce
  - **D**ecoder → Encode/Decode
  - **C**omparer → Compare data
  - **S**equencer → Test randomness

## Burp Suite Options

Before using modules like Proxy, Repeater, or Intruder, it's important to understand how Burp Suite settings work. Burp provides two main types of configuration settings:

### 1. Global Settings (User Settings)

These settings affect the entire Burp Suite installation.

#### Characteristics
- Applied every time Burp Suite starts.
- Remain unchanged across sessions.
- Used for configuring default behavior.
- Affect all projects opened in Burp.

#### Examples
- UI preferences
- Proxy listener defaults
- TLS settings
- Display options
- Keyboard shortcuts

#### Use Case
If you always want Burp to behave a certain way regardless of the project, configure it in **User Settings**.

---

### 2. Project Settings

These settings apply only to the current project/session.

#### Characteristics
- Specific to the current project.
- Override global settings when necessary.
- Lost when Burp Community Edition is closed.
- Useful for target-specific configurations.

#### Examples
- Scope definitions
- Proxy interception rules
- Session handling settings
- Target-specific configurations

#### Use Case
If you are testing a specific web application and need custom settings only for that engagement, use **Project Settings**.

## Connecting Burp Suite with Firefox (FoxyProxy)

FoxyProxy allows Firefox traffic to be routed through Burp Suite so requests can be intercepted and analyzed.

## Why FoxyProxy is Needed ? 

Burp Suite works as a proxy server that sits between the browser and the target website.

Without proxy configuration:

Browser → Website

Burp cannot see or intercept any traffic.

With FoxyProxy configured:

Browser → Burp Proxy (127.0.0.1:8080) → Website

Now Burp can:
- Intercept requests
- Modify requests
- Drop requests
- Forward requests
- Log traffic
- Send requests to other Burp tools

FoxyProxy is simply an easy way to tell the browser to send all traffic through Burp Suite.

### Alternative Methods

Instead of FoxyProxy, we can use:
- Manual browser proxy settings
- Burp's built-in browser (already configured)

The goal is always the same:
Browser traffic must pass through Burp before reaching the website.

### Real Pentesting

Yes, in real web application pentesting we usually configure a browser to use Burp Suite.

Typical workflow:

1. Start Burp Suite
2. Configure browser (FoxyProxy / Manual Proxy / Burp Browser)
3. Browse the target application
4. Intercept and analyze requests
5. Modify requests to test vulnerabilities
6. Send requests to Repeater, Intruder, Decoder, etc.

Most professional pentesters either:
- Use Burp's built-in browser, or
- Use Firefox + FoxyProxy

because they can quickly enable/disable the proxy during testing.

### Extra Point 

Burp alone ≠ Interception

Browser configured to use Burp = Interception works

Traffic must flow through Burp for Burp to inspect or modify it.

---

### Step 1 : Install FoxyProxy

1. Open Firefox.
2. Install **FoxyProxy Basic** extension.
3. FoxyProxy icon appears in the top-right toolbar.

### Step 2: Create Burp Proxy Configuration

<img width="840" height="477" alt="image" src="https://github.com/user-attachments/assets/d15f692e-4179-4eea-9451-a89dc407bb98" />

2. Select **Options**.
3. Click **Add** to create a new proxy profile.

#### Proxy Configuration

Fill in:

| Field | Value |
|---------|---------|
| Title | Burp |
| Proxy IP | 127.0.0.1 |
| Port | 8080 |

#### Explanation

```text
127.0.0.1 = Localhost (your machine)
8080      = Burp's default proxy port
```

Click **Save**.

### Step 3: Enable the Proxy

1. Click the FoxyProxy icon.
2. Select the **Burp** profile.

Firefox traffic will now be redirected to:

```text
127.0.0.1:8080
```

> Burp Suite must be running.

### Step 4: Enable Intercept in Burp

Open:

```text
Proxy → Intercept
```

Ensure:

```text
Intercept is ON
```

### Step 5: Test the Proxy

1. Open Firefox.
2. Visit a website.

## Scoping and Targeting

Scoping allows Burp Suite to focus only on specific targets and ignore unrelated traffic.

### Why Scoping is Important ?

Without scope:

- Burp captures traffic from every website.
- HTTP history becomes cluttered.
- Harder to find relevant requests.
- Wastes time during testing.

With scope:

- Burp focuses only on the target application.
- Cleaner logs and history.
- Easier analysis and testing.

## Steps to Trust Burp's CA Certificate

### 2. Open Firefox Certificate Settings

## Why is This Needed ?

### Normal HTTPS

```text
Browser <---- Encrypted ----> Website
```

The browser directly trusts the website's certificate.

### With Burp Proxy

```text
Browser <---- Encrypted ----> Burp
Burp    <---- Encrypted ----> Website
```

Burp acts as a **Man-in-the-Middle (MITM) Proxy**.

To inspect encrypted traffic, Burp generates certificates for websites on-the-fly.

Since the browser doesn't trust Burp's CA by default, certificate warnings appear until the CA certificate is installed and trusted.

## Example Attack – Bypassing Client-Side Validation with Burp

### Scenario

A support form validates the **Contact Email** field on the client side and blocks special characters.

```html
<script>alert("Successful XSS")</script>
```

The browser prevents this from being entered because it is not a valid email address.

Try typing: <script>alert("Succ3ssful XSS")</script>, into the "Contact Email" field. You should find that there is a client-side filter in place which prevents you from adding any special characters that aren't allowed in email addresses:

## Why Burp Works ? 

### Without Burp

```text
User Input
     ↓
Client-side Validation
     ↓
Blocked ❌
```

The request never reaches the server.

### With Burp

```text
User Input
     ↓
Client-side Validation
     ↓
Valid Request
     ↓
Burp Intercepts Request
     ↓
Modify Request
     ↓
Send to Server
```

Burp allows us to modify requests **after browser validation** but **before they reach the server**.

## Key Lesson

Client-side validation is **not security**.

Attackers can easily bypass browser restrictions using tools like Burp Suite and send modified requests directly to the server.

**Security must always be enforced on the server side.**
