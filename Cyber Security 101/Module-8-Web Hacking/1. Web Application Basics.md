# Web Application Basics

## What is a Web Application ?

A web application is software that runs on a web server and is accessed through a web browser.

Users interact with the visible parts of the application, while many processes work behind the scenes to provide functionality and store data.

---

## Main Components of a Web Application

A web application has two main parts:

1. Front End
2. Back End

---

## Front End

## What is the Front End ?

The Front End is the part of a web application that users can see and interact with in their browser.

It is mainly built using:

- HTML
- CSS
- JavaScript

---

## HTML (HyperText Markup Language)

### What is HTML ?

HTML provides the structure of a web page.

It tells the browser what content should be displayed.

### Examples of HTML Elements

- Headings
- Paragraphs
- Images
- Links
- Forms
- Buttons

### Key Points

- Creates the structure of a webpage.
- Forms the foundation of every website.
- Defines the content displayed to users.

---

## CSS (Cascading Style Sheets)

### What is CSS ?

CSS controls how a web page looks.

It is responsible for the design and layout of the website.

### CSS Can Control

- Colors
- Fonts
- Spacing
- Layouts
- Animations

### Key Points

- Improves appearance of web pages.
- Separates design from content.
- Makes websites visually appealing.

---

## JavaScript (JS)

### What is JavaScript ?

JavaScript adds functionality and interactivity to web pages.

It allows websites to react to user actions and update content dynamically.

### Common Uses

- Form validation
- Interactive menus
- Dynamic content updates
- Animations
- API requests

### Key Points

- Adds logic to web pages.
- Makes websites interactive.
- Runs in the user's browser.

---

## Back End

## What is the Back End ?

The Back End consists of components that users do not directly see.

It processes requests, stores data, and handles application logic.

---

## Database

### What is a Database ?

A database is used to store, modify, and retrieve information required by the application.

### Examples of Stored Data

- User accounts
- Passwords
- Preferences
- Product information
- Messages

### Key Points

- Stores application data.
- Allows data retrieval and updates.
- Used by most modern web applications.

---

## Infrastructure

### What is Infrastructure ?

Infrastructure includes the systems and services that support a web application.

### Examples

- Web Servers
- Application Servers
- Storage Systems
- Networking Devices
- Cloud Services

### Key Points

- Supports application functionality.
- Handles communication between components.
- Keeps the application running.

---

## Web Application Firewall (WAF)

### What is a WAF ?

A Web Application Firewall (WAF) is a security layer that filters incoming web traffic.

It helps protect web applications from malicious requests.

### Functions

- Blocks suspicious traffic
- Filters malicious requests
- Helps prevent common web attacks

### Key Points

- Improves web application security.
- Acts as a protective layer before requests reach the server.
- Commonly used in production environments.

---

## Key Points 

### Front End Components

- HTML → Structure
- CSS → Design
- JavaScript → Functionality

### Back End Components

- Database → Stores data
- Infrastructure → Supports application operation
- WAF → Provides security

---

## Uniform Resource Locator (URL)

### What is a URL ?

A Uniform Resource Locator (URL) is the address used to access resources on the Internet.

Resources can include:

- Web pages
- Images
- Videos
- Documents
- APIs

A URL tells the browser where a resource is located and how to access it.

### Example URL

```text
http://user:password@tryhackme.com:80/view-room?id=1#task3
```

---

## Structure of a URL

A URL is made up of multiple components, each serving a specific purpose.

<img width="824" height="208" alt="image" src="https://github.com/user-attachments/assets/1d49f0fe-693e-4f06-a810-3c998063a652" />

```text
scheme://user:password@host:port/path?query#fragment
```

---

## Scheme

### What is a Scheme ?

The scheme specifies the protocol used to communicate with the server.

### Common Schemes

```text
http
https
```

### Key Points

- HTTP = HyperText Transfer Protocol
- HTTPS = HyperText Transfer Protocol Secure
- HTTPS encrypts communication between client and server
- HTTPS is recommended for security

### Example

```text
https://tryhackme.com
```

Here, `https` is the scheme.

---

## User Information

### What is User Information ?

Some URLs may contain authentication information such as a username and password.

### Example

```text
http://user:password@example.com
```

### Key Points

- Used for authentication.
- Rarely used today.
- Considered insecure because credentials are exposed in the URL.

---

## Host / Domain

### What is a Host ?

The host (domain) identifies the website or server being accessed.

### Example

```text
https://tryhackme.com
```

`tryhackme.com` is the domain.

### Key Points

- Every domain must be unique.
- Registered through domain registrars.
- Used to identify websites.

### Security Note

Be aware of **typosquatting**, where attackers create domains that look similar to legitimate websites.

Example:

```text
tryhackme.com
tryhaclme.com
```

These fake domains are often used in phishing attacks.

---

## Port

### What is a Port ?

A port identifies a specific service running on a server.

It helps direct traffic to the correct application.

### Common Ports

| Port | Service |
|--------|---------|
| 80 | HTTP |
| 443 | HTTPS |

### Example

```text
https://example.com:443
```

Here, `443` is the port number.

### Key Points

- Port range: 1–65535
- Different services use different ports
- Usually hidden because browsers use default ports automatically

---

## Path

### What is a Path ?

The path specifies the exact resource or page on the server.

### Example

```text
https://tryhackme.com/view-room
```

`/view-room` is the path.

### Key Points

- Points to a specific location on the server.
- Can reference pages, files, or directories.
- Sensitive paths should be properly protected.

---

## Query String

### What is a Query String ?

A query string sends additional information to the server.

It begins with a question mark (`?`).

### Example

```text
https://example.com/search?q=cybersecurity
```

Query parameter:

```text
q=cybersecurity
```

### Multiple Parameters

```text
https://example.com/page?id=1&user=admin
```

Parameters:

```text
id=1
user=admin
```

### Key Points

- Starts with `?`
- Multiple parameters are separated by `&`
- Commonly used in searches and forms
- User-controlled input should always be validated

### Security Note

Improper handling of query strings can lead to injection attacks.

---

## Fragment

### What is a Fragment ?

A fragment points to a specific section of a webpage.

It begins with a hash symbol (`#`).

### Example

```text
https://example.com/page#section1
```

`section1` is the fragment.

### Key Points

- Used for navigation within a page.
- Does not usually get sent to the server.
- Commonly used for headings and page sections.

### Security Note

Fragment data should also be validated if processed by client-side scripts.

---

## Complete URL Example

```text
http://user:password@tryhackme.com:80/view-room?id=1#task3
```

| Component | Value |
|------------|---------|
| Scheme | http |
| User | user |
| Password | password |
| Host | tryhackme.com |
| Port | 80 |
| Path | /view-room |
| Query String | id=1 |
| Fragment | task3 |

---

## Key Points 

### URL Components

- Scheme → Protocol used for communication
- User Info → Authentication details
- Host/Domain → Website address
- Port → Service identifier
- Path → Specific resource location
- Query String → Additional parameters
- Fragment → Specific section of a page

---

## HTTP Messages

### What are HTTP Messages ?

HTTP messages are packets of data exchanged between a client (user/browser) and a web server.

They are used to send requests and receive responses, allowing web applications to function.

### Example Flow

```text
Client (Browser) ---- HTTP Request ----> Server

Client (Browser) <--- HTTP Response ---- Server
```

---

## Types of HTTP Messages

There are two types of HTTP messages:

<img width="1536" height="318" alt="image" src="https://github.com/user-attachments/assets/1143b7e9-9b1f-41d8-b1b1-6d745ace5213" />

### HTTP Request

Sent by the client to the server to perform an action or request a resource.

Examples:

- Open a webpage
- Submit a login form
- Search for information
- Upload a file

### HTTP Response

Sent by the server back to the client after processing a request.

Examples:

- Returning a webpage
- Returning API data
- Showing an error message
- Confirming a successful login

---

## Structure of an HTTP Message

Both HTTP requests and responses follow a similar structure:

```text
Start Line
Headers
Empty Line
Body
```

---

## Start Line

### What is the Start Line ?

The start line is the first line of an HTTP message.

It tells whether the message is a request or a response and provides important information about it.

### Request Example

```http
GET /index.html HTTP/1.1
```

Components:

- GET → HTTP Method
- /index.html → Resource Path
- HTTP/1.1 → HTTP Version

### Response Example

```http
HTTP/1.1 200 OK
```

Components:

- HTTP/1.1 → HTTP Version
- 200 → Status Code
- OK → Status Message

### Key Points

- First line of every HTTP message.
- Identifies the message type.
- Contains important request or response details.

---

## Headers

### What are Headers ?

Headers are key-value pairs that provide additional information about the message.

### Example

```http
Host: example.com
User-Agent: Mozilla/5.0
Content-Type: application/json
```

### Common Headers

| Header | Purpose |
|----------|---------|
| Host | Target website |
| User-Agent | Information about browser/client |
| Content-Type | Type of data being sent |
| Content-Length | Size of message body |
| Cookie | Sends stored cookies |
| Authorization | Authentication information |

### Key Points

- Provide metadata about requests and responses.
- Help clients and servers understand how to process data.
- Can contain security-related information.

---

## Empty Line

### What is the Empty Line ?

The empty line separates the headers from the body.

### Example

```http
Host: example.com
Content-Type: application/json

{
  "username":"admin"
}
```

Notice the blank line before the body.

### Key Points

- Marks the end of headers.
- Marks the beginning of the body.
- Required for proper message formatting.

---

## Body

### What is the Body ?

The body contains the actual data being sent.

### Request Body Example

```http
POST /login HTTP/1.1

username=admin&password=password123
```

The body contains login information.

### Response Body Example

```html
<html>
<head>
<title>Home</title>
</head>
<body>
Welcome User
</body>
</html>
```

The body contains webpage content.

### Key Points

- Stores actual message data.
- Optional in some requests and responses.
- Commonly used with POST requests.

---

## Example HTTP Request

```http
POST /login HTTP/1.1
Host: example.com
Content-Type: application/x-www-form-urlencoded

username=admin&password=admin123
```

### Breakdown

#### Start Line

```http
POST /login HTTP/1.1
```

#### Headers

```http
Host: example.com
Content-Type: application/x-www-form-urlencoded
```

#### Body

```text
username=admin&password=admin123
```

---

## Example HTTP Response

```http
HTTP/1.1 200 OK
Content-Type: text/html

<html>
<body>
Login Successful
</body>
</html>
```

### Breakdown

#### Start Line

```http
HTTP/1.1 200 OK
```

#### Headers

```http
Content-Type: text/html
```

#### Body

```html
<html>
<body>
Login Successful
</body>
</html>
```

---

## Why HTTP Messages Matter ? 

### Troubleshooting

Understanding HTTP messages helps identify communication issues between clients and servers.

### Web Development

Developers use HTTP messages to build and debug web applications.

### Security

Understanding HTTP messages helps detect:

- Malicious requests
- Injection attacks
- Authentication issues
- Sensitive data exposure

---

## Summary

### HTTP Message Components

- Start Line → Identifies request or response
- Headers → Additional information about the message
- Empty Line → Separates headers from body
- Body → Contains actual data

### HTTP Message Types

- HTTP Request → Sent from client to server
- HTTP Response → Sent from server to client

### Communication Flow

```text
Client → HTTP Request → Server

Server → HTTP Response → Client
```

## HTTP Request: Request Line and Methods

## What is an HTTP Request ?

An HTTP Request is a message sent from a client (browser/user) to a web server to perform an action or request a resource.

<img width="806" height="388" alt="image" src="https://github.com/user-attachments/assets/1731b23d-2803-4a7e-b1c3-c9660db8cfa5" />

### Examples

- Open a webpage
- Submit a login form
- Upload a file
- Delete data
- Update information

### Example Request

```http
GET /login HTTP/1.1
Host: example.com
```

---

## Request Line

### What is the Request Line ?

The Request Line is the first line of an HTTP request.

It tells the server:

- What action to perform
- Which resource is being requested
- Which HTTP version is being used

### Format

```http
METHOD /path HTTP/version
```

### Example

```http
GET /login HTTP/1.1
```

### Components

| Component | Description |
|------------|-------------|
| GET | HTTP Method |
| /login | URL Path |
| HTTP/1.1 | HTTP Version |

---

## HTTP Methods

### What are HTTP Methods ?

HTTP methods define the action a client wants the server to perform.

---

## GET

### Purpose

Used to retrieve data from a server.

### Example

```http
GET /profile HTTP/1.1
```

### Common Uses

- Viewing web pages
- Loading images
- Fetching API data

### Security Considerations

- Do not place passwords in URLs.
- Avoid exposing sensitive information.
- Data in URLs may be logged or stored in browser history.

---

## POST

### Purpose

Used to send data to a server.

### Example

```http
POST /login HTTP/1.1
```

### Common Uses

- Login forms
- Registration forms
- File uploads

### Security Considerations

- Validate user input.
- Sanitize data before processing.
- Helps prevent SQL Injection and XSS attacks.

---

## PUT

### Purpose

Used to create or completely replace a resource.

### Example

```http
PUT /users/123 HTTP/1.1
```

### Common Uses

- Updating user information
- Replacing records

### Security Considerations

- Verify user authorization.
- Prevent unauthorized modifications.

---

## DELETE

### Purpose

Used to remove a resource from the server.

### Example

```http
DELETE /users/123 HTTP/1.1
```

### Common Uses

- Deleting accounts
- Removing files
- Deleting records

### Security Considerations

- Restrict access to authorized users.
- Verify permissions before deletion.

---

## PATCH

### Purpose

Used to partially update a resource.

### Example

```http
PATCH /users/123 HTTP/1.1
```

### Common Uses

- Updating a username
- Changing an email address
- Modifying specific fields

### Security Considerations

- Validate incoming data.
- Prevent inconsistent or invalid updates.

---

## HEAD

### Purpose

Similar to GET but returns only response headers.

### Example

```http
HEAD /index.html HTTP/1.1
```

### Common Uses

- Checking if a resource exists
- Viewing metadata
- Testing connectivity

### Security Considerations

- May reveal server information.
- Restrict unnecessary information exposure.

---

## OPTIONS

### Purpose

Returns the HTTP methods supported by a resource.

### Example

```http
OPTIONS /api/users HTTP/1.1
```

### Common Uses

- API discovery
- CORS requests
- Capability checking

### Security Considerations

- May reveal supported methods.
- Disable if not required.

---

## TRACE

### Purpose

Used for debugging HTTP requests.

### Example

```http
TRACE / HTTP/1.1
```

### Common Uses

- Diagnostics
- Request tracing

### Security Considerations

- Often disabled.
- Can expose sensitive information.

---

## CONNECT

### Purpose

Creates a tunnel between the client and server.

### Example

```http
CONNECT example.com:443 HTTP/1.1
```

### Common Uses

- HTTPS connections
- Secure communication through proxies

### Security Considerations

- Should be properly controlled.
- Can be abused if misconfigured.

---

## URL Path

### What is a URL Path ?

The URL path identifies the specific resource being requested.

### Example

```text
https://example.com/api/users/123
```

Path:

```text
/api/users/123
```

### Key Points

- Identifies a resource on the server.
- Used to locate pages, files, or API endpoints.
- Different paths provide access to different resources.

### Security Considerations

- Validate all path values.
- Prevent unauthorized access.
- Sanitize user-controlled input.

---

## HTTP Version

### What is HTTP Version ?

The HTTP version defines the communication standard used between client and server.

---

## HTTP/0.9 (1991)

### Features

- First HTTP version
- Supported only GET requests

### Example

```http
GET /index.html
```

---

## HTTP/1.0 (1996)

### Features

- Added HTTP headers
- Improved content handling
- Better caching support

---

## HTTP/1.1 (1997)

### Features

- Persistent connections
- Improved caching
- Chunked transfer encoding

### Key Points

- Most widely supported version.
- Still heavily used today.

---

## HTTP/2 (2015)

### Features

- Multiplexing
- Header compression
- Request prioritization

### Benefits

- Faster performance
- Reduced latency
- Better resource usage

---

## HTTP/3 (2022)

### Features

- Uses QUIC protocol
- Improved connection speed
- Better reliability

### Benefits

- Faster page loading
- Improved security
- Better performance on unstable networks

---

### Request Line Structure

```http
METHOD /path HTTP/version
```

### Common HTTP Methods

| Method | Purpose |
|----------|----------|
| GET | Retrieve data |
| POST | Send data |
| PUT | Replace resource |
| PATCH | Partially update resource |
| DELETE | Remove resource |
| HEAD | Retrieve headers only |
| OPTIONS | Show supported methods |
| TRACE | Debug requests |
| CONNECT | Create secure tunnel |

### HTTP Versions

| Version | Key Feature |
|-----------|-------------|
| HTTP/0.9 | GET only |
| HTTP/1.0 | Added headers |
| HTTP/1.1 | Persistent connections |

## HTTP Request: Headers and Body

## Request Headers

### What are Request Headers ?

Request headers provide additional information about an HTTP request.

They help the server understand:

- Who sent the request
- What type of data is being sent
- Where the request came from
- Session and authentication information

### Header Format

```http
Header-Name: Value
```

---

## Common Request Headers

### Host

#### Purpose

Specifies the target web server.

#### Example

```http
Host: tryhackme.com
```

#### Key Points

- Required in HTTP/1.1 requests.
- Tells the server which website is being requested.
- Useful when multiple websites are hosted on the same server.

---

### User-Agent

#### Purpose

Identifies the client making the request.

#### Example

```http
User-Agent: Mozilla/5.0
```

#### Key Points

- Contains browser information.
- May include operating system details.
- Often used for browser compatibility.

---

### Referer

#### Purpose

Shows the webpage that sent the user to the current page.

#### Example

```http
Referer: https://www.google.com/
```

#### Key Points

- Indicates where the request originated.
- Commonly used for analytics and tracking.
- Can sometimes reveal sensitive URLs.

---

### Cookie

#### Purpose

Sends stored cookie data to the server.

#### Example

```http
Cookie: user_type=student; room=introtowebapplication
```

#### Key Points

- Stores session information.
- Helps maintain user login state.
- Can store preferences and settings.

---

### Content-Type

#### Purpose

Specifies the format of data being sent.

#### Example

```http
Content-Type: application/json
```

#### Common Content Types

| Content Type | Description |
|-------------|-------------|
| application/json | JSON data |
| application/xml | XML data |
| text/html | HTML content |
| multipart/form-data | File uploads |
| application/x-www-form-urlencoded | Form submissions |

---

## Request Body

## What is a Request Body ?

The request body contains data sent from the client to the server.

It is commonly used with:

- POST requests
- PUT requests
- PATCH requests

### Example

```http
POST /login HTTP/1.1

username=admin&password=password123
```

The data below the empty line is the request body.

---

## URL Encoded Data (application/x-www-form-urlencoded)

## What is URL Encoded Format ? 

URL encoded data stores information as key-value pairs.

### Format

```text
key=value
```

Multiple values are separated using `&`.

### Example

```text
name=Aleksandra&age=27&country=US
```

### HTTP Example

```http
POST /profile HTTP/1.1
Host: tryhackme.com
Content-Type: application/x-www-form-urlencoded

name=Aleksandra&age=27&country=US
```

### Key Points

- Commonly used in HTML forms.
- Easy to read and process.
- Special characters are encoded.

---

## Form Data

## What is Form Data ?

Form data allows multiple pieces of data to be sent in separate sections.

It is commonly used for file uploads.

### Content Type

```http
Content-Type: multipart/form-data
```

### Example

```http
POST /upload HTTP/1.1
Content-Type: multipart/form-data

username=aleksandra
profile_pic=image.jpg
```

### Common Uses

- Uploading images
- Uploading documents
- Sending mixed data types

### Key Points

- Supports binary files.
- Uses boundaries to separate data blocks.
- Commonly used in upload forms.

---

## JSON

## What is JSON ?

JSON (JavaScript Object Notation) is a lightweight data format used for exchanging information.

### Content Type

```http
Content-Type: application/json
```

### Example

```json
{
  "name": "Aleksandra",
  "age": 27,
  "country": "US"
}
```

### HTTP Example

```http
POST /api/user HTTP/1.1
Content-Type: application/json

{
  "name": "Aleksandra",
  "age": 27,
  "country": "US"
}
```

### Key Points

- Widely used in APIs.
- Easy for humans to read.
- Easy for applications to process.

---

## XML

## What is XML ?

XML (eXtensible Markup Language) stores data using tags.

### Content Type

```http
Content-Type: application/xml
```

### Example

```xml
<user>
    <name>Aleksandra</name>
    <age>27</age>
    <country>US</country>
</user>
```

### HTTP Example

```http
POST /api/user HTTP/1.1
Content-Type: application/xml

<user>
    <name>Aleksandra</name>
    <age>27</age>
    <country>US</country>
</user>
```

### Key Points

- Uses opening and closing tags.
- Can contain nested elements.
- Common in older systems and APIs.

---

## Comparison of Request Body Formats

| Format | Content Type | Common Use |
|----------|-------------|------------|
| URL Encoded | application/x-www-form-urlencoded | Form submissions |
| Form Data | multipart/form-data | File uploads |
| JSON | application/json | APIs |
| XML | application/xml | Legacy systems and APIs |

---

## Summary

### Common Request Headers

- Host → Target server

- URL Encoded → Key-value pairs

- JSON → Modern API communication
- XML → Structured tagged data
