# Active Reconnaissance

## Introduction

**Active reconnaissance** is the process of directly interacting with a target system or network to gather information about its hosts, ports, services, and network behavior.

Unlike passive reconnaissance, which relies on publicly available information, active reconnaissance sends packets or establishes connections to the target. These interactions can reveal information that public sources cannot provide.

### Passive vs. Active Reconnaissance

| Passive Reconnaissance                             | Active Reconnaissance                                      |
| -------------------------------------------------- | ---------------------------------------------------------- |
| Collects information from public sources.          | Directly interacts with target systems.                    |
| Usually generates no direct traffic to the target. | Generates traffic that may be logged or detected.          |
| Uses WHOIS, DNS intelligence, CT logs, and Shodan. | Uses `ping`, `traceroute`, `curl`, `telnet`, and `netcat`. |
| Generally less detectable by the target.           | More likely to trigger security monitoring.                |

### What Can Active Reconnaissance Reveal ?

Active reconnaissance can help identify:

* Whether a host responds to particular probes.
* Which ports accept connections.
* What services and protocols are exposed.
* Service banners and potentially disclosed software versions.
* HTTP response headers and application behavior.
* Possible network paths and intermediate devices.

A failed response does not necessarily mean a host is offline. Firewalls, filtering rules, routing issues, and disabled protocols can all affect the results.

### Detection and Defensive Perspective

Active reconnaissance can leave traces in:

* Firewall and network traffic logs.
* Web server access logs.
* Web Application Firewall (WAF) events.
* Intrusion Detection System (IDS) alerts.
* Security Information and Event Management (SIEM) monitoring.

Security teams monitor these signals to detect unusual connection patterns, repeated probing, and unexpected access attempts.

### Modern Networking Considerations

* **CDNs and WAFs:** May filter, proxy, or block probes before they reach the origin server.
* **IPv4 and IPv6:** A host may respond differently to IPv4 and IPv6 traffic because of different routing or filtering policies.
* **HTTPS:** Encrypts HTTP traffic in transit, so modern tools must account for TLS when inspecting web services.
* **Legacy protocols:** Telnet sends data without encryption and is unsuitable for transmitting sensitive information over untrusted networks.

### Authorization and Scope

Active reconnaissance must only be performed against systems you own or have explicit authorization to test. In professional penetration testing, the permitted targets, techniques, and testing windows should be defined in the engagement scope.

### Key Takeaways

* Active reconnaissance gathers information through direct interaction with a target.
* It can reveal reachability, exposed ports, services, banners, and application behavior.
* Responses depend on network conditions and security controls, lack of a response does not prove a host is offline.
* Active probes can be detected through network and application monitoring.
* Always obtain authorization and remain within the approved scope before testing.

## Web Browser

A web browser is a convenient tool for active reconnaissance because it allows testers to interact with websites and inspect the information returned by web servers. However, browsing generates network requests that may be recorded by security monitoring systems.

> The web browser is one of the most convenient and least suspicious tools for active reconnaissance. It is present on virtually every system, and its traffic blends in with normal user activity. This makes it difficult for defenders to distinguish reconnaissance from legitimate browsing.

## Transport-Level Basics

- **HTTP:** Traditionally uses TCP port 80, traffic is unencrypted.
- **HTTPS:** Uses TCP port 443 with TLS encryption.
- **HTTP/3:** Uses QUIC over UDP port 443. In browser Developer Tools, its protocol is commonly shown as h3.
- **Non-standard ports:** A port can be specified directly in the URL to access a service running on that port.

> Many modern sites also support HTTP/3, which uses the QUIC protocol. QUIC (Quick UDP Internet Connections) is a transport protocol originally developed by Google that combines the functions of TCP and TLS into a single protocol running over UDP port 443. The result is faster and more reliable connections than traditional TCP+TLS. You can identify HTTP/3 traffic in the browser's Network tab, where the protocol column displays h3.

Examples:

```text
https://target.com:8443/
http://192.168.1.100:8080/
```

A page loading successfully suggests that a web service is reachable at that address and port, but does not establish that the service is secure.

## Browser Developer Tools

Open Developer Tools with `Ctrl + Shift + I` on Windows/Linux or `Option + Command + I` on macOS in supported browsers.

| Tab | Reconnaissance use |
|---|---|
| **Network** | Inspect HTTP requests and responses, headers, status codes, cookies, and timing. |
| **Console** | View JavaScript errors, execute JavaScript in the page context, and interact with the DOM. |
| **Sources** | Examine loaded HTML, JavaScript, and CSS files for API endpoints, paths, comments, and technology references. |
| **Application / Storage** | Inspect cookies, Local Storage, and Session Storage for client-side data. |
| **Security** | Review TLS certificate details, issuer, validity, and Subject Alternative Names (SANs). |

### Important observations

- **HTTP headers:** Values such as `Server` and `X-Powered-By` may disclose technology information. `Content-Security-Policy` describes browser-enforced content restrictions.
- **JavaScript files:** May reveal API routes, hidden application functionality, internal service references, or developer comments.
- **Browser storage:** May contain session identifiers or other sensitive data. Never assume client-side storage is safe simply because it is not immediately visible on the page.
- **TLS certificates:** SAN entries can reveal additional hostnames associated with a certificate, but do not prove that every hostname is active or owned by the same organisation.

## Browser Extensions

Browser extensions can simplify technology identification and traffic inspection.

| Extension | Purpose |
|---|---|
| **FoxyProxy** | Switch between proxy configurations, such as Burp Suite and OWASP ZAP. |
| **User-Agent Switcher and Manager** | Change the browser's User-Agent to test how a site responds to different client identities. |
| **Wappalyzer** | Identify technologies such as CMS platforms, web servers, frameworks, analytics tools, and CDNs. |
| **BuiltWith Technology Profiler** | Provides another way to identify website technologies. |
| **WhatRuns** | Lightweight website technology detection. |
| **Library Detector** | Helps identify JavaScript libraries and frameworks. |

Technology fingerprinting results are clues, not guaranteed proof. Confirm important findings using additional evidence where possible.

## Detection and Defensive Monitoring

Even ordinary browser traffic can attract attention when its patterns are unusual. Defenders may monitor:

- Repeated or unusually rapid requests.
- Suspicious changes to request headers or User-Agent strings.
- Requests for sensitive paths or exposed resources.
- Unusual authentication and session activity.
- Web application firewall (WAF), intrusion detection, and web server logs.

**Key lesson :** Active reconnaissance should remain within the authorised scope. Use browser inspection to understand the application's exposed behaviour without accessing data or functionality beyond your permission.

## Key Takeaways

- Browsers support reconnaissance through ordinary navigation and Developer Tools.
- The Network and Sources tabs are particularly useful for understanding requests, responses, and client-side code.
- Cookies, browser storage, headers, and TLS certificates can reveal useful information.
- Extensions such as Wappalyzer help identify technologies quickly.
- Browser activity can be logged and monitored, so only test systems you are authorised to assess.

## Ping

ping is a network diagnostic tool used to check whether a host responds to network probes and to measure round-trip time (RTT). It is commonly used as an initial step in network reconnaissance.

> The name ping comes from the sound of a sonar pulse. You send out a signal and listen for the echo to come back. In networking, the ping command does the same thing. It sends a small test packet to a remote host and waits for a reply. This simple exchange tells you whether the target is reachable over the network and whether it is online and responding.

## How Ping Works ? 

Ping uses **ICMP (Internet Control Message Protocol)**:

- **ICMP Echo Request (Type 8):** Sent by the source to the target.
- **ICMP Echo Reply (Type 0):** Returned by the target if it receives the request and is configured to respond.

Ping does not scan TCP or UDP ports. It tests ICMP responsiveness.

## Basic Commands

**Linux / macOS:**

```bash
ping -c 5 <IP>
ping -c 5 tryhackme.com
```

- `-c 5` sends five requests.
- A hostname is resolved through DNS before the ping is sent.

**Windows:**

```cmd
ping -n 5 <IP>
```

- `-n 5` sends five requests.
- On Linux, ping usually continues until stopped with `Ctrl+C` if no count is specified.

**Force an IP version:**

```bash
ping -4 -c 5 tryhackme.com
ping -6 -c 5 MACHINE_IPV6
```

- `-4` uses IPv4, while `-6` uses IPv6.
- This is useful when a hostname has both IPv4 and IPv6 addresses.

Ping alone also cannot tell you which TCP or UDP ports are open.

Low latency can suggest a nearby or fast network path, but it does not prove that the target is on the same local network.

## Understanding TTL

**TTL (Time To Live)** limits how many router hops a packet can traverse before being discarded. Routers decrement the TTL as packets pass through them.

Typical initial TTL values are:

- Linux: often `64`
- macOs: often `64`
- Windows: often `128`

The received TTL may be lower because intermediate routers decrement it. For example, a reply received with TTL `58` could have started at `64` and passed through six hops.

TTL can provide a rough OS fingerprinting clue, but it is not definitive because initial values vary and can be modified.

## When Ping Receives No Reply

A failed ping does **not** automatically mean the target is offline.

Possible causes include:

- The host is offline or still starting.
- A firewall filters ICMP requests or replies.
- A router has no route to the destination.
- NAT or cloud network rules block ICMP.
- The local machine or network prevents the request from reaching the target.

Example:

```text
From ATTACKBOX_IP icmp_seq=1 Destination Host Unreachable
5 packets transmitted, 0 received, +5 errors, 100% packet loss
```

**Interpretation:** The source or a network device is reporting that the destination is unreachable. This may indicate a routing or connectivity problem; it does not conclusively prove that the target is powered off.

## Quick Reference

| Result | Possible interpretation | Next step |
|---|---|---|
| Replies with low packet loss / Fast replies, low or no packet loss | Host responds to ICMP / Target is online and allows ICMP | Continue authorised reconnaissance / Proceed to port scanning |
| Destination Host Unreachable | Routing or connectivity issue / Target is down or no route exists | Check addressing, routes, and lab connectivity / Check if machine is powered on |
| 100% packet loss without an error message | ICMP may be filtered, or the host may be unreachable / ICMP is filtered or blocked | Use authorised TCP-based checks, such as Nmap port discovery / Try TCP/UDP host discovery with Nmap |
| High latency or heavy / packet loss | Congestion, distance, instability, or filtering / Network congestion, long distance, or filtering| Investigate the network path with traceroute |

## Key Takeaways

- Ping checks ICMP responsiveness, not whether TCP/UDP ports are open.
- Successful replies confirm that the host responded at the time of testing.
- No reply does not prove a host is offline.
- RTT, packet loss, and TTL provide useful network diagnostic clues.
- If ICMP is blocked, use other authorised discovery techniques to assess reachability.

## Traceroute

traceroute is a network reconnaissance and diagnostic tool that identifies the intermediate routers (hops) packets pass through to reach a destination. It helps understand network paths, measure latency at each hop, and identify possible routing or filtering issues.

- Linux/macOS : `traceroute MACHINE_IP`
- Windows : `tracert MACHINE_IP`
- IPv6 : `traceroute -6 MACHINE_IPV6`

The route may change between runs because of dynamic routing, load balancing, and network changes.

> The traceroute command traces the route that packets take from your system to a target host. Its purpose is to discover the IP addresses of the routers (hops) along the path and to determine how many of them sit between you and the destination. This information is useful for understanding network topology, identifying where filtering or latency occurs, and mapping infrastructure.

> However, the route packets take is not fixed. Many routers use dynamic routing protocols such as BGP or OSPF that adapt to network changes. Modern networks also employ load balancing and anycast routing, meaning packets can take different paths even in consecutive runs of the same command.

## How Traceroute Works ? 

Traceroute uses the **TTL (Time To Live)** field in the IP header to discover routers along the path.

> There is no direct way to discover the full path from your system to a target. Instead, traceroute exploits the TTL (Time To Live) field in the IP header. Each router that handles a packet decrements the TTL by one before forwarding it. When the TTL reaches 0, the router drops the packet and sends an ICMP Time-to-Live Exceeded message back to the sender.

### TTL decreases at each router

<img width="1327" height="867" alt="image" src="https://github.com/user-attachments/assets/7f9d64e4-1335-43c1-943e-e2fb9bb20b22" />

This diagram illustrates a packet travelling from source `192.168.0.202` to destination `10.1.2.254`.

- The source sends a packet with an initial TTL of `64`.
- Each router decreases the TTL by `1` before forwarding the packet.
- After passing through four routers, the packet's TTL becomes `60`.
- If the TTL reaches `0` before reaching the destination, the router discards the packet and typically sends an **ICMP Time Exceeded** message back to the source.

**Key concept :** TTL limits how many router hops a packet can traverse; it is not a timer measured in seconds.

### Traceroute discovers hops incrementally

<img width="1067" height="658" alt="image" src="https://github.com/user-attachments/assets/eed0bb1e-6569-43cb-8e87-8d701665755c" />

This diagram illustrates how traceroute discovers the route one hop at a time.

1. **TTL = 1:** The first router receives the probe, reduces TTL to zero, and returns an ICMP Time Exceeded message. Its address is revealed.
2. **TTL = 2:** The probe passes through the first router and expires at the second router, revealing that router's address.
3. **TTL = 3:** The third router responds when the probe expires there.
4. The process continues with increasing TTL values until the destination is reached or the maximum hop limit is exceeded.

Traceroute therefore discovers the path by sending probes with progressively larger TTL values.

Some routers do not return ICMP responses, often because of filtering or rate limiting. These hops appear as `*` in the output.

> Some routers are configured not to send ICMP Time-to-Live Exceeded messages. This is common in secure environments intended to prevent reconnaissance. These routers appear as * in the traceroute output.

## Basic Commands

```bash
# Default traceroute on Linux/macOS
traceroute MACHINE_IP

# TCP-based traceroute on Linux
traceroute -T MACHINE_IP

# ICMP-based traceroute on Linux
traceroute -I MACHINE_IP

# IPv6 traceroute
traceroute -6 MACHINE_IPV6

# Continuous path and latency monitoring
mtr MACHINE_IP
```

Linux `traceroute` typically uses UDP probes by default. TCP and ICMP modes use different probe types and may produce different results depending on network filtering.

## Important Interpretation Notes

- A hop number represents a TTL step, not necessarily a unique physical router in every probe.
- An asterisk does not prove that a router is offline, it may simply suppress or rate-limit responses.
- A missing response at one hop does not necessarily prevent packets from reaching later hops.
- RTT measures the time for a probe to reach a hop and for its response to return. It is not a direct measurement of the router's processing delay.
- Traceroute output reveals only the path visible to the probes, it may not show every device or the exact internal network topology.

## Additional Tool : MTR (My Traceroute) (originally Matt's Traceroute)

`mtr` combines traceroute with repeated ping-like measurements. It continuously displays hop-level latency and packet-loss statistics, helping identify where performance problems may occur.

> Use mtr MACHINE_IP (My Traceroute) for a real-time, continuous view that combines traceroute with ping-like statistics, showing packet loss and latency per hop. For bypassing filters, try TCP mode with traceroute -T MACHINE_IP or ICMP mode with traceroute -I MACHINE_IP. For IPv6, the standalone traceroute6 command ensures compatibility with dual-stack networks.

### TTL in Normal Network Communication

In normal communication, the sender sets an initial TTL (Time to Live) value, commonly 64 on Linux systems. Each router decreases the TTL by 1 before forwarding the packet.

If the TTL reaches 0 at a router, the packet is dropped. However, if the packet reaches its destination before the TTL expires, it is delivered normally.

**Example:**

Network path: `A → R1 → R2 → R3 → R4 → R5 → B`

| Step | TTL |
|---|---:|
| A sends the packet | 64 |
| R1 forwards it | 63 |
| R2 forwards it | 62 |
| R3 forwards it | 61 |
| R4 forwards it | 60 |
| R5 forwards it | 59 |
| B receives the packet | 59 |

The destination receives the packet with TTL = 59, so it can process it normally.

**Key Point:** TTL is a maximum hop limit, not a value that must reach zero. It prevents packets from circulating indefinitely due to routing loops.

### Who decides the TTL value ?
The sender's operating system or application sets the initial TTL.
- Normal traffic: The operating system chooses a default initial TTL, commonly 64 on Linux/macOS or 128 on Windows.
- Traceroute: The traceroute program deliberately sets the TTL for each probe to 1, then 2, then 3, and so on.

### What does 30 hops max mean ?
When you see :
```
traceroute to target.com, 30 hops max
```
The 30 is traceroute's maximum number of hop levels it will probe, not the TTL of every packet.
Typically, it sends probes with TTL values from 1 up to 30, stopping sooner if it detects that the destination has been reached.

**Remember :** Normal packets usually start with a relatively large TTL to reach their destination. Traceroute intentionally starts with TTL = 1 and increases it to discover the path, one hop at a time

### How Traceroute Learns a Router's IP Address ? 

When a probe's TTL reaches 0, the router discards the original probe and usually sends a new **ICMP Time Exceeded** message back to the sender.

- **How the router knows where to send it:** The original packet's IP header contains the sender's source IP address, which the router uses as the destination of the ICMP response.
- **What the response contains:** An ICMP error message and part of the original packet, allowing the sender to match the response to its probe.
- **How traceroute identifies the router:** The ICMP response's source IP address identifies the responding router interface.

**Key Point:** The router does not return the discarded probe. It generates a separate ICMP error response, and traceroute uses the response's source IP to identify the hop.

## Key Takeaways

- Traceroute discovers intermediate hops by increasing the packet TTL.
- Routers commonly send ICMP Time Exceeded messages when a probe's TTL expires.
- `*` means no response was received for that probe, not necessarily that the router is down.
- Different runs can reveal different paths or destination IPs.
- Use traceroute alongside ping and other authorised diagnostics to investigate connectivity and routing.
