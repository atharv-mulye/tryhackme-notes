# Active Reconnaissance

## Introduction

**Active reconnaissance** is the process of directly interacting with a target system or network to gather information about its hosts, ports, services, and network behavior.

Unlike passive reconnaissance, which relies on publicly available information, active reconnaissance sends packets or establishes connections to the target. These interactions can reveal information that public sources cannot provide.

### Passive vs. Active Reconnaissance

| Passive Reconnaissance                             | Active Reconnaissance                                      |
| -------------------------------------------------- | ---------------------------------------------------------- |
| Collects information from public sources.          | Directly interacts with target systems.                    |
| Usually generates no direct traffic to the target. | Generates traffic that may be logged or detected.          |
| Uses WHOIS, DNS intelligence, CT logs, and Shodan. | Uses `ping`, `traceroute`, `curl`, `telnet`, and `netcat`. |
| Generally less detectable by the target.           | More likely to trigger security monitoring.                |

### What Can Active Reconnaissance Reveal ?

Active reconnaissance can help identify:

* Whether a host responds to particular probes.
* Which ports accept connections.
* What services and protocols are exposed.
* Service banners and potentially disclosed software versions.
* HTTP response headers and application behavior.
* Possible network paths and intermediate devices.

A failed response does not necessarily mean a host is offline. Firewalls, filtering rules, routing issues, and disabled protocols can all affect the results.

### Detection and Defensive Perspective

Active reconnaissance can leave traces in:

* Firewall and network traffic logs.
* Web server access logs.
* Web Application Firewall (WAF) events.
* Intrusion Detection System (IDS) alerts.
* Security Information and Event Management (SIEM) monitoring.

Security teams monitor these signals to detect unusual connection patterns, repeated probing, and unexpected access attempts.

### Modern Networking Considerations

* **CDNs and WAFs:** May filter, proxy, or block probes before they reach the origin server.
* **IPv4 and IPv6:** A host may respond differently to IPv4 and IPv6 traffic because of different routing or filtering policies.
* **HTTPS:** Encrypts HTTP traffic in transit, so modern tools must account for TLS when inspecting web services.
* **Legacy protocols:** Telnet sends data without encryption and is unsuitable for transmitting sensitive information over untrusted networks.

### Authorization and Scope

Active reconnaissance must only be performed against systems you own or have explicit authorization to test. In professional penetration testing, the permitted targets, techniques, and testing windows should be defined in the engagement scope.

### Key Takeaways

* Active reconnaissance gathers information through direct interaction with a target.
* It can reveal reachability, exposed ports, services, banners, and application behavior.
* Responses depend on network conditions and security controls; lack of a response does not prove a host is offline.
* Active probes can be detected through network and application monitoring.
* Always obtain authorization and remain within the approved scope before testing.
