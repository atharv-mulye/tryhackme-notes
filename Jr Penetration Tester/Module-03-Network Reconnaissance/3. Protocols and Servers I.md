# Protocols and Servers I

## Introduction

Network protocols define the rules that devices and applications follow to communicate over a network. This room introduces five commonly used application-layer protocols:

- **HTTP** - transfers web pages and other web resources.
- **FTP** - transfers files between systems.
- **POP3** - retrieves emails from a mail server.
- **SMTP** - sends and relays emails.
- **IMAP** - accesses and synchronises emails stored on a mail server.

## Why Learn These Protocols ?

Understanding how protocols work helps cybersecurity professionals identify exposed services, understand network traffic, and recognise security weaknesses.

- **Real-world usage:** These protocols remain relevant, although encrypted alternatives and secure configurations are widely used.
- **Penetration testing:** Misconfigured or unencrypted services may expose sensitive information or credentials.
- **Understanding attacks:** Knowing how a protocol communicates makes it easier to understand vulnerabilities such as insecure authentication, email spoofing, and web application attacks.

## Interacting with Protocols

Graphical applications such as web browsers and email clients hide most of the underlying communication. Using a command-line client such as Telnet allows you to observe and send protocol commands directly to a service.

For example, an HTTP client sends a request to a web server, which processes the request and returns an HTTP response.

The goal is to understand the **request-and-response process**, rather than memorise every protocol command.

## Cleartext Communication and Security

Some protocols can transmit information without encryption. If credentials or other sensitive data travel in cleartext, an attacker with access to the relevant network traffic may be able to read them.

Examples include:
- HTTP without TLS
- FTP without TLS
- POP3 without TLS
- SMTP without TLS
- IMAP without TLS

**Important:** These protocols can also be protected using encryption, depending on the protocol and configuration. For example, HTTPS protects HTTP traffic using TLS, while email protocols can use TLS-protected connections or supported upgrade mechanisms.

## Key Takeaways

- Protocols define how applications communicate over networks.
- HTTP, FTP, POP3, SMTP, and IMAP support web, file-transfer, and email operations.
- Command-line interaction helps reveal how protocols work beneath graphical interfaces.
- Unencrypted communication can expose sensitive data.
- Understanding protocol behaviour is foundational to network reconnaissance and cybersecurity assessments.

## Telnet

## What Is Telnet ?

Telnet is an application-layer protocol that allows users to access a remote computer's command-line terminal over a network. It traditionally uses **TCP port 23**.

After connecting, the user may be prompted for a username and password. If authentication succeeds, the server provides access according to the user's permissions.

> The Telnet protocol is an application-layer protocol used to connect to a virtual terminal of another computer. Using Telnet, a user can log into a remote machine and access its terminal (console) to run programs, start batch processes, and perform system administration tasks remotely.

> The Telnet protocol is relatively simple. When a user connects, they are asked for a username and password. Upon correct authentication, the user gains access to the remote system's terminal. However, all communication between the Telnet client and the Telnet server is unencrypted, making it an easy target for attackers.

## Telnet Today

Telnet has largely been replaced by SSH for remote administration because Telnet does not encrypt its communication.

Telnet may still be found on:
- Legacy systems and older routers or switches
- Embedded and IoT devices
- Internal networks with weak security
- Systems where Telnet has been unnecessarily enabled

An exposed Telnet service on TCP port 23 can indicate a security risk and should be investigated within the authorised assessment scope.

## How Telnet Works

A Telnet server listens for incoming connections. The client connects, provides credentials when prompted, and receives a remote terminal if authentication succeeds.

Example:

```bash
telnet MACHINE_IP 23
```

Illustrative login flow:

```text
bento login: frank
Password:
Welcome to Ubuntu
frank@bento:~$
```

**Interpretation:**
- `bento login:` - the server requests a username.
- `Password:` - the server requests a password.
- `Welcome to Ubuntu` - the login was successful.
- `frank@bento:~$` - the user has received a shell prompt. The `$` commonly indicates a non-root shell on Linux.

The example is illustrative, the target VM in this task does not have Telnet open, so the same login cannot be reproduced against it.

## Why Telnet Is Insecure

Telnet sends credentials and other session data without encryption. Someone who can capture the network traffic may be able to read the information exchanged.

<img width="500" height="250" alt="image" src="https://github.com/user-attachments/assets/ca71d001-1677-4645-9fae-6b98e9fcb7c7" />

Even if the password characters are hidden on the terminal screen while typing, **the password can still travel across the network in cleartext**.

Potential risks include:
- Credential theft through network traffic capture
- Exposure of commands and responses
- Account compromise if captured credentials are reused or remain valid

## Telnet Client for Reconnaissance

Even though Telnet is insecure for remote administration, its client can connect to other TCP ports for basic testing and manual protocol interaction.

For example:

```bash
telnet MACHINE_IP 80
```

This connects to TCP port 80, where you can manually send an HTTP request. This is a reconnaissance use of the Telnet client, not a Telnet login to the web server.

## Secure Alternative: SSH

SSH (Secure Shell) is the standard choice for remote command-line administration because it encrypts communication, including authentication data.

| Feature | Telnet | SSH |
|---|---|---|
| Default TCP port | 23 | 22 |
| Encrypts session data | No | Yes |
| Suitable for secure remote administration | No | Yes |

## Key Takeaways

- Telnet provides remote terminal access, traditionally over TCP port 23.
- Credentials and session data are transmitted in cleartext.
- Hiding password characters on screen does not encrypt network traffic.
- SSH is the secure alternative for remote administration.
- The Telnet client can also be used to test TCP ports and interact manually with text-based services.

## Hypertext Transfer Protocol (HTTP)

## What Is HTTP ?

**HTTP (Hypertext Transfer Protocol)** is an application-layer protocol used for communication between web clients and web servers.

A browser sends HTTP requests for resources such as HTML pages, images, and other files. The web server processes the requests and returns HTTP responses.

**Example:** A browser requests `index.html`, receives the HTML document, and may then request additional resources such as images and CSS files.

<img width="700" height="400" alt="image" src="https://github.com/user-attachments/assets/7626ea8f-5b4b-41b9-a2ca-2d09bc16a9a4" />

## HTTP vs HTTPS

| Feature | HTTP | HTTPS |
|---|---|---|
| Encryption | No, by itself | Yes, using TLS |
| Default port | TCP 80 | TCP 443 |
| Data confidentiality | Not provided by HTTP | Protected by TLS |
| Common use | Unencrypted web traffic | Secure web communication |

HTTP data sent without encryption can be read by someone able to capture the traffic. HTTPS protects data in transit using TLS.

Understanding HTTP remains important because HTTPS uses the same HTTP request and response structure, protected by encryption. Tools such as Burp Suite can inspect HTTPS traffic when configured as an authorised interception proxy.

## Manually Sending HTTP Requests

A tool such as Telnet or Netcat can connect to a plain HTTP server and allow you to send a request manually.

**Step 1 - Connect to port 80:**

```bash 
telnet MACHINE_IP 80
```

**Step 2 - Send an HTTP request:**

```http 
GET / HTTP/1.1
host: telnet
```

Press Enter twice after the final header to end the request.

**Example response:**

```http 
HTTP/1.1 200 OK
Server: nginx/1.18.0 (Ubuntu)
Date: Mon, 19 Oct 2026 05:42:54 GMT
Content-Type: text/html
Content-Length: 234
Last-Modified: Wed, 15 Sep 2021 08:53:59 GMT
Connection: keep-alive
ETag: "6141b4a7-ea"
Accept-Ranges: bytes

<!DOCTYPE html>
<html lang="en">
<head>
  <title>Welcome to my Web Server</title>
  <meta charset="UTF-8" />
  <meta name="viewport" content="width=device-width,initial-scale=1" />
</head>
<body>
  <h1>Coming Soon<h1>
</body>
</html>
```

The server may then return the requested HTML content.

### Understanding the Response

| Component | Meaning |
|---|---|
| `GET` | HTTP method used to request a resource |
| `/index.html` | Requested resource path |
| `HTTP/1.1` | HTTP protocol version |
| `Host` | Identifies the hostname being requested |
| `200 OK` | Request succeeded |
| `404 Not Found` | Requested resource was not found |
| `Server` | May reveal the web server software and reported version |
| `Content-Type` | Describes the response body's media type |
| `Content-Length` | Indicates the response body's size in bytes |

**Note:** The `Server` header may reveal software details, but it can be hidden, modified, or inaccurate. It does not independently confirm a vulnerability.

## Information Revealed by HTTP Headers

HTTP headers provide metadata about requests and responses. During authorised reconnaissance, they may reveal:

- Web server software and reported version
- Content types and response sizes
- Cookies and session-related information
- Redirects, caching behaviour, and security headers

Exposed software versions can be researched against vulnerability databases such as the CVE database. A matching version alone does not prove that a system is vulnerable.

## Web Servers and Clients

An **HTTP client** sends requests, while an **HTTP server** receives and processes them.

Common web servers include:

- **Nginx:** Known for performance and efficient handling of concurrent connections.
- **Apache HTTP Server:** Open-source and highly configurable.
- **Microsoft IIS:** Web server commonly used in Windows environments.
- **LiteSpeed and Caddy:** Other web server implementations.

> Internet Information Services (IIS) is an extensible web server software created by Microsoft to host websites, web applications, and services on the Windows NT family

> LiteSpeed is an Apache-compatible server optimized for high-performance PHP and WordPress hosting, while Caddy is a modern, Go-based reverse proxy built for simple configuration and automatic out-of-the-box HTTPS.

Common web browsers include Chrome, Firefox, Safari, and Microsoft Edge. Developer Tools help inspect network requests, response headers, JavaScript, and browser storage.

## HTTP Versions

| Version | Key Characteristics |
|---|---|
| HTTP/1.1 | Human-readable text protocol, supports persistent connections |
| HTTP/2 | Binary framing, multiplexed streams, and header compression |
| HTTP/3 | Uses QUIC over UDP rather than TCP |

HTTP/1.1 is convenient for manual learning because its requests are human-readable. HTTP/2 and HTTP/3 use different transport and framing mechanisms, so they cannot be tested in the same way with a basic Telnet session.

## Key Takeaways

- HTTP defines how clients request web resources and servers return responses.
- HTTPS protects HTTP communication using TLS.
- Manual HTTP requests help explain how browsers communicate with servers.
- Response codes and headers provide useful information during reconnaissance.
- Web server banners can guide further research but do not prove a vulnerability.
- HTTP/1.1 is the easiest version to inspect manually using Telnet or Netcat.

## File Transfer Protocol (FTP)

## What Is FTP ?

**FTP (File Transfer Protocol)** is an application-layer protocol used to transfer files between a client and a server. It traditionally uses **TCP port 21** for the control connection.

FTP is still found on legacy systems, internal networks, public file servers, and misconfigured services. Discovering an FTP server during authorised reconnaissance may reveal exposed files or weak access controls.

## FTP vs Secure Alternatives

Standard FTP sends credentials and data without encryption.

| Protocol | Default Port | Security |
|---|---:|---|
| FTP | TCP 21 (control) | Unencrypted by default |
| SFTP (SSH File Transfer Protocol) | TCP 22 | File transfer over encrypted SSH |
| FTPS (FTP Secure) | TCP 21 or 990, depending on mode | FTP protected by TLS |
| SCP (Secure Copy Protocol) | TCP 22 by default | File copying over SSH |

**Note:** SFTP is a separate protocol from FTP, it is not simply FTP with encryption added.

## Manually Interacting with FTP

A Telnet client can connect to an FTP server's control port to inspect its banner and send FTP commands.

```bash
telnet MACHINE_IP 21
```

Example interaction:

```text
220 (vsFTPd 3.0.3)
USER frank
331 Please specify the password.
PASS <password>
230 Login successful.
SYST
215 UNIX Type: L8
QUIT
221 Goodbye.
```

### Common FTP Commands and Responses

| Command / Response | Meaning |
|---|---|
| `220` | Service is ready and displays a greeting |
| `USER frank` | Supplies the username |
| `331` | Username accepted, password required |
| `PASS <password>` | Supplies the password |
| `230` | Login successful |
| `SYST` | Requests the server's system type |
| `STAT` | Requests server or session status information |
| `PASV` | Requests passive mode for data connections |
| `TYPE A` | Selects ASCII transfer mode |
| `TYPE I` | Selects binary transfer mode |
| `QUIT` | Ends the FTP session |

In the example, `vsFTPd 3.0.3` identifies the reported FTP server software and version. The response `215 UNIX Type: L8` indicates a UNIX-style system type.

**Security note:** Never use real credentials in an unencrypted FTP session. Credentials shown in training examples should be treated as demonstration data.

## FTP Control and Data Connections

FTP uses two separate connections:

- **Control connection:** Carries commands and responses, usually over TCP port 21.
> Control connection: Used to send commands, such as “show me the files” or “download report.pdf.”
- **Data connection:** Transfers directory listings and file contents through a separate connection.
> Data connection: Used to transfer the actual file or directory listing.

This two-connection design can complicate firewall and NAT configuration.

### Active vs Passive FTP

| Mode | How the Data Connection Works |
|---|---|
| Active | The client tells the server where to connect, the server initiates the data connection back to the client, traditionally from server TCP port 20. |
| Passive | The server provides an address and port for data transfer, and the client initiates the data connection to the server. |

Passive mode is generally more firewall-friendly because the client initiates both connections.

> In active mode, the data is sent over a separate channel originating from the FTP server's port 20. The server initiates the data connection back to the client. This often fails when the client is behind a firewall or NAT.

>  In passive mode, the data is sent over a separate channel originating from an FTP client's port above port number 1023. The client initiates both connections. This is more firewall-friendly and is the default for most modern FTP clients.

<pre>
The main difference between active and passive FTP is <strong>which side initiates the data connection</strong>.

<h3>Active FTP</h3>

In active mode, the client establishes the control connection to the server on TCP port <code>21</code>. The client tells the server which client-side port to connect to for data transfer. The <strong>server initiates the data connection back to the client</strong>, traditionally from server TCP port <code>20</code>.

<strong>Connection flow:</strong>
1. Client → Server: Establish control connection on TCP <code>21</code>.
2. Client → Server: Tell the server where to connect for data.
3. Server → Client: Initiate the data connection.
4. File or directory data is transferred.

<strong>Limitation:</strong> The incoming data connection may be blocked by the client's firewall or NAT configuration.

<h3>Passive FTP</h3>

In passive mode, the client establishes the control connection to the server on TCP port <code>21</code> and sends the <code>PASV</code> command. The server responds with an IP address and port for the data connection. The <strong>client then initiates the data connection to the server</strong>.

<strong>Connection flow:</strong>
1. Client → Server: Establish control connection on TCP <code>21</code>.
2. Client → Server: Send the <code>PASV</code> command.
3. Server → Client: Provide the data connection address and port.
4. Client → Server: Initiate the data connection.
5. File or directory data is transferred.

<strong>Advantage:</strong> Passive FTP is generally more firewall- and NAT-friendly because the client initiates both connections.

<h3>Understanding a PASV Response</h3>

Example response:

<pre>227 Entering Passive Mode (10,10,0,148,78,223)</pre>

The first four numbers represent the server's IPv4 address: <code>10.10.0.148</code>.

The last two numbers determine the data port:

<pre>Port = (p1 × 256) + p2

Port = (78 × 256) + 223

Port = 19968 + 223

Port = 20191</pre>

Therefore, the data connection port is <strong>TCP 20191</strong>.

## Transferring Files with an FTP Client

Telnet can demonstrate FTP commands, but it is not a practical general-purpose file-transfer client because FTP requires a separate data connection.

Use an FTP client instead:

```bash
ftp MACHINE_IP
```

Common commands at the `ftp>` prompt:

| Command | Purpose |
|---|---|
| `ls` | Lists remote files |
| `ascii` | Selects ASCII transfer mode |
| `binary` | Selects binary transfer mode |
| `get README.txt` | Downloads a remote file |
| `put FILE.txt` | Uploads a local file, if permitted |
| `exit` | Closes the FTP session |

Use ASCII mode for suitable text transfers and binary mode for binary files such as images, archives, and executables. For ordinary file downloads, binary mode is often the safest default because it preserves the file's bytes exactly.

## Anonymous FTP

Some FTP servers allow access without a personal account, commonly using the username `anonymous`. Depending on the server, a password may be optional or an email-style value may be accepted.

During an authorised assessment, check whether anonymous access is enabled and review what permissions it grants.

Potential risks include:
- Unintentionally exposed documents or backups
- Disclosure of configuration files or directory structures
- Unauthorised uploads if write permissions are enabled

Anonymous access is not automatically a vulnerability, the risk depends on the data exposed and the permissions granted.

## FTP Servers and Clients

Common FTP server implementations include:

- **vsftpd:** Commonly used on Linux.
- **ProFTPD:** Modular and configurable.
- **Pure-FTPd:** Focuses on simplicity and security.
- **Microsoft IIS FTP:** FTP server functionality for Windows environments.

Command-line FTP clients and GUI tools such as FileZilla can manage transfers. Most modern browsers have removed built-in FTP support.

## Security Implications

Unencrypted FTP can expose:
- Usernames and passwords
- Commands and server responses
- Directory listings and file contents

Prefer **SFTP** or appropriately configured **FTPS** for secure transfers. If legacy FTP must remain available, restrict access and permissions, and isolate the service appropriately.

## Key Takeaways

- FTP traditionally uses TCP port 21 for commands and responses.
- FTP uses separate control and data connections.
- Active and passive modes differ in which side initiates the data connection.
- `USER`, `PASS`, `SYST`, `PASV`, `STAT`, and `QUIT` are useful FTP commands to recognise.
- Anonymous FTP can expose files or allow uploads if configured insecurely.
- SFTP and FTPS provide encrypted alternatives, but they are different protocols.

## Simple Mail Transfer Protocol (SMTP)

SMTP is an email protocol used to **send emails between email clients and mail servers, and between mail servers**. Email clients use SMTP for sending messages, while POP3 and IMAP are commonly used to retrieve and access received emails.

## Email Delivery Components

| Component | Full Name | Purpose |
|---|---|---|
| MUA | Mail User Agent | Email application used to compose, send, and read emails / The email client (e.g., Thunderbird, Outlook, a webmail interface) |
| MSA | Mail Submission Agent | Accepts outgoing emails from the client and checks them before submission /  Receives mail from the MUA, checks for errors, and forwards it |
| MTA | Mail Transfer Agent | Routes and transfers/deliver emails between mail servers |
| MDA | Mail Delivery Agent | Places incoming emails into the recipient's mailbox / Stores the email in the recipient's mailbox for retrieval |

### Email Delivery Flow

<img width="700" height="300" alt="image" src="https://github.com/user-attachments/assets/91c32f56-f49c-40c6-b5a5-803bf899ce98" />

1. The **MUA** submits the email to the **MSA**.
2. The MSA validates the submission and passes the email to an **MTA**.
3. The sender's MTA transfers the email to the recipient's mail server.
4. The receiving server's delivery component stores the email in the recipient's mailbox.
5. The recipient uses their MUA to access the email through **IMAP or POP3**.

These components may run on the same server, they describe different functions rather than necessarily separate machines.

```
The figure shows the following five steps that an email needs to go through to reach the recipient's inbox :

1. The MUA has an email message to be sent. It connects to the MSA to submit the message.
2. The MSA receives the message, checks for any errors before transferring it to the MTA, which is commonly hosted on the same server.
3. The MTA sends the email message to the MTA of the recipient. The MTA can also function as an MSA.
4. A typical setup has the MTA server also functioning as the MDA.
5. The recipient collects their email from the MDA using their email client (MUA).

If the above steps sound confusing, consider the following analogy :

1. You (MUA) want to send postal mail.
2. The post office employee (MSA) checks the postal mail for any issues before your local post office (MTA) accepts it.
3. The local post office checks the mail destination and sends it to the post office (MTA) in the correct country.
4. The post office (MTA) delivers the mail to the recipient's mailbox (MDA).
5. The recipient (MUA) regularly checks the mailbox for new mail. They notice the new mail and take it.
```

## Email Protocols

| Protocol | Purpose |
|---|---|
| SMTP (Simple Mail Transfer Protocol) | Sends and transfers emails. |
| POP3 (Post Office Protocol version 3) | Downloads emails from a mailbox, commonly for local access. |
| IMAP (Internet Message Access Protocol) | Accesses and synchronizes emails stored on a mail server. |

## SMTP Ports and Encryption

| Port | Purpose | Security |
|---|---|---|
| TCP 25 | Primarily server-to-server email transfer (MTA to MTA). | STARTTLS may be used to upgrade the connection to TLS. |
| TCP 587 | Email submission from a client to its mail server (MUA to MSA). | Typically requires authentication and uses STARTTLS. |
| TCP 465 | Secure email submission. | Implicit TLS begins immediately upon connection. |

> Port 25 is the traditional SMTP port used for server-to-server communication (MTA to MTA). It is often blocked by ISPs for residential connections to prevent spam. On port 25, encryption is optional and negotiated via STARTTLS.

> Port 587 is the submission port, used by email clients (MUA) to submit messages to their mail server (MSA). This is the recommended port for sending email and typically requires authentication. TLS encryption is negotiated via the STARTTLS command.

> Port 465 was originally designated for SMTPS (SMTP over implicit TLS), then deprecated, and has since been reinstated. On this port, TLS encryption begins immediately upon connection.

Traditional SMTP can transmit commands and message content in plaintext. Modern deployments use TLS to protect email traffic in transit. Port 25 may be blocked by residential ISPs to reduce spam.

## Communicating with SMTP Using Telnet

A Telnet client can connect to a plaintext SMTP service, allowing a tester to observe SMTP commands and responses manually.

Example connection:

```bash
telnet MACHINE IP
```

A successful connection may display:

```text
220 bento.localdomain ESMTP Postfix (Ubuntu)
```

The `220` response indicates that the SMTP server is ready.

### Common SMTP Commands

| Command | Purpose |
|---|---|
| `HELO hostname` | Introduces the client to the SMTP server. |
| `EHLO hostname` | Introduces the client and requests extended SMTP capabilities. |
| `MAIL FROM:` | Specifies the envelope sender address. |
| `RCPT TO:` | Specifies the recipient address. |
| `DATA` | Begins the email headers and message body. |
| `QUIT` | Ends the SMTP session. |

### Example SMTP Conversation

```text
HELO telnet
MAIL FROM:<sender@example.com>
RCPT TO:<recipient@example.com>
DATA
Subject: Test Email

Hello,
This is a test message.
.
QUIT
```

The period (`.`) on a line by itself marks the end of the message data. The server may then queue the email for delivery.

**Note:** This is a protocol demonstration. Real servers may require authentication, valid sender addresses, permitted recipients, and other checks. Use only authorized mail servers and recipients.

## Email Spoofing

Email spoofing occurs when an email is made to appear as though it came from a sender who did not actually send or authorize it.

SMTP distinguishes between the **envelope sender**, specified using `MAIL FROM`, and the visible `From:` header in the message. These can differ, and neither field alone proves the sender's identity.

Some servers accept sender addresses without verifying control of the address. This weakness can be abused in phishing attacks, although modern servers may enforce authentication and anti-spoofing policies.

### Defenses Against Spoofing

- **SPF (Sender Policy Framework):** Specifies which servers are authorized to send email for a domain.
- **DKIM (DomainKeys Identified Mail):** Adds a cryptographic signature that receiving servers can verify.
- **DMARC (Domain-based Message Authentication, Reporting, and Conformance):** Defines how receivers should handle messages that fail domain authentication and provides reporting.

These mechanisms help reduce spoofing but do not eliminate every form of email impersonation.

## Security Implications for Pentesters

- **Phishing assessment:** Evaluate email security controls and organizational awareness within an authorized scope.
- **Open relay testing:** Check whether a mail server improperly allows unauthorized users to relay messages to external recipients.
- **Email header analysis:** Examine headers and authentication results to investigate suspicious messages.
- **Transport security:** Identify whether SMTP connections expose data because TLS is absent or improperly configured.

## Key Takeaways

- SMTP is used to send and transfer emails, IMAP and POP3 are used to access received messages.
- TCP 25 is primarily for server-to-server transfer, TCP 587 for submission with STARTTLS, and TCP 465 for submission with implicit TLS.
- Telnet can demonstrate SMTP commands on a server that permits plaintext connections.
- Sender addresses alone do not establish identity, SPF, DKIM, and DMARC help protect against spoofing.
- Always perform SMTP testing only on systems you are authorized to assess.

## Post Office Protocol Version 3 (POP3)

POP3 is an email protocol used by a Mail User Agent (MUA) to retrieve email messages from a mail server. The client connects to the POP3 server, authenticates, and downloads messages. Depending on the client's settings, messages may be deleted from the server after retrieval.

## POP3 Ports and Encryption

| Port | Protocol | Security |
|---|---|---|
| TCP 110 | POP3 | Plaintext by default, may support upgrading to TLS using `STLS`. |
| TCP 995 | POP3S | Implicit TLS, encryption begins immediately upon connection. |

> Port 110 is the default POP3 port using cleartext. Some servers support upgrading the connection to TLS using the STLS command (similar to STARTTLS in SMTP).

> Port 995 is used for POP3S (POP3 over implicit TLS). The connection is encrypted from the start.

Plaintext POP3 exposes usernames, passwords, and email contents to anyone able to observe unencrypted network traffic. Secure configurations should use TLS.

## Manually Interacting with POP3

A Telnet client can demonstrate POP3 commands when a server permits plaintext connections.

Example:

```bash
telnet MACHINE_IP 110
```

A typical session follows this sequence:

```text
USER frank
PASS <password>
STAT
LIST
RETR 1
QUIT
```

### Understanding the Commands

- `USER frank` - Specifies the mailbox username.
- `PASS <password>` - Supplies the password for authentication.
- `STAT` - Returns the number of messages and their total size.
- `LIST` - Lists messages and their sizes.
- `RETR 1` - Retrieves the contents of message number 1.
- `QUIT` - Ends the session and processes messages marked for deletion.

**Important:** On plaintext POP3, the username and password are transmitted without encryption. Use Telnet only with authorized test systems and accounts.

## Common POP3 Commands

| Command | Purpose |
|---|---|
| `USER username` | Identifies the user. |
| `PASS password` | Authenticates the user. |
| `STAT` | Returns the message count and total mailbox size in octets (bytes). |
| `LIST` | Lists messages and their sizes. |
| `RETR n` | Retrieves message number `n`. |
| `DELE n` | Marks message `n` for deletion. |
| `RSET` | Removes deletion marks from the current session. |
| `QUIT` | Ends the session, deletion marks are normally committed after a successful update. |

### Understanding the `STAT` Response

Example:

```text
+OK 1 179
```

- `+OK` - The command succeeded.
- `1` - There is one message in the mailbox.
- `179` - The mailbox contains 179 octets of message data.

The server's positive response to `STAT` follows the format `+OK nn mm`, where `nn` is the message count and `mm` is the total size in octets.

## POP3 Download Behaviour

POP3 is traditionally associated with a **download-oriented model**. Depending on client settings, messages may be deleted from the server after they are downloaded.

Potential limitations include:

- Emails may be stored primarily on one device.
- Messages and read/unread status may not synchronize across devices.
- If server copies are deleted and the local device is lost, the messages may be lost unless backed up.
- Keeping messages on the server is possible when the client is configured to do so.

POP3 can still be useful for offline access, local archiving, or single-device workflows.

<pre>
Based on the default settings, the mail client deletes the mail message after it downloads it. This "download and delete" model means :

1. Emails are stored locally on your device, not on the server.
2. Once downloaded, the email is only accessible from that specific device.
3. If your device is lost or damaged, the emails are gone (unless backed up).
4. Storage on the mail server is minimised.
  
The default behaviour can be changed from the mail client settings to keep copies on the server. However, accessing the same mail account via multiple clients using POP3 is usually not convenient because each client downloads its own copy, and there is no synchronisation between them. One would lose track of read and unread messages.

To keep all mailboxes synchronised across multiple devices, a different protocol is needed, such as IMAP
</pre>

## POP3 vs. IMAP

| Feature | POP3 | IMAP |
|---|---|---|
| Main purpose | Retrieves messages, often for local storage | Accesses and synchronizes messages on the server |
| Multi-device synchronization | Limited | Supported |
| Mail storage | Often downloaded locally | Usually maintained on the server |
| Read/unread status synchronization | Generally limited | Supported |
| Common secure port | TCP 995 | TCP 993 |

IMAP is generally more convenient when accessing the same mailbox across multiple devices because it synchronizes mailbox state.

<pre>
POP3 vs IMAP : When to Use Each
  
POP3 is still useful in specific scenarios :

1. When you want to access email offline and have limited or unreliable internet connectivity
2. When you need to minimise server-side storage
3. When you only access email from a single device
4. For archiving emails locally

  However, IMAP has largely replaced POP3 for most users because of its synchronisation capabilities.
</pre>

## Security Implications for Pentesters

- **Cleartext credentials:** Plaintext POP3 on TCP 110 may expose usernames and passwords to network sniffing.
- **Mailbox exposure:** Unauthorized mailbox access may reveal sensitive messages, personal information, or password-reset links.
- **Credential reuse:** Exposed credentials may be reused on other systems if the same password has been used elsewhere.
- **Authentication testing:** Assess password policies and authentication controls only within the authorized scope.
- **Transport security:** Check whether POP3 connections require TLS and whether insecure plaintext access is permitted.

## Key Takeaways

- POP3 retrieves emails from a mail server.
- TCP 110 is the traditional plaintext port, TCP 995 uses implicit TLS.
- `USER` and `PASS` authenticate the user, `STAT` summarizes the mailbox, `LIST` lists messages, and `RETR` retrieves a message.
- POP3 may download and delete messages, depending on client settings.
- IMAP is generally preferable when mailbox synchronization across devices is required.
- Plaintext POP3 can expose credentials and sensitive email contents.

## Internet Message Access Protocol (IMAP)

Internet Message Access Protocol (IMAP) is an email protocol that allows users to access and manage emails stored on a mail server. Unlike the traditional download-and-delete approach associated with POP3, IMAP keeps messages on the server and synchronizes mailbox changes across multiple devices.

For example, marking an email as read on a smartphone can synchronize that change with a laptop using the same mailbox.

## Why IMAP Is Widely Used

- **Server-side storage:** Emails remain on the mail server unless deleted or moved.
- **Synchronization:** Read/unread status, folders, and message flags can synchronize across devices.
- **Multi-device access:** Users can access the same mailbox from smartphones, laptops, and desktop clients.
- **Server-side search:** Clients can search messages on the server without downloading the entire mailbox first.

<pre>
Why IMAP Became the Standard ?

IMAP has largely replaced POP3 for most users because of how email is accessed today. People check email from their phones, laptops, tablets, and web browsers, often switching between devices throughout the day. IMAP's server-side storage model makes this seamless:

1. Emails remain on the server and are accessible from any device.
2. Read/unread status, folders, and flags are synchronised across all clients.
3. Deleting an email on one device removes it everywhere.
4. Search can be performed server-side without downloading all messages.

  This is in contrast to POP3's download-and-delete model, where each device has its own separate copy of messages.
</pre>

## IMAP Ports and Encryption

| Port | Protocol | Security |
|---|---|---|
| TCP 143 | IMAP | Plaintext by default, may support upgrading to TLS using `STARTTLS`. |
| TCP 993 | IMAPS | Implicit TLS, encryption begins immediately upon connection. |

Plaintext IMAP can expose login credentials and email contents to network observers. Secure configurations should use TLS.

> Like other email protocols, IMAP was originally designed without encryption:
> Port 143 is the default IMAP port using cleartext. Many servers support upgrading the connection to TLS using the STARTTLS command.
> Port 993 is used for IMAPS (IMAP over implicit TLS). The connection is encrypted from the start.

## Manually Interacting with IMAP

A Telnet client can demonstrate IMAP commands when a server permits plaintext connections.

Example:

```bash
telnet MACHINE_IP 143
```

After connecting, the server sends a greeting and may advertise supported capabilities.

### Example IMAP Session

```text
c1 LOGIN frank <password>
c2 LIST "" "*"
c3 EXAMINE INBOX
c4 LOGOUT
```

- `LOGIN` - Authenticates the user.
- `LIST "" "*"` - Lists available mailbox folders.
- `EXAMINE INBOX` - Opens the inbox in read-only mode.
- `LOGOUT` - Ends the session.

**Important:** IMAP requires each client command to begin with a tag, such as `c1` or `c2`. The server uses the tag to associate its completion response with the corresponding command.

Use Telnet only with authorized test systems and accounts.

## Understanding IMAP Server Responses

When an IMAP server first responds, it may advertise its capabilities.

| Capability | Meaning |
|---|---|
| `IMAP4rev1` | Support for the IMAP4rev1 protocol. |
| `STARTTLS` | Supports upgrading the connection to TLS. |
| `IDLE` | Allows the client to wait for mailbox updates and notifications. |
| `ACL` | Supports access control lists for mailbox permissions. |

The `LIST` response reveals available folders, such as `INBOX`, `Sent`, `Drafts`, and `Trash`. This can help understand mailbox organization after successful authentication.

Common mailbox responses include:

- `* 0 EXISTS` - The selected mailbox currently contains zero messages.
- `* 0 RECENT` - No messages are marked as recent.
- `* FLAGS (...)` - Lists message flags supported by the server.

## Common IMAP Commands

| Command | Purpose |
|---|---|
| `LOGIN username password` | Authenticates the user. |
| `LIST "" "*"` | Lists mailbox folders. |
| `SELECT folder` | Opens a mailbox for read/write operations. |
| `EXAMINE folder` | Opens a mailbox in read-only mode. |
| `FETCH n BODY[]` | Retrieves the contents of message sequence number `n`. |
| `SEARCH criteria` | Searches for messages matching specified criteria. |
| `STORE n +FLAGS (\Seen)` | Adds the `\Seen` flag, marking a message as read. |
| `LOGOUT` | Ends the session. |

Each command must have a tag, for example:

```text
c1 LOGIN frank <password>
c2 LIST "" "*"
c3 EXAMINE INBOX
c4 LOGOUT
```

## IMAP vs. POP3

| Feature | IMAP | POP3 |
|---|---|---|
| Primary purpose | Accesses and manages server-side mail | Retrieves and downloads mail |
| Server-side storage | Typically retained | May be deleted after download |
| Multi-device synchronization | Supported | Limited |
| Folder synchronization | Supported | Generally limited |
| Common secure port | TCP 993 | TCP 995 |

IMAP is generally more suitable for users who access their email from multiple devices. POP3 can still be useful for local storage and offline access.

## IMAP vs. Webmail

Webmail services allow users to access email through a browser, usually over HTTPS. Dedicated email applications can connect directly to a mail server using IMAP.

Both approaches can provide access to the same mailbox, but their client-server communication methods differ. Understanding IMAP is useful when assessing enterprise mail servers and investigating compromised email accounts.

> Many users today access email through web interfaces (Gmail, Outlook.com, etc.) rather than dedicated mail clients. These web interfaces use HTTPS to secure the connection between the browser and the mail provider's servers. However, the underlying mail storage still uses IMAP concepts, and many users configure traditional mail clients alongside webmail access.

> Understanding IMAP remains relevant because enterprise environments often run their own mail servers with IMAP access, penetration testers may encounter IMAP services during assessments, mobile devices and desktop mail clients still use IMAP extensively, and compromised IMAP credentials provide deeper access than webmail in some scenarios.

## Security Implications for Pentesters

- **Credential exposure:** Plaintext IMAP on TCP 143 may expose usernames and passwords to network sniffing.
- **Persistent mailbox access:** Compromised credentials may allow continued access to current and incoming messages.
- **Historical data exposure:** Mailboxes may contain sensitive business communications and documents.
- **Password-reset abuse:** Emails may contain account recovery links or security notifications.
- **Business email compromise:** Unauthorized access can enable impersonation, invoice fraud, and data theft.
- **Lateral movement:** Emails may reveal internal systems, employee information, or credentials that help an attacker move further into an organization.

Testing must remain within the authorized scope. Use secure authentication and TLS configurations to reduce credential and message exposure.

## Key Takeaways

- IMAP provides synchronized access to emails stored on a mail server.
- TCP 143 is the traditional IMAP port, TCP 993 uses implicit TLS.
- Each IMAP command uses a tag to match requests with server responses.
- `LIST` displays mailbox folders, `SELECT` opens a mailbox for read/write access, and `EXAMINE` opens it read-only.
- Compromised IMAP credentials can expose historical emails and provide persistent access to sensitive information.
- TLS protects credentials and email content while they travel across the network.

## Summary 

## Key Takeaways

- **Cleartext communication:** Protocols such as traditional FTP, HTTP, Telnet, POP3, IMAP, and SMTP can transmit data without encryption when configured for plaintext communication. Credentials and sensitive data may be exposed to network sniffing.
- **Manual protocol interaction:** Telnet can be used as a TCP client to interact manually with text-based services, such as HTTP, FTP, SMTP, POP3, and IMAP, when those services permit plaintext connections.
- **Email protocols:** SMTP sends emails, while POP3 retrieves emails and IMAP provides synchronized access to server-side mailboxes.
- **Secure alternatives:** Use HTTPS instead of HTTP, SSH instead of Telnet, SFTP or properly configured FTPS instead of plaintext FTP, and TLS-protected email protocols to protect data in transit.
- **Security assessment:** Understanding protocol commands, responses, ports, and authentication mechanisms helps pentesters identify misconfigurations and insecure services.

## Protocol Reference

| Protocol | Default TCP Port | Purpose | Security / Alternative |
|---|---:|---|---|
| FTP | 21 | File transfer control | Traditional FTP is plaintext, use SFTP (22) or FTPS (commonly 990 for implicit TLS). |
| HTTP | 80 | Web communication | Plain HTTP, use HTTPS (443). |
| IMAP | 143 | Access and synchronize email | Use IMAPS (993) or IMAP with STARTTLS. |
| POP3 | 110 | Retrieve email | Use POP3S (995) or POP3 with TLS where supported. |
| SMTP | 25 | Primarily server-to-server email transfer | Use TLS with STARTTLS where supported. |
| SMTP Submission | 587 | Submit outgoing email from clients | Typically authenticated submission with STARTTLS. |
| SMTPS | 465 | Secure email submission | Implicit TLS. |
| Telnet | 23 | Remote terminal access | Unencrypted, use SSH (22). |

**Note:** Ports shown are conventional defaults. Actual ports and security depend on server configuration. SFTP is a separate protocol running over SSH, not an encrypted version of FTP.

## Telnet as a Testing Tool

Although Telnet is unsuitable for secure remote administration, its client can help test TCP services manually.

Examples:

```bash
telnet TARGET_IP 80
telnet TARGET_IP 21
telnet TARGET_IP 25
telnet TARGET_IP 110
telnet TARGET_IP 143
```

These commands attempt to connect to the specified service ports. Whether manual interaction works depends on the protocol, service configuration, and encryption requirements. Telnet cannot directly perform a plaintext exchange with a service that expects TLS immediately upon connection.

## Security Lessons

- Encrypt sensitive traffic using TLS or a secure protocol.
- Avoid transmitting passwords over plaintext connections.
- Review exposed services and disable unnecessary or insecure protocols.
- Verify authentication, authorization, and mail-server relay settings.
- Analyze service banners and protocol responses carefully, a disclosed software version alone does not prove a vulnerability.

**Final takeaway:** Understanding how protocols work at a low level makes it easier to recognize insecure configurations, investigate exposed services, and recommend effective defenses.
